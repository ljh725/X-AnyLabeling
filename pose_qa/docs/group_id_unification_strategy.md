# group_id 统一策略

## 背景与定位

`person`、`head`、`face` 三类检测框（以及关键点）通过 `group_id`
表达"属于同一个真实实例"的语义。理想状态下，同一个人的身体框、头框、脸框、
全部关键点应当共享同一个 `group_id`。

真实标注中这个约束经常被破坏：

- 标注员忘记给 `head` 或 `face` 设置 `group_id`。
- `head` / `face` 使用了与所属 `person` 无关的独立编号。
- 多人画面中 `head` / `face` 归到了错误的人。
- 关键点和 `person` 共享一个 `group_id`，但 `head` / `face` 各自独立。

`group_id` 不一致不是单纯的格式瑕疵，它会直接污染所有下游环节：训练数据
按 `group_id` 分组会把 `head` 当成孤立实例或丢弃；关键点比对（如
`pose_qa_compare.py`）按 `group_id` 把 `person` 和模型预测配对，gid 一乱就
会串人；Inspector 按 `group_id` 聚合展示也会错位。

因此 group_id 统一不是可选优化，而是数据正确性的硬要求。本文档定义统一的
边界、判断方法、安全原则和与质检的关系。

## 核心判断：统一是数据清洗，不是质检动作

这一条是本文最重要的立场，也是对
`person_head_face_grouping_quality_flow.md` 两段式流程的修正。

两段式流程是：

```text
原始标注 → 空间归并生成 qa_group_id → 基于 qa_group_id 做空间规则检查
```

它的隐患在于：归并本身是一个**可能出错的空间猜测**。把它当成地基，后续所有
规则都吃它的误差——归并把 head 归错了人，那么"head 不在 person 内"的告警
就是假的，"两个 head 重复"的告警也会漏。误差会逐级传递。而且"用空间关系修
gid"和"用空间关系查关系"，判断依据是同一套几何，拆成两段等于把同一个动作
做了两遍。

更根本的一点：**质检的目标是发现需要人工复核的样本，而不是自动改数据**。
自动修 group_id 有风险——如果 head 框本身画错了，把它修到最近的 person 反而
掩盖了错误。机器能做的最高价值是把可疑样本捞出来给人看，而不是替人做决定。

因此本文的立场是：

```text
统一 group_id 是数据清洗，应当在质检确认无误后作为收尾动作。
不该把"自动修 gid"当成质检的前置步骤。
```

## 但 group_id 必须统一

上面说不该把统一当前置步骤，不等于不统一。相反，最终产出一份 gid 一致的干净
数据是硬要求——它决定了训练、比对、展示是否正确。

真正的关键不是"要不要统一"，而是"用什么质量的判断去统一"：

- **head 框画得对、位置对、明确在某个 person 上半身里**，只是标注员忘设或
  设错 gid → 几何无歧义，统一就是修正录入错误，安全且必要。
- **head 落在两个人中间、head 孤立在所有人之外** → 连"这 head 属于谁"都
  不知道，硬统一就是赌，会掩盖错误。这种该报出来，不自动改。

边界就是置信度。无歧义的高置信部分自动统一，有歧义的留给人。

## 统一方案

### 整体流程

一个脚本，一条线性流程，同时产出两样东西：

```text
输入：group_id 不一致的标注
  │
  ├─ 高置信（几何归属明确）→ 就地改 gid，输出干净数据副本
  └─ 低置信 / 孤儿（几何归属模糊）→ 进可疑清单，原样保留
  │
输出：
  ├─ 统一好 group_id 的数据副本（不动原始文件）
  └─ 一份可疑清单（哪张图、哪个框、为什么可疑）
```

不是先归并再修，是判断一次、该修的修、该报的报。

### 几何归属判断

对每个 `head` / `face`，用几何判断它**应该**属于哪个 `person`，得到一个匹配
分数和置信度档位。

三类框的关系本质是一条包含链：

```text
person ⊃ head ⊃ face
   大 → 中 → 小，且越小的越靠上、越居中
```

判断 head → person 归属，看的是包含 + 上半身位置，**不看 IoU**。因为 head 几
乎总是完全在 person 内，IoU 会因为 person 面积大而被压得很低，不灵敏。真正
有区分度的是"head 的中心是不是落在 person 的上部三分之一"——head 跑到 person
脚底下的，一眼就是错的。

face → head 同理，看 face 是不是在 head 内、是不是比 head 小。当找不到可信的
head 时，face 降级匹配到 person（漏标 head 是常见情况，强制 face 必须配 head
会产生大量假孤儿）。

多人靠近时同一个 person 会被多个 head 抢，这时用匈牙利算法做全局最优一对一
配对，而不是逐个贪心。这是唯一需要补全 `person_head_face_grouping_quality_flow.md`
的地方——它没有覆盖多对一的冲突解决。

### 置信度档位与边界

| 分数档 | 含义 | 处理 |
| ---- | ---- | ---- |
| ≥ HIGH_THR | 几何归属明确无歧义 | 改 gid，归入干净数据 |
| LOW_THR ~ HIGH_THR | 几何勉强（如 head 在两人重叠区） | 保留原 gid，进可疑清单 |
| < LOW_THR | 几何上谁都不像（head 孤立在所有人外） | 保留原 gid，进可疑清单 |

`person` 的 `group_id` 一律不动。只让 `head` / `face` 去贴所属 person 的 gid。
关键点跟 person 共享 gid，所以自动不受影响——这是这个方案干净的地方。

### 安全原则

统一是写操作、不可逆，因此必须有保护：

1. **只读原始文件**：所有写操作落到输出副本目录，原始标注不动，可 diff 抽检
   后再决定是否替换。
2. **只改高置信**：低置信和孤儿一律不碰。宁可不统一，也不能改错。
3. **写回前校验**：改 gid 时按 `shape_index` 定位 shape，并校验该位置当前的
   label 仍是报告匹配的 label。若标注文件在报告生成后被编辑过导致索引错位，
   跳过并报告，绝不盲目写入。

## group_id 统一与质检的关系

统一之后，后续的空间几何质检才可靠。但这两件事的产物不同：

| | group_id 统一脚本 | 后续空间质检 |
| -- | ----------------- | ------------ |
| 产物 | 干净数据副本 | 可疑样本清单 |
| 性质 | 数据清洗（写） | 质检（只读，报告） |
| 时机 | 质检确认后收尾 | 主质检流程 |

统一阶段本身也会输出一份可疑清单（低置信和孤儿），这份清单就是质检的一部分
输入——"这个 head 归属不明"本身就是质检要发现的问题之一。

后续空间质检可以设计为不依赖一个全局归并结果、而是每条规则自己临时按几何算
分组、用完即弃。这样某一条判断错了不会污染其他规则。本文不展开空间质检规则
的设计，参见 `quality_strategy.md` 的 L1 / L2 层。

## 与 `person_head_face_grouping_quality_flow.md` 的差异对照

| 维度 | 两段式文档 | 本文 |
| ---- | ---------- | ---- |
| 流程 | 先归并生成 qa_group_id，再基于它做规则检查 | 判断一次：高置信改 gid（清洗），低置信/孤儿进清单（质检） |
| 主产物 | qa_group_id 报告 | 干净数据副本 + 可疑清单 |
| 是否写原始数据 | 否（只生成旁路字段 qa_group_id） | 写副本，不动原始 |
| 几何判断次数 | 两次（归并算一遍，规则检查再算一遍） | 一次 |
| 误差传播 | 归并误差逐级传到所有规则 | 各规则独立判断，不串联 |
| 自动修 gid | 作为"匹配规则稳定后"的可选未来动作 | 高置信部分直接修，低置信留人 |

本文不否定两段式文档的几何打分思路（包含、中心接近、尺寸合理性、上半身偏置
都是对的），只是把它从"生成旁路字段再二次使用"改为"判断一次、直接落地为干净
数据"。

## 落地形态

一个脚本（如 `group_merger.py`），线性流程：

```python
def main():
    for json in gt_dir:
        data = load(json)
        persons, heads, faces = parse(data)        # 几何核心
        matches = match(heads, persons, faces)     # 匈牙利 + face 降级
        changed = apply_to_shapes(data, matches)   # 就地改高置信 gid
        save(data, output_dir / json)              # 写副本
    print(summary)  # stdout：改了几个、孤儿几个
```

几何与匹配核心（打分、匈牙利、face 降级）直接复用，不需要中间报告格式作为
传话筒。三件套 md/txt 不是主产物，可疑清单按需输出。

## 结论

```text
group_id 统一是数据清洗，用一次几何判断完成：
  高置信（明确归属）→ 就地改 gid，产出干净数据
  低置信 / 孤儿（模糊归属）→ 保留原样，进可疑清单

原则：
  - 必须统一（下游全依赖 gid 正确）
  - 只改无歧义的部分（有歧义的留给人）
  - person gid 不动，只 head/face 贴过去
  - 只读原始文件，写副本
```
