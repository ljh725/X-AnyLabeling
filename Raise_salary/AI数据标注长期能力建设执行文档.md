# AI 数据标注长期能力建设执行文档

## 一、目标定位

本文件的目标不是继续强化“普通数据标注员”身份，而是把现有经验升级为：

> AI 数据质量 / 标注自动化 / 数据处理能力

核心职业标签：

> 熟悉 CV/YOLO/关键点标注流程，能制定标注规范、发现质量问题、编写脚本进行数据检查和批处理，并能基于 AnyLabeling 做流程优化的人。

这条路线的关键不是学很多新东西，而是围绕一个主场景持续沉淀：

- 标注规范
- 质检规则
- 自动化脚本
- 工具扩展
- 数据报表
- 项目证据

最终目标是让自己从“执行标注的人”升级为“能提高标注质量和交付效率的人”。

---

## 二、执行原则

### 1. 先聚焦，不铺太宽

当前阶段只选择一个主场景，不同时铺开文本、语音、视频、大模型评测等方向。

建议主场景：

> CV / YOLO / 关键点 / AnyLabeling

原因：

- 你已有实际经验
- 有可展示脚本和工具扩展
- 容易形成作品
- 能和数据质检、标注主管、标注自动化岗位连接

### 2. 每个能力都要变成证据

不要只写“会 Python”“会质检”“会 AnyLabeling”。

要变成：

- 一个脚本
- 一份规范
- 一张报表
- 一个工具功能
- 一个项目说明
- 一个可讲清楚的案例

### 3. 先做最小闭环

不要一开始追求完整平台。

先完成：

> 规范文档 + 质检规则 + 检查脚本 + 问题报表 + 工具跳转

这个闭环一旦跑通，就能成为简历项目。

## 三、八件核心事情

## 1. 锁定主场景

### 目的

明确自己不是泛泛地做“AI 数据”，而是先在一个具体场景里建立深度。

建议锁定：

> CV 图像标注 / YOLO 标签 / 关键点标注 / AnyLabeling 工具链

### 具体做法

整理一页“主场景说明”，内容包括：

- 数据类型：图片
- 标注类型：矩形框、关键点、多标签、group_id
- 常见格式：AnyLabeling JSON、YOLO txt、YOLO Pose
- 工具：X-AnyLabeling / AnyLabeling
- 主要任务：标注、质检、格式转换、数据检查、批量处理
- 主要问题：错标、漏标、重复、标签不规范、group_id 错误、关键点缺失

### 产出物

文件名建议：

```text
01_主场景说明_CV_YOLO_关键点.md
```

### 验收标准

别人看完这一页后，能回答：

- 你处理什么数据
- 你解决什么问题
- 你和普通标注员的区别在哪里
- 你后续工具和脚本服务于什么场景

## 2. 写标注规范

### 目的

把个人经验变成可复用规则，让别人按你的文档也能标对。

这件事对应岗位能力：

- 标注规范制定
- 新人培训
- 质检标准统一
- 项目交付质量控制

### 具体做法

先从你最熟悉的一组标签开始，不要一次写所有标签。

每个标签按固定模板写：

```markdown
## 标签名

### 定义
这个标签表示什么对象。

### 包含
哪些情况应该标这个标签。

### 不包含
哪些相似情况不应该标这个标签。

### 标注方式
使用 rectangle / polygon / point / keypoint 中哪一种。

### group_id 规则
是否需要 group_id，同一对象的哪些 shape 必须共享 group_id。

### 常见错误
列出 3-5 个最常见错误。

### 审核点
质检时重点看什么。
```

### 争议样本整理

不要凭空写规范，要从历史问题中抽样。

建议收集：

- 10 张标错样本
- 10 张容易争议样本
- 10 张标准样本

每张样本写一句：

```text
为什么这样标，为什么不能那样标。
```

### 产出物

文件名建议：

```text
02_标注规范_CV_YOLO_关键点.md
```

### 验收标准

拿给一个新人看后，他能根据文档完成基本标注，且主要错误类型不会反复出现。

## 3. 建质检体系

### 目的

把“我觉得这里有问题”变成“规则可以判断这里有问题”。

这一步是从经验型质检升级到规则型质检。

### 先做 8 类基础规则

| 编号 | 规则 | 检查内容 | 处理方式 |
|---|---|---|---|
| R1 | 空标签 | label 为空 | 必须补标签 |
| R2 | 重复标签 | 同一 group_id 内同标签重复 | 删除或合并重复对象 |
| R3 | 标签不在允许集 | label 不属于项目标签集 | 修改为合法标签 |
| R4 | group_id 异常 | person 或关键点缺少 group_id | 补充正确 group_id |
| R5 | shape_type 不匹配 | label 应该是 rectangle 却被标成 point 等 | 修改 shape_type 或重新标注 |
| R6 | 关键点缺失 | 有 person 但关键点不足 | 补关键点或标记不可见 |
| R7 | 图片和标签不匹配 | 有图无标、有标无图、文件名不一致 | 补齐或剔除 |
| R8 | 属性一致性 | difficult、orphan_head 等属性不符合规则 | 按规范修正 |

### 每条规则要写清楚

模板：

```markdown
## R1 空标签

### 触发条件
shape.label 为空字符串或 None。

### 严重级别
error

### 为什么要检查
空标签无法训练，也无法进入统计。

### 处理方式
补充正确标签；无法确认则加入待复核列表。

### 自动化方式
脚本扫描 JSON 中 shapes 数组，检查 label 字段。
```

### 产出物

文件名建议：

```text
03_质检规则体系.md
```

### 验收标准

你能把每个错误归入明确规则，而不是只说“这里不对”。

## 4. 做统计报表

### 目的

把质检结果转成管理和面试都能看懂的结果。

报表不是为了好看，而是为了回答：

- 这批数据质量怎么样
- 谁的问题最多
- 哪类错误最多
- 哪个批次风险最高
- 修复后有没有改善

### 最小字段

先做一个 CSV 或 Excel 表，字段包括：

```text
date
project
batch_id
annotator
file_name
label
rule_name
severity
issue_message
is_fixed
reviewer
```

### 最小统计

先做 4 个统计：

| 指标 | 含义 |
|---|---|
| 总量 | 文件数、shape 数、问题数 |
| 错误率 | 问题数 / shape 数 |
| Top 问题 | 出现最多的错误类型 |
| 趋势 | 每天或每批次错误率变化 |

### 产出物

文件名建议：

```text
04_标注质检报表模板.xlsx
04_quality_report_sample.csv
```

### 验收标准

你能用这张表讲清楚：

- 哪类问题最多
- 质量是否改善
- 哪些规则需要调整
- 哪些人员或批次需要重点复检

## 5. 写自动化脚本

### 目的

把重复检查、转换、移动、统计工作自动化。

注意：脚本不是一次性代码，而是可复用工具。

### 先做 3 个脚本

## 5.1 YOLO 标签检查脚本

功能：

- 检查 txt 是否为空
- 检查类别 ID 是否超范围
- 检查坐标是否为 0-1 之间
- 检查每行字段数是否正确
- 检查图片和标签是否一一匹配
- 输出错误清单 CSV

命令示例：

```bash
python check_yolo_labels.py --images ./images --labels ./labels --classes classes.txt --output report.csv
```

## 5.2 格式转换脚本

功能：

- AnyLabeling JSON 转 YOLO
- YOLO 转检查用 CSV
- 支持批量目录
- 输出转换日志

命令示例：

```bash
python convert_anylabeling_to_yolo.py --input ./json --output ./labels --classes classes.txt
```

## 5.3 批量改名 / 移动脚本

功能：

- 根据标签类型移动图片和 JSON
- 根据错误规则移动问题样本
- 保持图片和标签成对移动
- 生成移动记录

命令示例：

```bash
python move_by_issue.py --report report.csv --images ./images --json ./json --output ./bad_cases
```

### 每个脚本必须具备

- 命令行参数
- README
- 输入示例
- 输出示例
- 异常提示
- 不直接覆盖原文件
- 处理日志

### 产出物

仓库结构建议：

```text
annotation-quality-toolkit/
├── README.md
├── check_yolo_labels/
│   ├── check_yolo_labels.py
│   └── README.md
├── format_converter/
│   ├── convert_anylabeling_to_yolo.py
│   └── README.md
├── badcase_mover/
│   ├── move_by_issue.py
│   └── README.md
└── samples/
    ├── input/
    └── output/
```

### 验收标准

别人只看 README，就能运行你的脚本，并得到和你示例一致的输出。

## 6. 做 AnyLabeling 工具扩展

### 目的

把标注工具从“手工操作界面”变成“质量控制和流程优化工具”。

这件事是你的差异化能力。

### 不要散着改

不要今天加一个快捷键，明天改一个按钮，后天修一个跳转。

要围绕一个闭环做：

```text
筛选问题 → 定位对象 → 修改对象 → 重新校验 → 导出问题样本
```

### 现有可用入口

当前仓库里已经有底座：

- `filter_state.py`：保存筛选条件
- `filter_engine.py`：控制当前图片内 shape 显示隐藏
- `filter_navigation_engine.py`：跨图片查找命中样本
- `validation_engine.py`：规则校验引擎
- `inspector_panel.py`：质检面板入口
- `rule_config_widget.py`：规则配置入口
- `export_manager.py`：问题样本导出入口

### 优先做 4 个功能

## 6.1 筛选保持

目标：

切换图片后，当前 label / group_id / shape_type 筛选条件不丢失。

使用场景：

只看 person，只看某个 group_id，只看关键点类型。

验收标准：

切换 20 张图片，筛选条件仍然保持，且只显示命中的 shape。

## 6.2 问题跳转

目标：

在问题列表中点击一条错误，自动打开对应图片并选中对应 shape。

使用场景：

质检人员不用手动找文件和对象。

验收标准：

双击问题列表中的 issue，可以准确定位到文件和 shape。

## 6.3 规则校验

目标：

点击扫描后，自动检查当前目录的 JSON，输出问题列表。

使用场景：

批量交付前先跑一遍质检。

验收标准：

至少支持 8 条基础规则，并能显示错误数、警告数、问题详情。

## 6.4 问题导出

目标：

按规则把问题 JSON 和图片复制到指定目录。

使用场景：

整理 bad case、返修样本、面试展示样本。

验收标准：

导出目录按规则分组，每组包含对应图片和 JSON。

### 产出物

项目说明建议：

```text
AnyLabeling 数据质检与流程优化扩展
```

说明结构：

```markdown
## 项目背景
原始标注流程中，问题样本需要人工查找，质检效率低。

## 我做了什么
实现筛选保持、问题跳转、规则校验、问题导出。

## 技术点
PyQt6、信号槽、QDockWidget、规则引擎、JSON 扫描、文件导出。

## 效果
减少人工查找问题样本时间，提高返修效率。

## 截图
放筛选面板、问题列表、导出结果截图。
```

### 验收标准

你能在面试中演示：

```text
打开目录 → 扫描问题 → 双击跳转 → 修改 → 重新扫描 → 导出 bad case
```

## 四、建议执行顺序

## 第 1 阶段：先做职业底盘

时间：1-2 周

任务：

- 完成主场景说明
- 完成第一版标注规范
- 完成 8 条质检规则文档

结果：

- 你知道自己到底做什么方向

## 第 2 阶段：做自动化证据

时间：3-6 周

任务：

## 六、最终判断标准

这套事情做完后，你要能回答 5 个问题：

1. 我处理什么类型的数据？
2. 我知道这些数据最常见的问题是什么吗？
3. 我能不能用规则和脚本自动发现问题？
4. 我能不能把问题统计成报表？
5. 我能不能用工具提高标注和质检效率？

如果这 5 个问题都能回答清楚，你的定位就不再是普通数据标注，而是：

> AI 数据质量与标注自动化人员

这是后续涨薪、跳槽和长期发展的基础。
