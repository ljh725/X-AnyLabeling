## Context

参见 `proposal.md` 的动机。当前实现已经有版本化事件、ActionSpan、ObjectEpisode、ActivitySegment、功能状态、返工指标和确定性数据包基础，但仍存在以下约束：记录器按 UTC 月写入并对每个事件重新打开文件；队列丢弃和写入错误主要停留在运行时状态；分析过滤器虽支持 UTC 边界，界面只真正接入当前项目；读取器扫描所有 JSONL、把全部选中事件放入列表并反复排序；对象轮次耗时尚未分解出未归属活跃时间；数据包的字节上限只覆盖代表轨迹而非所有高基数表。两阶段必须增量复用现有模型，同时兼容旧事件和旧月度文件。

## Goals / Non-Goals

**Goals:**

- 使每个受支持语义动作、对象轮次和活跃片段可闭合、可关联、可检测缺口。
- 使用小时分片、后台批写和持久化 manifest 降低写入放大并缩小范围查询扫描面。
- 用同一版本化事件契约支撑动作、工作流阶段、返工、未归属时间和双范围统计。
- 对百万级事件采用后台、可取消、内存不随事件总数线性增长的读取与聚合路径。
- 生成确定性、质量可解释、默认紧凑的数据包，供软件外部分析。
- 保持默认关闭、本地运行、无模型调用、无上传和隐私字段白名单。

**Non-Goals:**

- 不记录逐点鼠标轨迹、键盘文本、图片像素、完整标注坐标或绝对路径。
- 不建立全函数调用链、通用性能追踪平台或远程遥测服务。
- 不在软件内解释瓶颈、生成自然语言建议或宣称功能变化具有因果效果。
- 不自动重写已有月度 JSONL，也不要求旧版本软件识别新小时分片。
- 不以抽样替代受支持语义动作的完整记录；仅对高频底层回调做语义合并。

## Decisions

### 1. 两阶段以事件契约为唯一交界

第一阶段只产生版本化事件分片和分片 manifest；第二阶段只通过公开读取、校验和重放契约消费它们，不读取 UI 内存状态作为统计事实。事件 schema、统计算法、阶段映射、返工规则和数据包分别版本化，避免任一层升级隐式改变其他层口径。

替代方案是让导出器直接访问当前会话对象和控件状态。该方案只能覆盖当前运行，无法稳定重放历史范围，因此不采用。

### 2. 语义动作而不是调用链作为分析原子

继续以 ActionSpan 表示一次用户意图，并在 UI/Canvas 的提交边界接入 begin/terminal。底层回调仅用于驱动状态机和受控回放，不进入正式分析流。动作终态统一为 success、cancelled、failed、no_change 和 interrupted；生命周期事件与可计数动作分开。

覆盖矩阵升级为版本化、机器可校验的动作目录；文档表格和参数化回放从同一目录校验，防止文档、事件目录和测试漂移。

替代方案是记录所有 Qt 信号和函数调用后离线推断用户动作。该方案体积大、易重复且随重构改变统计含义，因此不采用。

### 3. sequence_no 以应用会话为作用域

每个应用会话从 1 开始分配严格递增 sequence_no，并与 application_session_id 共同构成连续性检查键。这样不需要跨进程维护全局计数器，也能检测单次运行内的静默丢失。队列拒绝事件时保留被跳过序号范围；恢复写入后由 recording_gap 事件或 manifest 会话段持久化。

全局永久序号能跨运行检测文件删除，但需要额外的原子持久计数器，增加热路径写入和恢复复杂度。文件删除由保留期和 manifest 索引负责，因此不采用全局序号。

### 4. 小时分片采用 UTC、单活动句柄和批量追加

事件按 `occurred_at_utc` 的小时路由到 `events-YYYY-MM-DD-HH.jsonl`。后台消费者在正常顺序下保持一个活动文件句柄，按批次数或短刷新间隔写入；小时变化时刷新、关闭并原子发布 sidecar manifest。极少数墙钟回跳或延迟事件通过受控追加旧分片处理并重建该分片 manifest。

UTC 避免夏令时重复小时和本地时区变化。按天分片扫描面更大，按分钟分片文件数过多，SQLite 会引入迁移和查询层重写；小时 JSONL 在当前规模与代码复用之间更平衡。

### 5. manifest 是可重建索引，不是真实事件来源

sidecar manifest 保存事件时间范围、按会话序号范围、事件数、丢弃/错误、schema 分布、大小和 SHA-256。JSONL 始终是事实来源；崩溃导致 manifest 缺失或陈旧时，读取器可扫描分片重建诊断，但必须把 manifest 不完整计入测量质量。

manifest 先写临时文件再原子替换，避免出现部分 JSON。正在写入的当前小时允许没有最终校验值。

### 6. 保留期按完整分片清理，旧月度文件只读兼容

仅删除最大事件时间早于截止时间且不再活动的完整小时分片及其 manifest。边界小时可以最多额外保留不到一小时，以避免逐行重写。旧月度文件继续由读取器识别，但新记录器不再向其追加；不执行自动历史迁移。若未来提供迁移工具，必须是显式、可校验且保留备份的独立操作。

### 7. 范围查询先选文件，再精确选事件

UI 的本地时间选择转换为明确 UTC 闭区间。分片选择器根据小时文件名求交，只打开可能相交的文件；首尾小时和旧月度文件再逐事件匹配。当前项目筛选要求存在活动 project_session_id，否则直接拒绝。双范围对照构造两个独立过滤器，并共享同一读取和算法配置。

### 8. 聚合改为按会话顺序流式重放

新事件使用 `(application_session_id, sequence_no)` 作为会话内权威顺序；不同会话之间不拼接动作序列。读取器按分片顺序流式产生事件，聚合器维护每个活动会话、对象、低基数分桶和滚动序列的有限状态。对象与图片汇总内存随唯一实体数增长，而不是随事件数增长；默认紧凑导出在达到实体明细上限后转入确定性分桶和候选选择。

需要第二遍事件时，只保存候选 episode/action ID 并重新扫描相交分片，用于代表轨迹和校验，不保留全事件列表。旧 schema 无 sequence_no 时使用文件顺序、UTC、单调时间和 event_id 的兼容排序，并在质量报告标记 legacy ordering。

替代方案是继续一次性加载并全局排序所有事件。其实现简单，但百万事件下内存、UI阻塞和重复排序不可接受。

### 9. 未归属时间使用活跃区间减法

对每个 episode 先构造 focused/active 区间，再将语义动作和明确系统等待区间裁剪到 active 区间并求并集，避免动作重叠重复计时。动作间低于版本化阈值的间隔进入 transition_gap；剩余值为 unattributed。所有组成项使用相同半开区间约定，输出时保证非负且总和在舍入误差内守恒。

未归属只表示当前分类无法解释的活跃时间。它既可能是思考/观察，也可能是接入遗漏，统计层不得自动解释。

### 10. 工作流阶段和时间贡献只输出事实

建立独立版本化阶段映射，把语义动作映射到导航定位、对象创建、几何编辑、标签属性、AI生成与修正、检查质检、返工恢复、保存提交、系统等待和未归属。time_contribution 输出总时间、占比、累计占比和覆盖率；排序规则固定，但不添加“瓶颈”标签。

双范围比较复用相同聚合器，对总体与低基数上下文分层输出样本、覆盖率和差值。没有随机分组时固定标记 observational；样本不足只输出不可比较原因。

### 11. 默认紧凑包通过低基数聚合和确定性上限控制

默认包固定包含 manifest、质量报告、动作/阶段/时间贡献、episode/object/image 汇总、返工、范围对照和代表轨迹。动作和阶段表天然使用低基数枚举；高基数 episode/object/image 明细使用确定性排序、代表行和 `other` 汇总，manifest 同时记录总数、导出数和省略数。代表轨迹按 common、median、P75、longest、rework、failure、unattributed_anomaly 和 measurement_anomaly 分类设置数量、事件数和总字节上限。

不把全量原始事件复制进默认包。需要审计单条事件时，用户仍可在本地原始分片中按 manifest 和匿名 ID 查找。

### 12. 导出使用后台 worker、批次取消和原子发布

UI 只负责收集范围、启动 worker、显示进度/质量和转发取消。读取、重放、聚合、第二遍轨迹选择和写包均在 worker 内执行，并在分片边界和固定事件批次检查取消。所有输出先写入目标父目录内的唯一临时目录，完整校验后原子改名；失败、取消和目标已存在均不覆盖正式结果。

### 13. 软件内没有 AI 执行路径

“紧凑”描述数据规模和外部可消费性，不引入 AI API、提示词、模型选择或自动报告。导出完成后 UI 仅显示目录、事件范围和质量状态。任何外部 AI 使用都由用户在软件外完成。

## Risks / Trade-offs

- [小时分片在 90 天内可能产生约 2160 个文件] → 仅在有事件时创建，按时间命名并用保留期批量删除；范围读取只枚举相交文件。
- [批量写入会增加崩溃时尚未刷盘的短窗口] → 使用较短刷新间隔、关闭时限时 flush、序号缺口和 manifest 诊断，不在 UI 热路径同步 fsync 每条事件。
- [队列满时仍可能丢失语义事件] → 有界队列保护 UI，持久化缺口事实并以覆盖率门槛阻止无依据的耗时结论；压力测试调整容量和批量策略。
- [覆盖矩阵仍可能遗漏新功能入口] → 将动作目录、文档和参数化回放绑定，并在新增可编辑工作流的验收清单中强制更新。
- [未归属时间容易被误读为浪费或漏记] → 字段和文档保持中性命名，单列 transition/system wait，并要求外部分析结合代表轨迹。
- [流式重放比全量排序实现复杂] → 先固定会话内 sequence 契约和纯 Python 聚合状态机，以夹具对照现有批量算法，再替换 UI 导出路径。
- [旧日志顺序和上下文质量不足] → 保留兼容统计但标记 legacy ordering/low granularity，不让缺失字段进入依赖指标。
- [紧凑上限可能隐藏长尾实体] → 所有截断可复算、输出总数和 other 汇总，并为异常和最长轨迹保留独立名额。
- [前后范围差异被误当作因果] → 固定 observational 标志、分层样本和 comparison_unavailable，软件不输出因果措辞。

## Migration Plan

1. 固定当前 v2 事件、统计和数据包夹具，增加新旧格式并存的回归基线。
2. 引入新事件/算法/阶段/返工/数据包版本常量和兼容读取，不改变现有写入路径。
3. 完成第一阶段覆盖目录、动作接入审计、sequence_no、缺口事实、批写小时分片、manifest、保留期和状态 UI；通过回放与压力门槛后切换新写入。
4. 保持旧月度文件原样，仅验证新读取器能在混合目录去重、过滤和报告质量。
5. 完成第二阶段分片预筛选、流式重放、未归属区间、阶段/时间贡献、返工和双范围聚合。
6. 新增后台导出 worker、范围 UI 和紧凑数据包，先以测试/配置开关验证，再替换同步全量导出入口。
7. 发布后若记录路径回归，可关闭行为记录或回退写入开关；已经生成的小时分片保持不变。若导出路径回归，可保留新日志并临时恢复旧分析入口，不修改源事件。
