## Why

当前软件只能零散看到部分功能结果，无法回答“标注一个对象通常经过哪些操作、哪些步骤最耗时、哪些功能状态会改变操作效率”等行为分析问题。需要先在应用内部形成可追溯、低干扰的结构化行为数据，再用确定性统计将原始记录压缩为可复核、可交给外部大模型分析的数据包。

## What Changes

- 新增默认关闭、仅本地运行的结构化行为记录能力，按应用、项目、自然日、图片访问、对象交互轮次和具体动作组织事件。
- 为 X-AnyLabeling JSON 生命周期内的每个 shape 增加顶层 `xanylabeling_shape_id`，用 `project_id + image_id + shape_id` 稳定区分对象；该 ID 不进入 VOC、YOLO、COCO 等交换格式。
- 建立“项目启动快照 + 有效状态变化事件 + 普通行为引用状态版本”的功能状态记录规则，并区分“已配置、当前生效、本轮实际使用”。
- 将拖拽、滚轮、连续微调等高频输入合并成语义动作或动作段，记录结果和耗时，不记录无分析价值的原始鼠标轨迹。
- 新增内部确定性统计能力，计算动作次数、耗时分位数、动作转移、常见序列、重复回路、对象交互轮次以及不同功能状态下的行为差异。
- 新增压缩分析数据包导出，将统计表和少量代表性轨迹写为 JSON/CSV/JSONL，供后续外部大模型寻找规律和生成建议；本次不在应用内调用大模型。
- 行为采集、统计和导出均采用显式开关、隐私最小化、故障放行与可审计的数据质量报告，不影响正常标注和保存流程。

## Capabilities

### New Capabilities

- `annotation-behavior-recording`: 在应用内部为项目、图片、shape、对象交互轮次、语义动作和功能状态建立版本化、可追溯的本地行为事件记录。
- `annotation-behavior-statistics`: 对行为记录进行确定性统计、质量校验和压缩导出，生成可复核且适合外部大模型消费的分析数据包。

### Modified Capabilities

无。

## Impact

- 影响 shape 的 JSON 读写、复制粘贴、撤销恢复、导入以及格式转换边界，但不改变现有标注格式的业务字段语义。
- 需要在项目/图片生命周期、选择与编辑、撤销重做、保存、模式与功能状态变化、AI 与质检动作等现有入口接入语义事件。
- 新增独立的行为分析服务、配置、事件存储目录、统计/导出入口及相应单元测试和集成测试。
- 现有矩形框复核精修统计继续兼容；可通过适配器映射到统一事件模型，但不得造成双重计数。
- 不引入云端上传或应用内大模型依赖；默认关闭时不得改变现有用户流程和性能表现。
