## Context

参见 [proposal.md](proposal.md) 的动机。当前应用的用户动作分散在 `label_widget.py`、`canvas.py`、Inspector、AI、保存与项目生命周期等入口，已有矩形框复核精修统计只覆盖局部场景。shape JSON 没有独立对象标识，`group_id` 表达业务分组，不能承担对象身份；同时行为分析要求既能按自然日统计，也能保留一次项目从打开到关闭的连续过程。

本设计横跨 JSON 数据模型、PyQt 交互层、本地持久化、确定性统计和导出。实现必须遵守默认关闭、只在本地、故障放行、隐私最小化，并避免在高频输入路径上同步执行文件 I/O 或重计算。

## Goals / Non-Goals

**Goals:**

- 用稳定身份、语义事件和功能状态版本，可靠重建“谁、在何时、处于什么状态、对哪个对象做了什么、结果与耗时如何”。
- 将采集层与统计层分离，使原始事件可审计，统计结果可重复，未来可以独立升级算法版本。
- 控制日志体量和 UI 开销，让启用采集后的标注体验接近未启用状态。
- 产出尺寸有界、字段清晰、可直接交给外部大模型的分析包，同时保留足够证据供人工复核。

**Non-Goals:**

- 本变更不在应用内接入大模型，不自动生成行为建议，也不上传数据。
- 不记录原始鼠标轨迹、键盘内容、图片像素或完整 shape 几何快照。
- 不把 `xanylabeling_shape_id` 设计成跨 VOC、YOLO、COCO 转换后仍可恢复的全球身份。
- 不替代 `group_id` 的业务语义，不用临时 QA 关系推断绑定正式对象关系。
- 不在第一版做跨设备、跨用户或团队级行为合并。

## Decisions

### 1. 使用一个统一变更、两个独立能力层

第一层只负责产生可信事件，第二层只读取事件并产生统计与分析包。两层共享事件 schema、ID 和时间口径，但拥有独立版本号：`event_schema_version` 与 `analytics_algorithm_version`。

这样可以先验证采集正确性，再启用统计；统计算法升级不会重写历史日志。备选方案是直接在每个 UI 动作发生时累加指标，但该方式无法重新计算、纠错或审计，故不采用。

### 2. 新增纯 Python 行为分析服务，Qt 层只做语义适配

新增 `anylabeling/services/behavior_analytics/`，承载事件模型、ID、时钟、会话、功能状态、写入、读取、校验、统计和导出。该包不依赖 PyQt6，可独立测试。

PyQt 交互层通过一个薄的协调器接入：

- `label_widget.py` 负责项目、图片、选择、保存、撤销重做、模式、Inspector/质检/AI 等高层语义事件；
- `canvas.py` 只在确实掌握几何交互边界时发出开始、提交、取消和摘要信号；
- 现有矩形框复核精修统计通过适配器提供统一事件或共享 `correlation_id`，统一管线只保留一次计数。

不采用自动监听所有 Qt 事件或统一包裹所有 `QAction`，因为它们只能看到输入，无法可靠判断业务对象、有效变化和结果。

### 3. shape ID 使用顶层专用字段并限定生命周期

JSON 键固定为 `xanylabeling_shape_id`，值使用随机 UUID 字符串。shape 对象将该字段视为显式身份字段，并在序列化、撤销快照和编辑中保留；复制、粘贴、导入和 AI 新建路径必须重新生成。对象在日志中的完整键为 `(project_id, image_id, shape_id)`。

旧文件加载时只在内存惰性补 ID，不仅因补 ID 设置 dirty；下一次因真实标注变化保存时一并持久化。导出器显式忽略该字段。删除事件保留 tombstone；撤销删除恢复原 ID。

备选位置 `flags`、`attributes` 和 `kie_linking` 都有既有业务语义或交换语义，容易被用户编辑、模型覆盖或转换器误处理，因此不采用。基于 points/label 计算哈希也会在每次几何或标签修改后改变，不能稳定追踪对象。

### 4. 会话、自然日和对象轮次采用正交标识

会话管理器维护以下关系：

```text
AppSession
└─ ProjectSession（打开到关闭）
   ├─ DaySlice（按本地午夜切分）
   ├─ ImageVisit（每次进入图片）
   └─ ObjectEpisode（一次连续选择/编辑轮次）
      └─ Event / ActionSpan
```

`project_id` 由规范化项目根目录的本机加盐哈希得到，日志不保存绝对路径；`image_id` 由项目内相对定位信息的加盐哈希得到。重新打开同一项目时身份稳定但会话 ID 更新。选择 A、B、A 时，A 的 shape ID 不变，后一次 A 生成新 episode。

UTC 时间负责排序和定位，当地日期与时区偏移负责自然日统计，进程内单调时钟负责时长。系统时钟变化不影响动作耗时。

### 5. 事件是追加的语义事实，高频输入先聚合再写入

事件 envelope 使用固定必需字段和按 `event_type` 校验的 payload。事件目录按应用实例和月份分片保存为 UTF-8 JSONL；每行一个完整事件，文件头信息由独立 manifest 管理。追加 JSONL 便于流式写入、故障后跳过尾行和按时间分片清理。

UI 线程只创建轻量事件并放入有界队列；后台批量写入。队列满、磁盘错误或编码错误只增加内存健康计数并放行用户操作。正常项目关闭和应用退出执行有限时长 flush，不能无限阻塞。

拖拽以 press/commit 或 cancel 形成一个 action span；滚轮缩放、键盘微调和平移使用静默窗口合并成 burst。payload 保存计数、起止摘要、净变化、结果和耗时，不保存中间采样点。异常退出留下的未闭合 span 在读取时标为 incomplete，不补造结束时间。

备选 SQLite 在复杂查询上更强，但首版的写入、迁移、锁与损坏恢复成本更高；统计本来就需要顺序重放状态，因此选择分片 JSONL。若未来数据规模证明 JSONL 不足，可在保持事件契约不变的前提下替换存储后端。

### 6. 功能状态使用版本化注册表

建立显式 feature registry，每项定义稳定键、取值类型、配置值读取器、生效判断器和实际使用判定。启动项目会话时写完整快照版本 1；一次设置事务产生一个 diff 事件和一个新版本；普通事件只引用版本号。无法读取快照时使用版本 0 与 `state_unknown`。

registry 只纳入会改变工作流或输入效果的功能。每项状态表示为：

```json
{
  "configured": true,
  "active": false,
  "used": false,
  "value": "optional_typed_value"
}
```

`used` 可在该功能首次实际参与动作时通过状态变化事件更新，也可由带有功能来源的动作确定性推导；每项功能必须选定一种权威方式，防止双重解释。纯颜色、主题等外观项不进入 registry。

备选方案是在每条行为中复制完整配置，虽然读取简单，但体量大且易产生同一时刻配置不一致，因此不采用。

### 7. 活跃时间通过状态机计算

记录窗口聚焦、用户空闲开始/结束、项目打开/关闭和动作段。统计层分别输出：

- wall：所选边界的墙钟跨度；
- focused：wall 扣除窗口失焦区间；
- active：focused 再扣除超过阈值的无语义活动空闲区间。

动作自身耗时由单调时间起止计算，不从相邻事件时间差猜测。空闲阈值属于分析配置并写入 manifest，保证结果可重现。

### 8. 阶段二采用流式重放和确定性聚合

读取器先按范围筛选分片，再逐行解析、校验并重放 feature state 与会话边界。无效事件分为 parse、schema、required-field、reference、time、state-version、incomplete-span 等原因；能参与部分指标的记录保留，但禁止进入依赖缺失字段的指标。

聚合器产生：

- 次数和结果分布；
- 总计、均值、中位数、P75、P95；
- 同一连续上下文内的相邻转移；
- 3 至 6 阶动作 n-gram；
- 撤销、取消、失败、反向调整和重复编辑回路；
- 对象与 episode 汇总；
- 按 feature `configured/active/used` 的观察性对比。

序列边界至少在项目会话、图片访问、对象 episode 结束或长空闲处断开。排序使用 UTC、单调值和 event ID 的固定复合键；分位数算法和最小样本阈值纳入算法版本，避免不同运行产生歧义。

### 9. 分析包为固定目录契约并原子发布

统计先写入同目标目录下的唯一临时目录，所有文件完成并通过自检后再重命名为最终目录。已存在的完整结果不会被失败任务覆盖。manifest 记录输入范围、schema/算法版本、配置、质量摘要、净化计数、文件大小和 SHA-256。

除 manifest 外，固定文件为：

- `summary.json`
- `action_counts.csv`
- `action_durations.csv`
- `transitions.csv`
- `common_sequences.csv`
- `object_episodes.csv`
- `feature_comparisons.csv`
- `representative_traces.jsonl`

代表性轨迹不随机抽样，按常见、接近中位数、接近 P75、最长、典型失败/回路分别选择，并以固定 tie-breaker 截断。每类上限和总字节上限写入 manifest。导出层再次执行字段白名单，防止未来事件 payload 中的新敏感字段泄漏。

### 10. 配置、入口和可观测性

在应用设置中提供总开关、保留期、空闲阈值和存储位置说明；在行为分析入口中提供范围选择、统计预览、生成/取消、打开结果位置和清理数据。开关默认关闭，升级不自动启用。

内部健康状态只展示累计写入、丢弃、解析失败、最后成功 flush 等汇总，不把日志故障弹窗置于高频操作路径。测试或问题排查可以通过显式诊断模式查看更详细原因。

## Risks / Trade-offs

- [事件接入遗漏导致统计偏差] → 建立事件目录和覆盖矩阵，以语义动作单测、Qt 集成测试及代表性人工流程回放校验。
- [高频操作造成 UI 卡顿或日志膨胀] → 有界队列、后台批写、burst/span 合并、单条 payload 大小限制和压力测试。
- [惰性 shape ID 导致未保存旧文件在不同运行中身份变化] → 明确 ID 只在当前运行内可用；用户真实保存后才跨运行稳定，并在质量报告标记 ephemeral ID 比例。
- [项目路径哈希仍可能被字典猜测] → 使用本机随机盐，不导出盐；分析包默认只保留匿名 ID。
- [日志尾部损坏或版本不兼容] → 一行一事件、分片、schema 校验、未知版本隔离和质量报告；不因单条错误丢弃整个文件。
- [状态重建缺口造成错误功能对比] → 缺失版本的事件退出功能对比但可参与独立指标，并明确报告缺口。
- [观察性差异被误解为功能因果效果] → 输出命名和 UI 文案固定标注“观察性比较”，保留样本量，不自动给因果结论。
- [现有矩形精修统计与新系统双计数] → 单一适配入口和共享事件/关联 ID，增加去重测试。
- [统计任务占用大量资源] → 流式读取、范围预过滤、可取消、进度反馈和代表性轨迹硬上限。

## Migration Plan

1. 先落地事件契约、shape ID 读写和纯 Python 服务，保持总开关关闭。
2. 接入项目/图片/对象/状态和核心编辑事件，使用测试配置验证日志，不改变现有默认 UI 流程。
3. 将现有矩形精修统计接到统一适配器并通过去重回归测试。
4. 加入阶段二读取、统计和分析包导出，使用固定夹具验证确定性和隐私白名单。
5. 发布时仍默认关闭，由用户主动启用；监测本地健康摘要与性能基线后再考虑扩大事件覆盖。

回滚时可关闭功能开关并移除 UI 入口；新增 JSON 顶层字段对支持未知字段的当前读取器保持兼容，旧版或外部转换器可忽略它。行为日志和分析包是派生本地数据，可由用户显式清理，不需要回写标注文件。

## Open Questions

- 默认保留期和默认 burst 静默窗口可在实现期通过性能测试确定，但必须作为版本化配置写入事件或分析 manifest。
- 第一版分析入口放在 Inspector 新 Tab 还是设置/工具菜单，可依据现有 UI 空间选择；两种入口不得改变本规格定义的行为和输出契约。
