## Context

当前 `Canvas` 使用 `epsilon` 作为屏幕稳定的命中尺度，并在命中时换算为图像坐标。原生顶点编辑通过 `nearest_vertex()` 工作；对象候选排序优先顶点，其后按距离、面积和栈顺序选择，因此重叠区域具有小目标优先行为。

现有矩形边编辑已经具备 `idle -> hover -> pending -> dragging` 状态控制、单边几何更新、反翻转、边界约束、取消回滚和 undo，但其鼠标边命中遍历全部可见矩形，不依赖正式对象选择，并在边 press 时主动取消选择。这是本设计需要替换的交互入口；几何与事务能力应继续复用。

本设计承接 `manual-person-annotation-refinement` 中已经完成的矩形边状态重构，不回写该历史变更。行为契约见 `specs/selected-rectangle-edge-editing/spec.md`。

## Goals / Non-Goals

**Goals:**

- 将直接边拖动嵌入既有“选择对象后编辑”的流程。
- 使对象选择、原生角点、单边调整和整体移动具有稳定、可解释的优先级。
- 让普通矩形易于命中边，同时让小矩形内部继续可用于原有选择和整体移动。
- 复用现有状态控制器、几何约束、精修拖动、稳定预览和 undo 边界。
- 用屏幕坐标定义热区，使交互手感不随 zoom 漂移。

**Non-Goals:**

- 不修改对象候选排序、小目标优先算法或正式选择所有权。
- 不修改原生角点阈值、顶点拖动几何或顶点绘制样式。
- 不为“矩形某条边”建立持久对象选择状态；键盘 active edge 保持既有独立语义。
- 不改变矩形 JSON、Shape 数据模型、自动标注或标注导出格式。
- 不在本变更中解决原生角点热区覆盖极小矩形内部的问题；用户可通过放大画布获得更多操作空间。

## Decisions

### Decision 1: 边编辑是正式选中矩形的增强能力

鼠标边候选只从“当前唯一选中的 rectangle”计算。功能开关关闭、无选择、非矩形选择或多选时直接返回无候选。边 press 不再调用取消选择，拖动全过程保持 `selected_shapes` 和 `Shape.selected` 不变。

**Rationale**: 这与现有角点和整体移动的对象所有权一致，也避免重叠框中边命中绕过小目标优先选择算法。

**Alternative considered**: 保留任意可见边可编辑，只在小框上降级。该方案仍存在“未选中对象被修改”和 press 后选择消失的问题，因此不采用。

### Decision 2: 保留主事件流程，只在选中对象编辑阶段插入边判断

事件语义固定为：

```text
既有对象选择与正式选中状态
              ↓
当前选中矩形的原生角点命中
              ↓ 未命中
当前选中矩形的有效边命中
              ↓ 未命中
既有整体移动或其他原生交互
```

活动边拖动仍保留高优先级 move guard，确保拖动开始后不会被平移画布、hover 或重新选择中断。该优先级只适用于已经进入 pending/dragging 的当前选中矩形，不扩展到未选中矩形。

**Rationale**: 选择逻辑和顶点逻辑已经稳定且覆盖多 shape 类型，局部插入比重写统一命中算法风险更小。

### Decision 3: 原生角点是唯一角点真相源

角点继续使用 `nearest_vertex(point, epsilon / scale)`。边命中前只检查当前选中矩形的原生顶点；命中任一顶点即不产生边候选。不得增加独立的 corner radius 或复制角点几何。

**Rationale**: 两套角点半径会形成灰区或重叠区，使相同位置的 hover 与 press 得出不同动作。复用原生判断可保证反馈与实际拖动一致。

**Alternative considered**: 为边功能设置 8px 角区。该值会与默认 10px 原生 `epsilon` 产生 8-10px 歧义，因此不采用。

### Decision 4: 用 `3 × epsilon` 区分普通矩形与小矩形

先把矩形宽高换算为屏幕像素：

```text
screen_width  = image_width  * canvas.scale
screen_height = image_height * canvas.scale
is_small = min(screen_width, screen_height) < 3 * epsilon
```

默认 `epsilon = 10px` 时分界为 30px。普通矩形沿用距边不超过 `epsilon` 的内外双向热区；小矩形只接受位于矩形外侧半平面的边候选，边界内侧由原有选择/移动逻辑处理。顶点排除始终先执行。

矩形外侧判断按边分别计算：left 只接受 `x <= left`，right 只接受 `x >= right`，top 只接受 `y <= top`，bottom 只接受 `y >= bottom`；同时投影必须落在对应有限边段范围内，端点附近仍由原生角点优先规则排除。

**Rationale**: `3 × epsilon` 保证普通策略下在最短轴上仍有约一个 `epsilon` 的中央区域；小框把边热区推出框外后，不再由四条边吞掉内部。

**Alternative considered**: 固定图像像素阈值。它会随 zoom 改变屏幕手感，因此不采用。按长宽轴分别降级更精细，但会让同一矩形四条边存在两种规则，V1 采用整框保守降级。

### Decision 5: 复用现有 pending 和 4px 拖动阈值

有效边 press 进入 pending，记录边引用、widget press 位置和 image press 位置。widget 位移达到现有 `RECT_EDGE_DRAG_THRESHOLD_PX = 4` 后进入 dragging。未达到阈值的 release 只清理 pending、保持选中，不写几何和 undo。

**Rationale**: 这能区分“点击确认当前对象”和“明确拖动边”，并与已经测试过的边事务状态一致。

### Decision 6: 边引用在 press 时锁定，拖动期间不重新仲裁

hover 可随指针重新计算；press 时重新验证当前 hover 是否仍属于当前唯一选中矩形。进入 pending 后锁定该边；达到拖动阈值后沿用锁定边更新，直到提交或取消，不因经过其他矩形、角点或边而切换目标。

**Rationale**: 拖动过程中重排候选会导致目标跳边，重叠标注中尤其危险。

### Decision 7: 继续复用几何与事务边界

单边坐标应用继续走现有矩形几何 helper，遵守图像边界、最小宽高和反翻转。drag start 保存 points；正常 release 仅在几何实际变化时提交一个 undo；Esc、失焦、窗口停用和鼠标抓取丢失时恢复 start points。

精修控制模式继续只改变 drag delta，不改变 hit-test、`epsilon`、大小分类或外侧判断。稳定预览仍为观察者，不参与候选仲裁。

**Rationale**: 本变更只改变“谁可以进入边拖动”和“哪里算边”，不复制已经稳定的几何及事务实现。

### Decision 8: “矩形框编辑”开关收窄为单边调整开关

保留现有 action、快捷键和配置接线，避免迁移用户设置。关闭时完全绕过新增边候选；开启时只为当前唯一选中矩形增加单边调整。开关不创建独立选择模式，也不改变角点和整体移动。

用户可见名称是否从现有文案改成“矩形单边调整”由实现阶段按当前翻译资源确认；无论文案是否调整，行为语义按本设计固定。

**Rationale**: 保留开关提供兼容和误触回退，同时避免用户把它理解为另一套对象选择工具。

### Decision 9: 状态变化必须主动失效旧边引用

以下事件统一清理 mouse hover、pending 和 active edge：正式选择对象变化、多选状态变化、功能关闭、进入绘制模式、切图、shape 删除/隐藏、Esc 取消以及应用失焦。活动拖动先按事务规则提交或回滚，再清理引用。

**Rationale**: 边候选现在依赖选择身份，任何选择或生命周期变化都会使旧引用失效。

### Decision 10: 测试按纯命中、状态仲裁和 Canvas 集成分层

纯命中测试覆盖屏幕尺寸分类、内外半平面、有限边段和角点排除；状态测试覆盖 idle/hover/pending/dragging；Canvas offscreen 测试覆盖选择保持、小目标优先不回归、光标/高亮、undo 和取消恢复。测试矩阵至少包含 50%、100%、200%、400% zoom 以及普通框、小框、细长框和重叠框。

**Rationale**: 将几何判定与 Qt 事件分开后，阈值边界可以稳定单测，少量集成测试负责验证真实事件顺序。

## Risks / Trade-offs

- **[Risk] 极小矩形仍可能被原生角点热区覆盖** → V1 明确保留原生行为，通过 zoom 放大处理；若实测仍阻塞移动，再另立角点降级设计，避免本次偷偷改变原生语义。
- **[Risk] 从全局边编辑改为仅选中边编辑会增加一次选择动作** → 这是有意的安全性调整；保留开关并提供一致 hover，降低学习成本。
- **[Risk] 30px 分界附近缩放会切换热区策略** → 分类只影响 hover/新 press；pending/dragging 锁定按下时的边，不在手势中切换。
- **[Risk] 外侧热区可能与邻近对象重叠** → 只计算当前唯一选中矩形，其他对象不能抢占已开始的边手势；未进入边候选的位置继续走原选择算法。
- **[Risk] 现有键盘 active edge 与鼠标边 hover 状态可能互相清理** → 保留既有“鼠标 hover 接管键盘边”规则，但接管仅在当前唯一选中矩形产生有效边候选时发生。
- **[Risk] 文案继续称“矩形框编辑”可能让用户误解** → 优先评估改为“矩形单边调整”，同时保持 action/config 标识不变以降低迁移风险。

## Migration Plan

1. 先补充命中策略和事件仲裁回归测试，记录当前失败行为。
2. 将全局可见矩形边候选收窄为当前唯一选中矩形，并移除边 press 的取消选择动作。
3. 加入屏幕尺寸分类和小矩形外侧半平面过滤，复用原生角点排除。
4. 接通选择变化和生命周期事件的状态清理，校验稳定预览、键盘选边和精修模式。
5. 运行目标测试、PyQt offscreen 回归和人工 zoom/重叠场景验收。

回滚时恢复原全局边候选入口和 press 取消选择行为；Shape 数据和标注文件无迁移需求。功能开关也可作为运行时快速回退路径。
