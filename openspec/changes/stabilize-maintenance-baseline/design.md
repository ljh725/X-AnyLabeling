## Context

上轮完整回归在 Windows 上观察到停止训练后 `join(3)` 超时。单凭断言失败无法判断子进程、读管道与清理各自的进度。规格与历史引用的背景见 [提案](proposal.md)。

## Goals / Non-Goals

**Goals:** 保留两个固定提交的独立复现和可关联的单调时钟证据。把历史链接映射到归档后的实际文件。

**Non-Goals:** 训练停止的运行时修复由后继变更承接。其他失败继续由上轮报告跟踪。

## Decisions

- 矩形预览以当前拟合契约、手册和实现为依据。先记录完整需求增量，再将同一内容同步至主规格。
- 使用两个独立 Git 工作树固定来源，并在同一 conda 环境串行交替运行原 pytest 节点，每边至少三次。用外部观察器记录调用、子进程状态、线程等待栈和退出。保留原 pytest 断言和 3 秒阈值。
- 在现有审计补充直达链接，避免重写历史证据与当时的测试结论。

## Risks / Trade-offs

- 观测可能引入少量时序开销。保存原始时间线和操作方法，必要时用无观察器运行作对照。
- 仅凭两边同样失败无法确定归因。以停止请求实际走过的代码和线程等待位置作判断。
