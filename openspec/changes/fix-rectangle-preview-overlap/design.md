## Context

动机见 `proposal.md`。当前创建链路在 `canvas.py::paintEvent` 中先调用 `_draw_rectangle_crosshair()`，再调用 `self.line.paint()`。当前 `_paint_point_fit()` 已在普通形状之后绘制，但下层原框会填满虚线间隙。`show_masks` 还在普通 Shape 绘制前描一次矩形轮廓，必须一起处理。

历史 `966e1456`、`a0cc74a0` 有先矩形后十字线的顺序，后续 `9e569a7c` 已反转。历史证据可供恢复顺序，未包含完整共边避让算法。

本变更同时影响 Shape 通用描边与 Canvas 的多个入口，故显式维护设计文档。现有 Inspector 和画布控制迁移仍在工作区，不能整文件覆盖或回退。

## Goals / Non-Goals

**Goals:**

- 通过当前帧局部轮廓替换解决共边混叠，复用当前创建和拟合几何。
- 普通轮廓与遮罩轮廓共用同一份绘制信息；临时信息不写入 Shape 或持久配置。
- 新计算限于一组四边，且兼容现有调用、缩放、顶点及撤销行为。

**Non-Goals:**

- 不改 Shift/Shift+Alt 的角点选择、内外拟合、命中、提交算法。
- 不为所有重叠标注做全局避让，也不复制 beta.4 的整套 Canvas/renderer。
- 不引入文件扫描、数据库、线程、菜单、资源或用户配置迁移。

## Decisions

### 1. 用边段差集构建临时轮廓

新增拟名 `anylabeling/views/labeling/rectangle_preview.py`，仅依赖 Qt 的几何/路径类型，不导入 Shape 或 Canvas。矩形规范化为四条轴对齐边；同向共线边求一维正长度交集，从原边扣除交集后构建开放线段路径。拟合至多做 4×4 次比较，创建将四边与两条引导轴比较。

共线容差只处理浮点数误差；“相近”不能等价于共线。描边线帽和抗锯齿的端点余量由实际屏幕线宽和缩放换算，在区间范围内裁限，不参与几何/命中计算。退化、非有限输入不生成新的避让。

备选：只调整层次仍会露出底层实线；用背景色擦除会遮图；平移候选边会使预览边界偏离实际坐标。因此采用只省略重复描边的方式。

### 2. Shape 增加单次描边路径覆盖

拟将 `Shape.paint` 扩展为 `paint(painter, *, outline_path=None)`。仍生成原有完整路径及顶点，只有描边时选择覆盖路径，填充仍使用完整路径。`None` 沿用原轮廓，空路径表示轮廓确实为空，不能按真假值回退。现有 `paint(painter)` 调用不变。

Canvas 遮罩分支使用相同覆盖路径描边，完整 mask_path 仍用于填充。顶点与高亮手柄不受整形状裁剪影响。其他图形类型保持原有通路。

备选：临时修改 Shape 的点、颜色或可见性会让预览渗入数据/命中/撤销；裁剪整个 Shape 会连带裁掉填充和手柄。因此通过调用参数传递局部描边路径。

### 3. 同一帧只准备一份有效拟合显示信息

在 `paintEvent` 开始时确认目标仍是唯一可操作矩形、候选有效且与原几何不同，再固定本帧的目标引用、原几何、候选几何、共享边段和剩余轮廓。普通 Shape、遮罩、候选叠层和引导资格判定消费同一份信息；不重复推断角点。

2026-11-04 复核补充（已实施，对应任务 4.6）：单帧快照还必须验证候选的来源几何。原 `_build_point_fit_preview()` 重新读取目标几何，却直接使用 `_point_fit_pending_box`；同一 Shape 实例被键盘微调后，仅校验目标引用不足以证明候选仍有效。

候选计算时应保留目标身份与原坐标快照，作为 Canvas 内的临时状态，不写入 Shape、标注 JSON 或配置。形成绘制快照前比较来源与当前几何：

- 未按下捕获的悬停预览：原几何变化时，使用当前目标、已记录指针和现有 Shift/Shift+Alt 语义重算候选；以重算结果统一决定候选、剩余轮廓和十字线显示。重算无效时恢复当前原框完整轮廓，并按既有规则显示无效位置反馈。
- 已按下捕获的拟合手势：若原几何与按下时快照不同，取消该手势并消费其鼠标释放；保留其他编辑入口产生的新几何，不基于变化后的框重新选择固定角或提交旧候选。后续新手势仍可正常开始。
- 仅当来源变化时执行所需重算，不在普通轮廓、mask 与候选入口各自推断一次，不引入目录/文件扫描或长期缺边缓存；刷新预览不新增 dirty、撤销或保存操作。

候选采用完整矩形路径一次描边，RGBA `(220,130,0,255)`、2.0 屏幕像素、cosmetic DashLine；保留固定角及指针标记。原框非共边不重新配色。候选与原框相同则保留完整原框并抑制重复候选轮廓；无效候选使用现有红色反馈，不应用避让。

备选：在每个入口独立判断会遗漏额外轮廓，且可能出现“原框已缺边、候选却不再有效”的不一致。因此统一当前帧判定。

### 4. 创建与拟合分别安排层次

创建顺序为已有图形 → 草稿剩余实线 → 青蓝色十字虚线 → 原有标签/尺寸信息。只在创建引导实际可见时对当前两点草稿避让；关闭引导或四极值/其他创建方式继续画完整原预览。忽略其他已存在标注与引导共线的情况，保持其正式轮廓。

拟合先画原框剩余轮廓，再画完整橙色候选。有效且不同的拟合预览期间，原生常驻十字线临时让位；结束后按原配置恢复。所有画笔变更用 save/restore 隔离，显示抑制不写配置。

### 5. 保持当前清理与编辑链路

使用现有失焦、取消、切图、修饰键和模式清理入口。临时路径每帧重建且不存入 Shape，退出预览后不传覆盖路径，原框自动恢复。提交和撤销继续由现有代码处理，不增加预览命令。

备选：维护长期缺边缓存需新增失效机制，在切图、候选变化和多选时更容易留残影。因此选择小规模逐帧计算。

### 6. 以可观察像素和行为验证

几何测试覆盖全/局部共边、相交、近邻、不变和无效候选。真实 Canvas 离屏渲染检查虚线间隙没有原描边、非共边保留、取消恢复；不能只验证函数顺序。采样避开有意存在的顶点、固定角和指针标记，考虑抗锯齿。

覆盖 0.25/0.5/1/2/4 倍缩放、四象限、小框/图边、遮罩和常驻线开关；几何用广覆盖参数化，像素与交互采用有代表性的组合。预览前后比较序列化、坐标、dirty 及撤销；提交后一次撤销恢复。补充完整画布导出检查，确保无预览上下文时导出轮廓完整。

2026-11-04 新增验证场景（已由 `test_keyboard_nudge_invalidates_hover_candidate` 等 8 项回归覆盖）：原框 `(100,100,200,200)` 在 Shift 指针 `(151.5,120)` 时得到候选 `(100,120,151.5,200)`；原框被右方向键移动 1 像素后为 `(101,100,201,200)`，同一指针应重算为无效候选。通过真实键盘事件和离屏像素同时确认旧橙色候选消失、当前原框完整且十字线按配置恢复。另覆盖重算仍有效、Shift+Alt 以及捕获后几何改变的取消/释放路径；区分键盘编辑的正常 dirty/撤销与预览刷新应有的零副作用。现有 127 项相关测试通过不覆盖该反例，不作为修复证据。

## Risks / Trade-offs

- [遮罩或其他入口重新画回原实线] → 普通轮廓与 mask 轮廓共享快照；像素验证打开遮罩；复核当前实际描边入口。
- [把接近但不共线的边隐藏] → 数值容差与线宽端点余量分开；用接近边、零长度交点反例验证。
- [短边受线帽/固定角影响] → 屏幕余量裁限、正确选择端帽；小框和多缩放采样，保留有意标记。
- [Shape 通用绘制回归] → 新参数关键字可选且默认路径不变；覆盖其他创建模式、填充、顶点及无预览导出。
- [共享文件有并行工作区修改] → 实施前检查差异并按功能归集最小改动，不批量替换 Canvas；状态记录区分本项和既有修改。
- [离屏颜色清晰而真实图像难辨认] → 保留橙色候选、青蓝引导的角色区分；真实屏幕深浅背景验收记录单列，不能由离屏测试代替。
