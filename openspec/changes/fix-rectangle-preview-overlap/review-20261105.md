## 验证缺口：dirty 状态没有被新增回归检查

- 对应任务：5.3 要求预览和取消前后比较 dirty；5.6 要求将键盘微调本身应有的 dirty 与预览的零副作用分开断言。
- `tests/test_canvas/test_rectangle_preview_overlap.py:231` 的 `snapshot()` 仅包含 Shape 序列化和撤销栈。悬停重算、候选失效和捕获取消用例比较这个快照，没有挂接主窗口 dirty 状态，也没有监听这些阶段是否额外发出提交信号。
- 主窗口在 `label_widget.py:682` 将 `canvas.shape_moved` 接到 `_on_geometry_committed()`，该方法调用 `set_dirty()`。所以即使坐标及撤销栈不变，额外提交信号仍可能让主窗口变脏并触发自动保存。
- 为确认这一缺口，本轮仅在独立 Python 进程内临时包装 `Canvas._build_point_fit_preview`，在存在预览时额外发出 `shape_moved`。未写回源码；现有 43 项预览测试依然全部通过。这是测试敏感性检查，不是当前实现的故障复现。

补齐要求：在悬停、重绘、取消及来源重算阶段验证 dirty 不变且无额外提交信号；键盘微调阶段验证正常 dirty/一次提交信号，再验证重绘与捕获取消/释放不增加信号；有效拟合提交保留正常 dirty 与一次撤销语义。应确保上述进程内错误行为能被测试检出，再关闭 5.3、5.6。
