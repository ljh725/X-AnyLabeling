## Context

参见 `proposal.md` 的动机。当前 `run_object_relabel_flow()` 在收到任意 `ObjectRelabelResult` 后先显示通用模态结果框，用户关闭后才调用 `on_finished(result)`。缩略图入口因此无法在自己的顶层窗口中即时应用结果；主窗口状态栏又位于另一个窗口。缩略图页面通过 75ms 单次定时器重查 SQLite，普通选择会在换页/换标签时清除，只有失败、冲突或取消对象通过 `_retained_selection` 恢复。

统一对象改标流程同时服务主菜单和缩略图入口。本变更不能为缩略图建立第二套 JSON 写盘路径，也不能让主菜单入口无意失去现有终态反馈。现有 manifest 保存原始指纹和备份，但恢复阶段尚不能证明文件在提交后未被再次编辑。

## Goals / Non-Goals

**Goals:**

- 让缩略图数字改标正常终态只保留一次提交前确认，不再要求关闭提交后结果框。
- 在缩略图顶层窗口内持续、准确地呈现结果、失败详情和本次恢复信息。
- 在索引及页面状态重新稳定前阻止缩略图再次提交。
- 维持主菜单入口、统一对象身份、预检、暂存、原子提交和结构化结果语义。
- 让从结果条发起的文件级恢复不会静默覆盖原事务之后的编辑。

**Non-Goals:**

- 不移除提交前预检确认，也不新增“单对象免确认”快速模式。
- 不改变数字→标签共享绑定；未绑定数字仍保持无操作。
- 不实现跨文件普通撤销/重做栈，不把 manifest 恢复命名为 Ctrl+Z 撤销。
- 不增加跨页普通选择；普通选择仍限制在当前页。
- 不改变结构化对象状态枚举或对象永久身份协议。

## Decisions

### 1. 使用缩略图窗口内独立结果条

在 `DatasetLabelThumbnailWindow` 顶部控制行与缩略图列表之间增加独立结果 `QFrame`，包含结果文本、可选的“查看详情”“恢复本次…”以及关闭按钮。该结果条与显示 `Selected: X objects in Y files` 的 `summary_label` 分离，并持续到下一次改标开始、用户关闭或窗口关闭。

选择持久窗口内结果条而非主窗口状态栏，是因为缩略图是 `Qt.WindowType.Window` 顶层窗口；选择它而非短时 Toast，是因为部分失败和恢复清单需要在用户继续检查缩略图时保持可访问。

### 2. 统一流程支持调用方接管结构化终态呈现

为 `run_object_relabel_flow()` 增加默认保持兼容的结果呈现选项。主菜单入口沿用通用结果对话框；缩略图入口关闭通用结果框并通过现有完成回调接收同一个 `ObjectRelabelResult`。流程仍负责 worker 排空、进度框关闭、`BatchWriteGate` 释放和终态只交付一次。

不在 `object_relabel_dialog.py` 中直接操作缩略图控件，以维持事务 UI 协调器与具体入口视图之间的依赖方向。

### 3. 先应用结果，再恢复入口可用性

`LabelingWidget._launch_object_relabel()` 的完成闭包应按以下顺序处理缩略图结果：

1. 保持 `_object_relabel_running` 为真；
2. 同步标记集合、当前画布和数据集索引；
3. 把终态交给缩略图窗口，使其更新失败 overlay、保留选择、结果条并进入本地刷新屏障；
4. 完成同步结果应用后恢复主菜单 action；
5. 缩略图自己的按钮和数字快捷键继续由刷新屏障控制，直到最新页成功装载。

这避免 action 先恢复、结果随后才应用的瞬时窗口。主菜单 action 与缩略图本地改标能力分开恢复，因为主菜单计划直接读取权威 JSON，而缩略图必须等待派生索引和当前页稳定。

### 4. 增加缩略图本地刷新屏障

窗口新增 `_relabel_refresh_pending`。收到包含已提交路径的终态时置为真；`_apply_digit_shortcut()`、`_request_relabel()` 和按钮 enabled 计算均检查该状态、控制器 busy 状态以及索引 ready 状态。`_load_page()` 只有在查询成功并替换模型后才能清除屏障。索引刷新失败时窗口进入现有 unavailable 状态并保持改标不可用，直到用户刷新或重建成功。

当前 `QShortcut` 仍保留 `WindowShortcut` 和输入控件焦点保护；`_object_relabel_running` 与 `BatchWriteGate` 继续作为上层重入及写入串行化防线。

### 5. 结构化结果使用确定的分类和片段组合

以 `succeeded=S`、`unchanged=U`、`deleted=D`、`conflict=C`、`failed=F` 分类：

| 条件 | 级别 | 标题 |
|---|---|---|
| `S>0, C=F=0` | success | 已完成 |
| `S=0, U+D>0, C=F=0` | neutral | 无需写入 |
| `S>0, C+F>0` | warning | 部分完成 |
| `S=0, C+F>0` | error | 未完成 |
| 全部为零 | neutral | 未执行 |

正文只拼接非零片段：`{S} 个已改为“{target}”`、`{U} 个原本已是目标标签`、`{D} 个已不存在`、`{C} 个身份冲突`、`{F} 个处理失败`。部分或全部失败追加“失败项已保留选中”。取消不参与上述混合矩阵，因为当前 `cancelled_result()` 保证所有对象统一为 cancelled：预检进度取消、确认点 No、暂存取消分别使用不同文案，均说明未进入提交。

### 6. 恢复按钮绑定准确 manifest，但不是一键撤销

结果条仅在存在成功提交文件及有效 `manifest_path` 时显示“恢复本次…”。点击后直接把该路径传给恢复入口，不打开文件选择框；查看详情显示并允许复制完整路径。恢复仍要经过 dirty 处理和显式文件级恢复确认。

提交成功后为每个 manifest entry 记录 `committed_fingerprint`。恢复前逐文件对比当前源文件：一致的文件进入恢复，不一致的文件记录冲突并保持不变，但不阻断同一清单中其他已通过校验的文件。最终结果分别汇总已恢复、冲突和失败文件数量。不一致或新格式清单缺少可验证状态时不得静默覆盖；旧清单继续可从菜单选择，但不得通过缩略图快捷入口无提示恢复无法验证的文件。

选择事务恢复而非对象级逆向变换，是因为当前 manifest 已有逐文件备份且本变更不引入跨文件撤销栈；指纹屏障明确限制了文件级恢复可能覆盖后续编辑的风险。

### 7. 结构化失败非模态，非结构化致命异常保留强提示

身份冲突、读取失败和文件提交失败都存在于 `ObjectRelabelResult`，缩略图已经能保留对应项并展示 mutation error overlay，因此结果条足以承担汇总与详情。worker 抛出异常等无法产生可信终态的情况仍走现有致命错误路径，避免把未知提交状态降级成普通提示。

## Risks / Trade-offs

- [结果条占用垂直空间] → 使用紧凑单行摘要和可展开详情，默认隐藏无结果状态。
- [索引信号先于缩略图收到结果] → 上层先完成同步索引更新，再由缩略图设置屏障并执行一次最终页面重载；控制器 busy 或 stale 时屏障不得提前解除。
- [结果条关闭后恢复路径不可见] → 菜单恢复入口继续存在；关闭仅隐藏本次快捷入口，不删除 manifest。
- [旧 manifest 无提交后指纹] → 不允许通过新快捷入口直接恢复，保留明确的兼容性提示和原菜单审慎入口。
- [主入口与缩略图入口反馈分叉] → 两者共享唯一结构化结果和格式化数据，只允许呈现载体不同，事务逻辑保持单一。
- [部分成功后立即继续可能作用于旧项] → 本地刷新屏障覆盖按钮和数字快捷键，并在模型替换完成后才解除。
- [单个恢复冲突导致整批可恢复文件被阻塞] → 恢复预检和执行均按文件隔离；冲突文件跳过，其他通过校验的文件继续恢复，结果明确分项汇总。

## Migration Plan

1. 先扩展 manifest 写入和恢复校验，保持读取旧清单兼容。
2. 为统一改标流程增加默认兼容的调用方呈现选项，确认主菜单行为不变。
3. 增加缩略图结果条、刷新屏障和准确 manifest 恢复信号。
4. 更新翻译资源并运行缩略图、对象改标和恢复相关测试。
5. 若需要回滚 UI，可恢复缩略图通用结果框；新增 manifest 字段为向后兼容字段，无需迁移既有标注 JSON。
