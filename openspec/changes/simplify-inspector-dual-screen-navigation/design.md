## Context

动机与范围见 [proposal.md](proposal.md)。当前 Inspector 已是独立非模态 `QDialog`；主窗口的 `inspection_navigate_to()` 能切图、按稳定身份选中对象并聚焦区域。现有列表单击只刷新详情，上一个／下一个只切换行，保存回调不会自动执行规则复查。

本设计基于当前代码，延用 `refactor-data-inspector-workflow` 的检查、反馈、报告和编辑桥接，不把旧设计文档中的“尚未实施”描述当成当前代码状态。该变更保留的人工验收待办继续独立存在，本次规划不会替它们勾选完成。

用户于 2026-11-06 确认的最终参考图为 [双屏独立窗口效果图](assets/inspector-dual-screen-approved.png)。图中两屏布局、单一主画布、F1／F2 和主要操作用于表达交互；示例图片、对象编号、计数、尺寸及像素位置不构成实现约束。

## Goals / Non-Goals

**Goals:**
- 使显式选择问题、按钮导航和快捷键导航共享一次可靠的切换过程，避免列表与画布指向不同问题。
- 保留完整主画布，在独立检查窗口中完成发现、解释、忽略和复查，支持两个窗口间连续操作。
- 将保存、规则复查和可选推进串起来，同时保留既有身份、撤销、持久化及逐来源验证语义。
- 在界面收敛时保持旧报告、反馈和高级能力可用。

**Non-Goals:**
- 不重写规则引擎，不新增第二个图像查看器、缩略图、标注画布或主窗口停靠面板。
- 不新增操作系统全局热键，不让其他程序、模态编辑器或尚未提交的绘制操作触发队列导航。
- 不自动决定重复对象中应删除哪一个，不直接写标注 JSON，不新增整图／整文件删除功能。
- 不把“已解决”解释为图片质量合格，不改变原有审核字段，也不迁移报告格式。

## Decisions

### D1. 延用独立非模态窗口，记住可见位置

保留 `InspectorDialog` 的独立窗口生命周期、可移动／缩放能力和单实例入口。主窗口不增加检查结果停靠区；打开、移动、最小化和关闭检查窗口均不重新布局主画布。

通过已有本地配置保存路径记忆 Inspector 的窗口位置、大小及自动推进偏好。恢复位置时校验当前屏幕可用区域，第二屏拔除或布局变化后把窗口移回可见屏幕；不把屏幕编号写入检查报告，也不要求用户必须有双屏才能使用。

选择延用现有窗口而非新建双屏管理器，可以保留现有单屏工作方式和主窗口编辑归属。停靠面板会缩小画布，另一套编辑器会产生两份编辑状态，均不采用。

### D2. 默认界面围绕问题处理，高级能力按需展开

主界面按以下顺序呈现：

1. 规则方案、检查范围、规则设置、开始／取消检查和运行状态。
2. 待处理／已解决／已忽略视图及必要规则筛选；列表突出图片、问题原因与对象。
3. 一组“上一个问题 F1／下一个问题 F2”按钮、当前位置及主窗口联动提示。
4. 当前问题简短说明、关联对象选择、忽略入口、保存并复查和自动推进选项。

阶段选择、历史恢复、方案与报告管理、外部候选、密集复核、批量动作及详细状态收进“更多”或按需展开区域，保持可达。阶段虽然不再常驻，生效值仍在规则说明中可查，不能因视觉收敛而静默修改执行配置。

默认区不保留“确认错误／标记已修改”等与实际编辑混淆的前置操作。已有底层动作仍可由高级入口使用；修改、改类、删除和撤销由原主画布完成。效果图不是要求重绘整个主窗口工具栏。

### D3. 三类视图是现有状态的投影

不增加覆盖旧反馈语义的另一套完成状态。统一按以下优先级分组并统计：

| 判定顺序与界面分组 | 条件 |
| --- | --- |
| 1. 待处理 | 待复查、过期、无法核验；失效的旧忽略或旧解决也回到这里 |
| 2. 已解决 | 当前输入和相关配置可核验，当前问题所有相关有效来源成功、完整复查且均未再检出，不被旧待处理／确认错误等人工判断覆盖 |
| 3. 已忽略 | 未归入前两项，且当前上下文中仍有效的误报或可接受判断 |
| 4. 待处理 | 其余情况，包括尚未成功验证解决的待处理／确认错误／需讨论问题 |

首次进入默认为“待处理”。“忽略此问题”写入现有可接受判断并保留来源，既有误报也归入已忽略；忽略只排除待处理，不声称规则复查通过。详细证据继续显示实际人工判断、动作和机器状态。

分组采用同一派生逻辑供计数、筛选和导航使用，避免按钮导航经过不可见条目。继续暴露旧机器状态筛选而让用户组合多个条件较难理解；直接压成新的单状态又会丢失验证信息，故采用界面投影。

### D4. 所有用户导航经过一次事务式切换

显式点击问题、用户用键盘改变当前问题、上／下一个按钮及对应快捷键进入同一导航入口。程序填表、恢复游标、更新计数或合并复查结果只更新呈现，不通过通用 `selectionChanged` 信号无条件跳图。

一次切换保留原问题稳定键、筛选／页码、文档和对象选择，先确定目标及可定位上下文，再调用主窗口既有切图与未保存提示路径。只有主窗口加载和所需定位成功，才提交新的队列游标、页码和详情；取消离开、保存失败、加载失败或身份不可信时恢复原队列选择并保持原文档上下文，明确显示失败原因。必要的主窗口桥接应支持导航前校验及失败恢复，不能以表格已选中作为成功依据。

定位始终使用数据集、输出目录、相对文件及持久对象身份。图片／区域级问题不伪造对象；对象已删除或身份不可核验时提示复查，不把另一个同序号对象当作目标，也不自动略过失败项。

复用主窗口导航可以继续遵守锁定、隐藏、保存和编辑规则；新增文件加载捷径容易绕过这些行为，因此不采用。多对象问题可显示并选择具体对象，只有明确选中的可编辑对象才进入原删除／改类链路。

### D5. 导航顺序基于筛选后的完整队列

以当前筛选后的稳定顺序和问题稳定键计算前后项，跨分页时按需加载目标页，不局限于当前 200 行。界面计数是该筛选范围中的问题位置，不能使用图片序号替代。同一图片多个问题依次定位对象，跨图片才切图。

队列首尾不循环；相应按钮禁用，快捷键无副作用。仅在既无选中项也无有效导航锚点时，F2 进入第一项、F1 进入最后一项；空队列全部禁用。复查解决导致当前项移出筛选时保留该项稳定键及原顺序位置作为锚点，后续 F1／F2 从此处寻找仍可见的前驱／后继。改变筛选或刷新导致原项不再可见时，只清理当前选择或保留结果摘要，直到新的显式导航请求才切换主画布；上下文改变使锚点不可用时才采用首项／末项规则。

不按文件排序键重建另一份导航顺序，避免同图多问题丢失；不以界面行号作为持久游标，避免复查、删除和分页后指向错误对象。

### D6. F1／F2 绑定两个相关窗口，统一守卫

新增配置项 `inspector_previous_issue` 和 `inspector_next_issue`，默认分别为 `F1`、`F2`，接入现有配置 schema、冲突检测及运行时更新。按钮提示从实际生效配置生成；清空或改键立即同步两个窗口，不遗留旧绑定。

主窗口与 Inspector 分别注册窗口作用域动作，调用同一导航入口，并确保只有当前相关活动窗口的动作响应一次。主窗口可复用 `runtime_applier.py` 的隐藏动作设施；Inspector 生命周期内幂等注册和解绑。不用应用级或操作系统级热键，以免无关窗口操作也切图。

统一守卫覆盖队列有效性、数据集绑定、活动窗口和忙碌状态：模态窗口打开、主画布绘制／拖动未提交、检查或保存复查执行中均不导航。关闭 Inspector 结束当前导航会话并停用绑定；最小化不结束有效会话，在主窗口仍可用 F1／F2，且不自动弹回或抢焦点。

从主窗口按键后保持主窗口焦点，便于继续拖动、改类或删除；从检查窗口按键或点击后保持检查窗口焦点，便于连续浏览。导航不得为了选中对象主动激活另一个顶层窗口。

### D7. 保存并复查是显式串行操作

该按钮仅处理当前已成功定位、且与主画布同图的问题。成功定位后删除了问题对象仍可复查该图片，不要求重新选中已删除对象；定位依据是本次成功的图片上下文。用户手动切到其他图片后禁用按钮并说明需重新定位，不能误把另一张图片保存后当作当前问题已修复。

操作开始时冻结当前问题稳定键、数据／输出身份、文档版本、报告方案及后继顺序，进入忙碌状态；先通过主窗口常规保存流程确认标注保存成功，再沿原报告冻结方案执行当前图片复查。未修改的文档可以按既有保存语义确认后复查，保存失败或取消则立即停止。

复查仍使用现有逐来源覆盖与合并机制，保留其他图片的结果、新发现问题及历史依据。复查期间文档或上下文变化，或用户通过其他入口手动切图／换问题时，本次结果不得驱动自动推进或抢回导航；回调应核对开始时的导航代次与活动问题。新报告与反馈成功持久化后再完成本轮处理；若持久化失败保留内存结果和重试入口，并停留当前项。

不把普通保存回调改成无条件检查入口：普通 Ctrl+S 继续只做原保存工作，显式“保存并复查”才启动这条串行流程，避免保存候选、其他文件或自动保存造成隐式跳转。

### D8. 自动推进依据验证结果，允许用户停留

“通过后进入下一个问题”默认勾选并记住选择。仅在 D7 全部成功且当前问题所有相关有效来源完整未再检出时推进，失败、取消、截断、未执行、规则停用或任何来源仍命中均停留并显示原因。

推进时以操作前的稳定后继为锚点，在合并后的当前筛选队列中寻找仍需处理的后继；原后继已解决时顺序后移，不因当前行移除而额外跳过一项。新发现问题纳入当前排序并保留，不在后继范围内的新问题也不能被丢弃；没有稳定后继则保留当前摘要并显示队列终点，若仍有待处理项则提示剩余数量供用户显式选择，不自动环回。队列清空显示处理完成摘要，不标记图片正式审核通过。

用户关闭自动推进后，即使当前项从待处理列表移出，也保留当前图片、已解决摘要及 D5 的导航锚点供核对，下次显式导航从原位置继续，不按“无选中”重新从头或从尾开始。撤销／重做或再次编辑使相关结论待复查，并重新进入待处理视图；成功解决不是永久隐藏。

## Risks / Trade-offs

- [列表刷新引发意外切图] → 区分用户导航和程序刷新；用稳定键回填选择，测试刷新／复查不会触发未保存提示。
- [两个窗口注册同键导致一次按键走两项] → 窗口作用域、统一守卫和幂等生命周期；测试两窗口焦点、重复打开及动态改键。
- [切图取消后列表与画布错位] → 仅成功提交游标；覆盖保存失败、加载失败和身份失效的回退，不静默跳过。
- [第二屏移除造成窗口无法找回] → 恢复几何前核对可见区域，保存位置仍不影响单屏打开。
- [三种视图掩盖旧判定差异] → 保留详细状态与来源；过期／待复查优先回待处理，忽略不计为已解决。
- [保存成功但检查或报告持久化失败] → 停留并分别呈现保存／复查结果，不回滚已成功保存的标注，不自动推进。
- [双屏焦点及缩放无法由离屏测试完整证明] → 自动测试验证状态和调用；真实双屏、不同缩放比例及屏幕移除另留人工验收记录。

## Migration Plan

1. 基于当前 Inspector 实现增量修改，先固定导航／状态回归，再调整界面和快捷键；不覆盖其他活动变更。
2. 新快捷键及窗口偏好使用现有配置缺省值兼容旧配置。历史报告、反馈和会话继续读取现有格式，恢复时照旧核验上下文。
3. 更新文案、翻译、操作说明及本变更的验收记录。自动回归与真实双屏验收分别记录，未开展的人工项保持未完成。
4. 回退仅撤销本变更的界面、桥接、配置默认项和资源差异；未知的新配置键由兼容机制处理，保留用户标注、报告、反馈和其他变更的工作。
