## Goals / Non-Goals

**Goals:**
- 普通使用者只需要选方案、选范围、开始检查、处理和复查；间隔一段时间后仍能理解规则。
- 通用与场景规则独立维护，计算、输入适配、报告和界面清晰分层。
- 复用可靠逻辑，同时修复身份、取消、输入版本和人工反馈有效性等衔接缺口。
- 重复检查作为整套检查中的一个能力，与其他规则合并呈现但保留独立依据。

**Non-Goals:**
- 不为所有标注任务开发通用可视化编程语言，不在配置中运行任意代码。
- 不在本变更内新增模型推理、模型下载、视频跟踪、自动补全遮挡目标或无确认批量改标。
- 不迁移整个双屏模块、不替换当前画布、不重写密集复核工作区。
- 不保证找全漏标，不以问题清零、红色风险或模型分数代替验收。

## Decisions

### D1. 单一日常入口，保留高级能力

用户主要流程为“选择检查方案 → 选择范围 → 开始检查 → 点击问题处理 → 复查 → 继续人工复核/查漏”。面板初始呈现：

```text
检查方案 [屏幕四角点 ▾]  阶段 [标注后 ▾]
范围 [当前数据集 ▾]     [规则说明与设置]
本次启用：标签、图形、逐屏幕角点完整性、疑似重复框
[开始检查] [继续上次处理]      运行时：[取消]
已检查 128/140 张；9 张有问题；2 张失败；10 张未执行
[问题列表] [运行记录]         高级：[外部导入/导出]
```

数值仅为界面示例。规则说明、参数、例外、上次运行与数据来源可直接查看；错误详细日志可展开。首期保留必要列表和反馈交互，旧数据表格编辑及按规则复制原始数据的导出不作为迁移前置依赖，正常编辑统一交回画布。外部导入仍可使用，但软件内运行不要求用户找结果文件。

选择此入口以减少切换页签和记忆命令。保留五个旧页签原样不利于日常使用；整套重做界面会扩大迁移风险，因此先改主流程、按需保留高级入口。

### D2. 规则目录与场景方案分离

计划新增纯 Python 检查服务目录（如 `anylabeling/services/inspection/`）和 Inspector 界面目录。规则目录登记 `rule_id`、`implementation_version`、中文名/说明、正反例、参数约束、输入形状、作用域、依赖字段及执行适配器。场景专用规则以独立模块登记，不能表达为通用规则的业务逻辑不强行塞进公共引擎。

方案配置为带 schema 的数据文件：`profile_id`、`profile_version`、显示名称、说明、阶段、启用规则及参数、标签绑定、例外和类间关系。规则实现版本也进入有效配置摘要，不仅比较方案名称。内置模板只读，用户复制、改名、编辑、导入/导出或停用自己的方案；停用不删除其历史报告。

首期提供三类模板：
- 通用矩形：字段、合法标签、几何有效性和疑似重复框；标签集未配置时提示，不能假装检查过名称。
- 屏幕角点：用户映射四种角点标签及已有屏幕主体/分组规则后，启用逐实例约束。仅有四类点且无可信分组时，只提供图级粗筛与关系待确认。
- 课堂动作：通用结构检查、用户确认的互斥/共存关系与动作规范说明；不给未知动作自动生成判定规则。举手与抬头是否互斥由任务决定，不预设。

有效配置由模板副本及项目参数生成不可变快照；运行期间编辑设置只影响下一次运行。方案绑定数据集根与标注输出根，迁移目录需重新确认绑定，不以文件名自动认作同一项目。未知规则、错误参数、冲突关系和未完成标签映射均可见；需补齐或明确停用后形成新的有效版本。

用户明确选择只运行可用子集时，先建立排除项可见的新配置快照（可另存为自定义方案），仅对该子集建立运行，原完整方案仍显示未全部执行。不能在运行中偷偷忽略不可用项。

替代方案是每个场景一个独立脚本入口或所有规则全塞入主窗口；选择登记目录＋配置，是为了共享操作和输出，同时允许独立维护业务代码。

### D3. 通用关系规则的确定性边界

提供标签/类型绑定、字段与几何合法性、计数、组完整性、唯一性、配对/包含的基础构件。所有构件明确对象过滤条件、作用范围（图片/可信实例组）、必要前提和例外；前提缺失返回无法评估/待确认，不能返回通过。

屏幕规则检查已有主体或可信组内每种角点各一；必须覆盖少一个/另一组多一个相互抵消、整组漏掉、四类全零、无效 group_id、遮挡允许缺点等情形。总数相等只能表示未发现这类数量矛盾。空间匹配可形成待确认关联，不把推断写入正式 group_id，也不自动声称真实目标不存在。

规则异常、输入不支持和业务上确实不适用分别记录。只有方案明确规定且前提可核验的不适用，才可作为已评估范围；缺数据或缺能力不能伪装不适用。

### D4. 统一输入快照与四种执行范围

当前图片由 GUI 线程在一次编辑提交结束后生成不可变快照，包含当前文档版本和已加载图像信息；不捕捉拖动预览，不从后台访问 QWidget 或活动 Shape。批量范围使用磁盘快照，由图片清单和标注输出映射生成完整 manifest，不能把未加载到列表、没有 JSON 或空标注的图片静默排除；缺少标注文件单独记为缺失/未标注线索。

批量中有 dirty 当前文档时显示“保存后运行 / 排除未保存图片 / 取消”；排除进入报告范围，保存失败不启动。当前图未保存快照的结果显示来源，不能在下次会话直接绑定磁盘。每个文件读取后保留内容摘要，显示或应用结果前再核对；图像相关规则/候选核对像素或可信内容摘要、尺寸和方向，纯几何规则至少核对标注与对应图像边界元数据。

已变更检查基于 manifest、内容与有效配置摘要比较，包含新文件、移除文件、规则版本变化和前次未完成项；不能只看 mtime。跨文件规则若后续登记，必须申报依赖范围，否则保守全范围复查。

旧 GUI 适配 `rectangle_snapshot()` 依赖 QPoint 风格点和持久 ID；新增 JSON/QcShape 适配器直接构造纯数值快照，检查有限数和有效边界。持久 ID 唯一时复用；缺失或重复 ID 时使用文件摘要＋原始下标的运行内临时身份，并独立报告身份异常。检查不得回写修复 ID；临时身份只能在原快照不变时定位。

替代方案是统一从磁盘读取，容易漏掉刚改的内容；统一从当前 GUI 读取则无法覆盖整个数据集，因此采用两种明确标识的适配器。

### D5. 统一运行器与明确终态

所有规则通过同一执行接口返回问题、覆盖范围和执行状态。旧脚本优先抽取纯函数调用；不能立即拆开的已登记脚本由受控进程适配器传入参数、临时输入/输出及取消信号，不经 shell 拼接命令，不把配置中的路径当成可执行代码。旧只读约束同样适用于适配器。

运行状态为 queued/running/completed/partial/cancelled/failed；记录每文件每规则 completed/not_applicable/failed/skipped/cancelled/not_run 及原因。run_id、项目/输出目录身份、文档版本、方案摘要和任务 generation 共同约束回调；新运行不会被旧信号覆盖。

旧 `full_scan()` 在取消时返回空 pairs，必须改变共享核心取消返回契约或让适配器携带明确的 cancelled 标志；不能单靠 pairs 判定成功。后台在文件边界、规则边界和长候选循环中检查取消，UI 立即显示取消中，完成线程/进程回收后才终止运行。无法中断的旧规则不得作为首期无界后台任务直接引入。

结果按文件分批落盘、界面分页加载，有界缓存预览；密集场景可能产生平方级对象对，允许显式资源上限，达到上限记录 partial 与截断证据，不发布完整无问题结论。初始验收目标是在约定测试机上常规样本取消 1 秒内被计算端观察到；超出须定位原因，不能删掉未处理范围来满足指标。

### D6. 共享疑似重复框核心并保留场景策略

将 beta4 的几何计算、阈值类型、矩形快照、空间候选索引及增量维护提取到公共检查层，保留原指标尺度和旧预设值。当前目标仓库不存在双屏能力，因此不为了共享计算而迁入它的 UI；未来双屏接入同一核心。

几何候选层在所有矩形间计算，不按类别或 group_id 提前排除；场景策略层读取类别关系，形成同类疑似重复、互斥类别疑似冲突、允许共存/包含和未配置待判断。允许关系只影响匹配的跨类策略，不压掉同类检查或其他结构错误；过滤原因保留在可展开证据中。

纯改类可以复用几何指标，但必须重算场景策略；改组会重算依赖组的旧规则；阈值变化重扫。几何增量更新在编辑提交后触发，不把整图计算塞进 mouseMove。组合移动、多选删除、撤销重做后与同快照全扫比较。

L2-13 保持其规则 ID 和独立阈值。问题族使用 `dataset/output/file + sorted(object_ids)`；只有同一输入快照且与当前有效配置匹配的来源才聚合为一个当前处理项。sources 分别保存自己的实现版本、数值、阈值、原因和 verification，其他运行/过期配置作为历史证据分开展示。任一有效来源仍命中，问题仍为当前待处理；取消、停用或未再检出的另一个来源不能清除它。几何风险与旧 error 等级单独显示，不直接用 severity 数字做同义映射。移除某来源时，只能说明该来源不再执行，不代表其问题已解决。

替代方案为复制 detector 到 Inspector 或用新算法覆盖旧 L2-13；前者会导致双屏与检查器漂移，后者改变历史语义，因此选择共享核心＋独立策略＋展示聚合。

### D7. 问题记录和定位契约

新报告采用版本化结构，建议字段：

| 字段 | 内容 |
| --- | --- |
| run | schema_version、run_id、状态、时间、完整有效配置和规则实现版本 |
| context | 数据集/输出根身份、文件 manifest、内存或磁盘来源、内容/图像指纹及坐标约定 |
| coverage | 每文件每规则的完成、失败、排除、截断、未执行及原因 |
| issue | 稳定问题族标识、规则来源、中文说明、疑似性质、期望/实际证据和建议操作 |
| location | image / objects / region；文件身份、对象 ID 列表或独立候选区域；对象 ID 可为空 |
| evidence | 多来源规则版本、阈值、几何指标、输入快照摘要、候选模型来源/分数（若有） |

对象对使用无序 ID 集合但必须带文件身份；group 问题保留组依据和相关成员快照。问题族标识用于比较复现，evidence_revision 表示本次证据，不能把“同 key”当成结论仍有效。

导航先解析文件，再核验身份和证据；对象删除、身份修复、版本不符时转为待复查/图片级查看。旧普通导入格式的 basename＋shape_index 仅在无歧义映射和快照可信时使用，否则保持历史线索，不能跳错对象。新区域坐标明确为 EXIF 正向图像坐标；不明方向、尺寸或映射的外部候选拒绝叠加，并说明原因。

### D8. 人工反馈、复查和复现状态机

分离三个维度：人工 decision（pending/confirmed_error/false_positive/acceptable/needs_discussion）、action（未改/用户声明已改及动作类型）、verification（current/stale/pending_recheck/not_detected_on_successful_recheck/unverifiable）。修改记录不自动产生最终通过。

| 事件 | 当前显示和处理 |
| --- | --- |
| 只查看、导航或缩放 | 不改变人工判断 |
| 修改相关标注 | 证据过期，待重检；人工结论仅历史保留 |
| 同规则同范围成功检查，未再命中 | 本次未再检出，保留原证据和人工动作 |
| 失败、取消、规则关闭或范围缩小 | 无法验证，不变为已解决 |
| 消失后再次命中 | 创建新证据版本并重新进入待复核，不沿用 resolved 状态 |
| 误报/可接受且输入和规则摘要完全一致 | 可保留该人工判断；摘要改变后待复核 |
| 撤销/重做 | 以当前编辑内容触发失效与复查，不能盲目复活旧判断 |

改类、改组、新增/删除可能影响其他对象，首期按整文件依赖保守失效；几何候选可增量更新，但仅在关系依赖可确定时保留其他证据。问题清零只代表当前执行范围未发现对应问题，界面仍显示未运行、失败和人工复核状态。

### D9. 独立存储、导入与恢复

运行报告和反馈保存到项目检查目录；默认提议数据集旁 `.xanylabeling/inspection/`，不可写时允许选择用户可写位置，绑定原数据集/输出根。扫描结果不写回训练标注。每次运行新建 report，原始证据不可就地覆盖；feedback 与 session 通过 report_id/hash 和 context 摘要关联。

反馈和会话文件采用临时写入＋原子替换，保存前比较持有的 revision，并使用排他写锁覆盖比较到替换过程；冲突保留双方文件并要求重新加载/另存，不后写覆盖前写。报告、反馈和会话不假装跨文件事务：恢复以有效完整报告为基准，缺失反馈按待处理，损坏会话只影响游标，不能恢复完成结论。失败写入保留旧文件与内存未保存提示。

支持旧普通 TSV/CSV/JSON 及 L1/L2 report.json/review.tsv/feedback 导入；保留来源批次，导入默认新增来源而不替换当前队列。无法识别的版本、字段缺失、路径歧义和丢失证据单独报告。新格式导出 JSON 可完整表达区域和多对象，简化 TSV 附说明，不宣称无损往返。旧阈值建议保留为可选人工建议，不自动修改有效方案。

替代方案是把问题记录全部写入标注 JSON；这会让只读扫描污染训练文件并与已有密集复核元数据混淆，因此报告用独立存储。画布正式编辑与 dense-review 的确认/覆盖仍按各自已有保存契约完成。

### D10. 人工处理与密集复核的边界

Inspector 必须能在普通画布独立运行；提供图片/对象/对象对聚焦、原图上下文、误报/可接受/待讨论和复查。删除或接受候选均通过现有编辑命令，遵守锁定、隐藏、取消切图及 undo/redo；几何计算不直接改文件。

重复框可明确选择删除哪一个或两者保留；批量删除预览精确 ID 集合，多个相邻重叠对不自动合并成一个实体。重标入口只清空当前图片明确选择的矩形类别/对象，必须确认范围并保留无关点、多边形、属性等其他内容。

密集复核可用时，handoff 传入项目/文件身份、对象集合或区域和问题 ID；接收端核验快照，成功后反馈定位，不复制其状态。上下文卡片、类别/几何确认和全图重叠区域查漏继续由该变更负责。不可用时正常画布可处理问题，显示“独立查漏尚未开展/需人工全图复核”，不增加假的覆盖完成按钮，也不阻塞结构检查。

三个状态并列显示：规则运行情况、问题处理情况、独立人工复核/查漏情况；旧 checked/review_status 仍由正式验收操作管理。自动检查不能更改它们。

### D11. 模型候选仅接入结果，不启动新推理

首期接收外部模型产生的 image/region 类型候选，至少含源图身份/尺寸/方向、候选类别与框、来源和版本；分数可选，只作该来源证据，不跨模型比较为统一正确率。没有足够坐标映射信息时仅列出不能叠加的导入错误。

候选在独立覆盖层显示，用户可接受、调整后接受、拒绝或暂存。接受只为明确选中候选创建正式对象、新持久 ID 并触发相关规则待复查；批量接受需先预览具体集合，均可撤销。拒绝不删除任何原标注；不同来源不得静默合并/覆盖标注。当前内容变化后先核对候选来源，不照搬旧预测。

候选关联使用带图片身份的 source_run＋candidate_id；旧格式没有候选 ID 时使用原报告摘要＋原行号，重导相同报告保持身份。接受前记录含预分配正式对象 ID 的待提交意图，再通过普通编辑命令新增并关联；尚未保存时显示已接受未保存。标注保存后才完成持久关联记录。反馈保存失败时保留待确认状态，不让重复点击再次新增。重开根据该 ID 与目标文件当前内容核对：对象存在则恢复关联，对象不存在则保留未完成意图并允许用户重新处理，不自动重放新增。undo/redo 同步更新内存关联；外部删除、复制或身份修复使关联待核验。这样 sidecar 与标注无需假设跨文件原子提交，也能防止相同候选重复接受。

新增推理、跟踪与模型选择需要独立实验；先比较额外找回的真实漏标、误报处理时间和人工查漏后的残留，不能凭模型架构名称断言效果。

### D12. 验证策略

- 迁移用固定样例比较旧核心与新核心：同类/异类、偏移、包含、合法多目标重叠、全重叠、极小框与异常坐标；原逻辑差异必须分类为适配/策略变化，不伪造零差异。
- 规则测试覆盖总数抵消、全零、整组漏标不可检出、例外、坏分组和未配置类间关系。
- 生命周期测试覆盖 dirty 当前图、保存失败、异步切图、切输出根、取消、外部改动、身份缺失/重复、同名文件、问题复现、关闭规则、并发反馈冲突及损坏恢复。
- 小样本试用建议先选约 30–50 张，包含稀疏/密集、正常/异常、遮挡和空标注；这只是试用规模，不作为全量质量保证。两位使用者采用难度相近的对照批次，减少重复看同一图片造成的记忆偏差。
- 比较总处理时间（包含运行/误报/复查）、真实错误找回数、残留错误和重开后恢复操作；独立复核部分随机未报警图片，发现盲区。若误报成本抵消收益或质量下降，不进入默认工作流，先调整方案。

## Risks / Trade-offs

- [规则组合过多] → 首期只提供有限构件与三类模板，专用规则独立登记，不建设复杂规则语言。
- [重叠被误当成重复] → 几何候选与业务关系分层，红黄只表疑似，不自动删除。
- [旧版模块依赖隐含 UI 状态] → 固定来源、先纯数据适配测试、逐项迁移，避免复制巨大主窗口。
- [报告失效判断带来开销] → 摘要在加载/运行/恢复边界计算并缓存，不进入鼠标移动热路径。
- [外部候选方向或尺寸错误] → 显式坐标契约与导入校验，拒绝不明映射。
- [密集复核尚未实施] → 普通画布先可用，查漏完成状态诚实显示未开展，后续按既有协议接入。
- [保存 sidecar 增加文件管理] → 软件管理路径、报告关联和恢复，提供定位目录/导出，不让用户日常手工维护。

## Migration Plan

1. 记录当前 Git 状态及已知失败测试，固定 beta4 来源版本，按定制台账新增“方案/实施中”条目；不修改其他变更完成标记。
2. 建立纯检查数据契约、规则目录和共享几何核心，完成来源一致性及输入适配验证。
3. 迁移必要 Inspector 入口、运行/取消/报告和最小问题队列；先让一套通用方案从点击运行走到复查。
4. 加入场景方案管理、逐实例规则、重复框成对处理、兼容导入及恢复；保留未知旧字段并对无法核验的历史结论降级。
5. 接入画布编辑命令与可用的 dense-review 协议；后续模型结果作为可选导入来源，不影响普通规则使用。
6. 完成针对性回归和两人试用后再默认启用。回退时关闭新增入口/回退本变更独立提交，保留独立报告和配置；不逆向改写标注数据，不撤销其他人此前的正常编辑。

## Open Questions
