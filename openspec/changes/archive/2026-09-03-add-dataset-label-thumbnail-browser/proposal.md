## Why

现有标注界面一次只能查看当前图片中的对象，用户无法按标签聚合浏览整个数据集并通过对象缩略图快速发现和修正误标。项目已有 SQLite 数据集索引、永久 Shape ID 和安全的跨图对象改标事务，因此现在可以在不复制数据加载与写盘逻辑的前提下补齐这一数据集级视图。

## What Changes

- 新增“标签缩略图”窗口，按标签从现有 SQLite 派生索引分页查询对象，并以图片裁剪缩略图展示跨图片结果。
- 扩展 SQLite Shape 索引字段，保存 `xanylabeling_shape_id` 和由 Shape points 计算的 bbox，使窗口无需重新全量解析 JSON 即可定位和渲染候选对象。
- 每页最多展示 100 个对象；只为可见项按需加载原图、裁剪和缩放，并使用有界内存缓存与磁盘缩略图缓存保持界面响应。
- 支持在缩略图中多选具体对象、选择新的标签名、查看影响对象数与文件数并明确确认。
- 确认后把选中对象转换为现有 `MarkedObjectRef` 快照并调用统一的跨图对象改标流程；继续复用永久 Shape ID 预检、当前文件未保存内容处理、备份、原子写回、结果报告与恢复清单。
- 成功写回后按文件刷新 SQLite 索引并重新查询当前标签；已改名对象退出当前结果，窗口继续显示下一批。
- 明确首版只提供按标签浏览和对象改标，不增加删除、任意字段编辑、自动标注、多人协作、跨进程冲突合并或新的撤销体系。

## Capabilities

### New Capabilities

- `dataset-label-thumbnail-browser`: 定义数据集级按标签查询、对象缩略图按需渲染、多选改标以及写回后索引与视图闭环刷新的行为。

### Modified Capabilities

无。缩略图入口调用现有 `cross-image-object-relabel` 统一流程，不改变其行为契约。

## Impact

- 扩展 `anylabeling/views/labeling/dataset_index/` 的 SQLite schema、轻量 JSON 扫描结果和分页对象查询接口；数据库仍是可删除、可重建的派生缓存。
- 新增独立的标签缩略图窗口、分页模型、后台缩略图生成与缓存组件，并在 `label_widget.py` 增加一个薄入口和结果刷新连接。
- 复用 `widgets/object_relabel.py`、对象改标对话框及 `widgets/label_batch.py` 的现有事务能力，不新增 JSON 写入实现。
- 增加纯 Python 索引/缓存测试、PyQt offscreen 窗口测试和现有对象改标回归测试；新增用户可见文案需要进入现有翻译资源流程。
- 运行前提为单用户、单应用实例操作一个数据集；不设计多人或多进程同时修改同一标签目录的协调机制。
