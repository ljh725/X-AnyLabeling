## Context

参见 [proposal.md](proposal.md) 的动机。当前 `Shape` 已在构造时生成 `uuid.uuid4().hex`，通过 `to_dict()` / `load_from_dict()` 读写顶层 `xanylabeling_shape_id`，并以 `copy()` 和 `copy_for_new_object()` 区分撤销快照与复制新对象。`LabelFile` 负责文件加载，`LabelingWidget` 通过 Shape 字典保存，VOC、YOLO、COCO 转换路径当前不会主动读取该私有字段。

现有缺口主要位于集合级不变量：单个 Shape 能保证“有 ID”，但一个文件加载后未验证“所有 ID 唯一”；保存入口也没有身份预检。质检、虚拟复核和部分运行时模块仍存在数组下标、QA 临时 ID 或 Python 对象地址等局部身份，这些可以保留用于瞬时计算，但不能被误用为跨保存周期主键。

## Goals / Non-Goals

**Goals:**

- 在 Shape 对 UI 和下游服务可见之前建立文件内非空、唯一身份不变量。
- 保持编辑、撤销、保存和重载中的身份稳定，并让所有“创建新对象”入口产生新身份。
- 对旧文件、损坏身份和重复身份提供兼容、可诊断的治理策略。
- 在保存边界防止异常扩展写出含歧义身份的 JSON。
- 提供下游采用稳定身份的边界规则和可回归测试的生命周期矩阵。

**Non-Goals:**

- 不让 Shape ID 取代 `group_id` 或表达对象间业务关系。
- 不承诺经过 VOC、YOLO、COCO 往返后恢复同一身份。
- 不把本次变更扩展为跨设备、跨用户或中心化 ID 注册服务。
- 不要求所有瞬时 UI 算法立即弃用数组下标或对象地址，只治理持久引用边界。
- 不因加载旧文件时补 ID 自动触发无条件写盘。

## Decisions

### 1. 文件内唯一，跨模块使用复合对象键

`xanylabeling_shape_id` 的直接不变量是同一标注文件内唯一。需要跨文件或行为日志聚合时使用 `(project_id, image_id, shape_id)`，从而允许复制整个 JSON 到另一张图片后仍由图片身份隔离。

备选方案是要求 Shape ID 单独承担全世界范围的强全局唯一。UUID 已提供极低碰撞概率，但系统无法验证所有离线项目；把可验证范围定义为文件内并使用复合键更符合本地桌面应用的数据边界。

### 2. 新 ID 使用 UUID4 hex，历史有效 ID 保持宽松兼容

系统生成 32 位小写 UUID4 hex。加载历史数据时，任意非空字符串视为可保留的历史身份；只有缺失、非字符串、空字符串或集合内重复才触发修复。

严格拒绝非 UUID 字符串会破坏已经由脚本或旧实验版本写入的身份。身份格式与身份唯一性分离，可在不迁移所有旧数据的情况下强化不变量。

### 3. 在集合加载边界集中规范化

新增纯 Python 风格的身份规范化/验证帮助层，由 `LabelFile` 在构造 Shape 集合时维护 `claimed_ids`。按原数组顺序处理：首次出现的有效非空字符串保留，缺失/非法/重复项循环生成新 UUID，直到不在 `claimed_ids` 中。规范化结果同时返回结构化诊断计数或记录，供日志和测试使用。

不把重复治理只放在 `Shape.load_from_dict()`，因为单个 Shape 无法知道同文件其他 Shape 的身份。也不依赖随机 UUID“自然不会碰撞”，生成器仍需针对当前集合进行成员检查。

### 4. 保存阶段验证但不静默换 ID

正常加载和创建入口应在 Shape 被消费前完成身份治理。保存前执行一次只读集合验证；若发现缺失或重复，抛出可定位的 `LabelFileError`，阻止写出歧义 JSON。

在保存阶段自动换 ID 虽然能保证文件格式正确，却会使此前已经记录的行为事件、复核引用和当前内存对象键失效，因此选择显式失败。修复应发生在对象进入系统的边界，而不是生命周期末端。

### 5. 用显式 API 区分状态复制和对象复制

保留 `Shape.copy()` 的身份，用于撤销、重做和内部状态快照；使用 `copy_for_new_object()` 或等价工厂产生独立对象。系统剪贴板反序列化、Duplicate、合并导入和任何绕过标准构造器的 AI/插件路径必须显式采用“新对象”语义。

不改变普通 `deepcopy` 自动重置 ID，因为这会破坏撤销恢复；身份语义必须由调用点表达。

### 6. 私有字段采用显式导出白名单边界

X-AnyLabeling JSON 保留顶层字段。外部转换器继续只读取目标格式需要的公共字段，不为私有身份添加隐式扩展。边界测试验证输出中不存在 ID 且源文件未被修改。

相比在转换前临时删除字段，白名单读取更不容易影响源数据，也避免未来新增私有字段意外泄漏。

### 7. 下游迁移按“是否跨生命周期”分类

审计行为分析、Inspector、质检和虚拟复核的身份字段：跨编辑/保存/重载的引用改用持久 Shape ID 或复合键；只服务当前画布布局、命中测试或一次扫描的下标和对象地址保留并明确命名为 runtime/qa identity。

本次不做无差别全局替换，因为 QA 临时匹配和渲染顺序具有不同语义，强行共用持久 ID 会混淆领域边界。

## Risks / Trade-offs

- [损坏文件修复后身份与外部旧引用不同] → 保留首个有效出现者，后续重复项换新并输出诊断；歧义输入本身无法无损判定哪个对象拥有原身份。
- [旧文件仅加载未保存时补出的 ID 下次运行变化] → 延续“不仅因迁移标记 dirty”的兼容策略，并在文档中明确只有正常保存后才跨进程稳定。
- [遗漏某个插件或 AI 创建入口导致身份复用] → 审计所有 Shape 构造、复制、反序列化和合并入口，并增加调用路径测试。
- [保存预检暴露既有扩展缺陷并阻止保存] → 错误包含冲突 Shape 的数组位置和 ID，便于定位；标准入口在更早阶段完成治理。
- [下游把瞬时 ID 当成持久 ID] → 使用清晰字段命名和边界测试，持久输出 schema 只接受 Shape ID/复合键。
- [大型标注文件增加加载开销] → 使用单次 O(n) 集合扫描和 O(n) 辅助集合，不做全对全比较。

## Migration Plan

1. 先增加集合级规范化器、验证器及纯逻辑测试，不改变外部格式。
2. 将 `LabelFile` 加载接到规范化器，保留旧文件惰性补 ID 行为并记录诊断。
3. 在保存前加入只读唯一性预检，确保标准创建入口全部先满足不变量。
4. 审计 Duplicate、两种剪贴板、导入、AI 和撤销/重做路径，补齐生命周期测试。
5. 增加 LabelFile 文件往返与转换器边界测试，并更新身份契约文档。
6. 按是否需要跨生命周期持久引用审计下游模块，优先迁移行为分析和持久复核数据。

回滚时可移除集合规范化和保存预检，已有顶层 ID 字段仍由现有 Shape 读写逻辑兼容；本变更不需要批量重写用户文件或修改外部格式。
