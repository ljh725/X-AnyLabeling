## Context

问题与证据见 `proposal.md` 及 `reports/digit_rectangle_save_20261104/REVIEW.md`。当前链路为 `create_digit_mode()` 设置 `digit_to_label` → Canvas 完成几何 → `new_shape()` 确定类别并加入标签列表 → `set_dirty()` 自动保存或等待 Ctrl+S。

`new_shape()` 从 `unique_label_list` 读取预选类别；数字绑定目前只在“开启标签弹窗或没有预选类别”等条件成立时消费，因此关闭弹窗且有预选类别时会跳过绑定。保存层只是序列化已确定的类别，修改保存层无法修正画布和标签列表中的错误语义。

本轮为规划阶段：只新增当前 change 文档，不实施源码、测试或配置变更。既有测试及报告沿用上次复核记录，不视为本轮重新执行。

## Goals / Non-Goals

**Goals:**

- 明确普通创建中数字绑定、类别预选及弹窗之间的优先级，在类别最终确定阶段一次处理。
- 成功提交后清除本次绑定，使画布、标签列表、撤销快照及保存文件使用同一类别。
- 用现有端到端失败用例证明问题关闭，保留不带数字绑定的创建与编辑语义。

**Non-Goals:**

- 不重构整个快捷键或绘制状态机，不调整数字映射持久化。
- 不改变 JSON 格式、文件写入机制或自动保存开关。
- 不根据类别或几何猜测历史错误标注，不批量重写用户文件。
- 不把未经复核的取消绘制、切图等绑定生命周期问题宣称为已确认缺陷；实施时仅检查与本次改动相邻的回归风险。

## Decisions

### 在创建阶段解析数字绑定

保留自动标注特殊标记的优先处理。普通绘制存在待应用数字绑定时，优先采用并消费该绑定，再进入共同的合法性验证、属性处理、标签列表登记及保存流程。没有绑定时使用原有类别选择路径。

取舍：不通过强制开启 `display_label_popup` 规避问题，因为弹窗关闭是有效用户设置；不在 `save_labels()` 中覆盖类别，因为那会让画布、撤销和 JSON 出现不同语义。

### 限定绑定消费边界

本次创建的绑定只能决定本次矩形类别，成功完成后不得留在 `digit_to_label`。实施前梳理模式切换和 `new_shape()` 的调用顺序，确保不会在自动切回编辑模式时提前丢失合法绑定。

取舍：优先做局部修复，不新增全局绑定管理器；若公共创建分支受影响，增加相邻用例验证，不扩大到整体状态机重构。

### 沿用保存链路，直接检验落盘结果

保留 `set_dirty()`、`save_file()`、`save_labels()` 的现有职责。验收使用真实窗口、数字键、鼠标完成和 Ctrl+S，检查实际 JSON，并通过 `load_file()` 重载。

现有 16 种保存组合及 0–9 数字键测试作为主回归；实现修复时移除四项已知缺陷的严格 xfail，使其成为普通必过断言。补充成功提交后的绑定清理、下一次普通绘制和复用上次类别优先级用例。

## Risks / Trade-offs

- [公共类别解析分支影响非矩形或自动标注] → 保留特殊标记处理，核对受影响调用并运行选中对象改类、普通绘制及自动标注相关回归。
- [过早清理绑定导致本次类别丢失，或未清理导致下次绘制串类] → 对本次提交与下一次普通创建分别断言类别，检查自动切回编辑模式的执行顺序。
- [xfail 被保留导致已知缺陷没有成为必过门槛] → 任务中明确移除标记，验收不得有这四项 XFAIL 或 XPASS。
- [把历史测试结果当成修复后证据] → 重新运行指定测试并独立保存修复后结果，明确原始 35 passed / 4 failed 仅为缺陷基线。

## Migration Plan

实现时仅改动必要的类别解析及测试；无需数据迁移或新增依赖。完成定向回归和界面复现验收后记录结果；若引入回归，回退本次局部变更，不触碰既有用户 JSON。当前阶段所有实现任务保持未完成。
