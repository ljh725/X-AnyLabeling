## Context

当前实现同时维护 `ViewportController` 的精确视口历史以及 `LabelingWidget` 中的旧缩放、旧滚动缓存。重置逻辑必须同时处理这三类来源，否则 `load_file()` 的回退路径会再次恢复旧视图。现有实现通过删除记录表达重置，但“没有记录”同时也是允许 `keep_prev_viewport` / `keep_prev_scale` 继承的条件，因此无法保证非当前目标下次默认打开。

画布有两套右键菜单。初始化阶段向两套菜单添加了重置动作，但 `populate_mode_actions()` 会清空普通画布菜单并只恢复模式动作和筛选菜单，导致实际运行中的三个重置入口消失。该问题来自两条独立的菜单组装路径，而不是 QAction 没有创建或 Canvas 没有弹出菜单。

## Goals / Non-Goals

**Goals:**

- 让“重置”成为比视口继承策略优先级更高的一次性显式意图。
- 将目标解析、缓存失效、当前画布复位和反馈数量分开建模，避免一个 `cleared` 数字承担多种含义。
- 由唯一构建路径维护两套画布右键菜单。
- 保持批量操作为 O(N) 内存处理并提供可直接测试的状态接口。

**Non-Goals:**

- 不改变正常切图时精确历史、保持上一张视口和旧缩放回退的既有优先级。
- 不持久化视口状态或重置标记到配置文件。
- 不修改 shape、标注 JSON、图片数据、文件排序和导航顺序。
- 不为重置功能新增确认弹窗、撤销历史或快捷键。

## Decisions

### 1. 使用一次性“强制默认”标记表达非当前图片重置

在视口状态管理层维护数据集作用域的 `force_default_on_next_load` 文件集合。重置非当前图片时清除其历史并加入集合；加载该图片时先消费标记，跳过精确历史、上一张视口继承、旧缩放和旧滚动回退，执行默认视图。标记消费后恢复正常保存流程。

当前图片立即复位，因此其标记在本次操作中直接消费，避免用户重置后重新调整的视图在离开图片时被错误忽略。

选择标记而不是预先保存默认 `ViewportState`，因为适应窗口的缩放值取决于图片尺寸和加载时的可用窗口大小，无法在重置非当前图片时正确计算。

### 2. 以结构化结果区分目标数、缓存清理数和当前图片影响

重置协调逻辑返回不可变结果，至少包含去重后的目标、目标数量、实际移除的缓存记录数量、是否包含当前图片以及待默认打开标记数量。用户成功反馈使用目标数量；缓存清理数量仅用于调试和测试。

目标文件在变更前统一转为稳定的去重序列。缓存变更发生异常时恢复本次操作涉及的状态快照，并返回失败结果，避免三类缓存相互冲突。当前画布复位只有在状态提交成功后执行。

考虑过继续使用整数 `cleared`，但它无法表达“无缓存却成功复位当前图片”，也是当前 0 个反馈问题的根源。

### 3. 使用单一默认视图应用函数同步所有 UI 状态

新增窄范围的当前画布复位函数，统一完成：设置 FIT_WINDOW 模式、更新 Fit Window/Fit Width QAction 勾选、计算默认缩放、更新缩放控件和导航器、把滚动条移动到最小值并重绘。顶部菜单、文件列表和画布菜单不得各自实现视图复位步骤。

该函数不调用 dirty/save 路径，并在图片无效时返回明确的未应用结果。

### 4. 由单一画布菜单构建函数维护两套菜单

将重置 QAction 和复制/移动 QAction 保存为可复用成员，并由 `_rebuild_canvas_context_menus()` 统一清空、按固定顺序重建普通菜单和待移动 shape 菜单。初始化和 `populate_mode_actions()` 都调用该函数，筛选子菜单的引用也在该路径中重新绑定。

菜单构建函数每次从空菜单开始，因此天然避免重复动作和分隔符累积。只在初始化追加动作、随后尝试“补回”的方案被放弃，因为任何后续菜单重建都可能再次漏项。

### 5. 明确视口状态的数据集生命周期

在替换文件列表、关闭数据集或打开独立文件形成新数据集边界之前，调用统一的视口会话清理函数，同时清空精确历史、一次性默认标记、旧缩放和旧滚动缓存，并重置 `last_loaded`。普通的同数据集切图不得触发该清理。

“重置所有”仍严格表示当前数据集全部文件；跨数据集残留通过生命周期清理解决，而不是把当前操作扩展到用户不可见的历史文件。

### 6. 国际化使用英文 source 文本并编译资源

新增菜单和反馈以英文作为 `tr()` source，在四个 `.ts` 文件中提供对应翻译，随后运行项目语言编译脚本生成 `.qm` 和 `resources.py`。生成的 `resources.py` 不手工编辑。

### 7. 分层测试状态契约和 Qt 集成

纯状态测试覆盖目标去重、三类缓存一致失效、一次性默认标记、数据集清理和异常回滚。PyQt offscreen 测试覆盖两套画布菜单在初始化及重复 `populate_mode_actions()` 后的内容、当前画布 UI 同步、反馈数量以及 shape/dirty 不变。

测试使用最小 LabelingWidget fixture 或窄 adapter，避免在每个状态用例中启动完整应用和扫描数据集。

## Risks / Trade-offs

- [一次性默认标记未在所有数据集入口清理] → 收口数据集替换入口，并用切换文件夹和独立文件测试验证。
- [重建两套菜单可能改变既有动作顺序] → 在设计中固定顺序，并为原有复制/移动、标注动作和筛选子菜单添加存在性断言。
- [异常回滚增加状态协调代码] → 将回滚限制在小型内存映射和标记集合，不捕获不可恢复的进程级异常。
- [同步编译翻译资源产生较大生成文件 diff] → 只由 `compile_languages.py` 生成，并单独核对源 `.ts` 变化。
- [在大文件中继续增加编排代码] → 将状态计划和结果模型放入小型独立模块，`LabelingWidget` 只保留 Qt adapter 和入口绑定。

## Migration Plan

1. 先引入状态结果模型、一次性默认标记及单元测试，不改变菜单入口。
2. 接入加载优先级、当前画布复位和数据集生命周期清理。
3. 收口画布菜单构建并增加 PyQt 回归测试。
4. 更新翻译并编译资源，运行相关测试、Black 和 Flake8。
5. 若需要回滚，可整体撤销新协调器和菜单构建路径；没有文件格式或配置迁移需要处理。
