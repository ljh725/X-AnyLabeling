## Why

“重置图像视图”当前能够清理部分视口缓存，但其行为与用户理解并不完全一致：非当前图片可能再次继承旧视图、UI 状态和反馈计数可能失真、历史状态和国际化没有完整收口，也缺少回归测试保护。同时，三个画布右键重置入口虽然在初始化阶段被添加，却会在菜单重建时被清除，导致用户实际看不到这些选项。

## What Changes

### 第一类目标：修复 7 项可靠性风险

- 将“重置”定义为明确的行为契约：目标图片下次打开时必须使用默认视图，不得立即从上一张图片继承视口或旧缩放。
- 同步维护 `zoom_mode`、Fit Window/Fit Width 菜单勾选、缩放控件、画布比例、滚动条和导航器状态。
- 统一“目标数量”“实际清除缓存数量”和用户反馈语义，避免成功重置当前图片却显示 0 个。
- 明确“重置所有”的范围为当前数据集，并在数据集切换/关闭时清理不再属于当前数据集的历史视口状态，防止跨数据集残留。
- 使批量重置先完成目标解析和必要校验，再统一变更状态；失败时不得留下无法解释的半清理状态。
- 为新增菜单、提示和状态文案补齐 `en_US`、`zh_CN`、`ja_JP`、`ko_KR` 翻译资源并重新编译语言资源。
- 增加纯状态逻辑和 PyQt 菜单/画布集成测试，覆盖当前、区间、全部、无缓存、继承开关、数据集切换和失败边界。

### 第二类目标：修复画布右键菜单

- 修复 `populate_mode_actions()` 清空并重建 `canvas.menus[0]` 时丢失三个重置动作的问题。
- 保证空白画布菜单和存在待移动 shape 的画布菜单都稳定显示三个重置选项。
- 将画布菜单组装收口为单一可重复调用的构建路径，避免初始化菜单与后续重建菜单产生不同结果。
- 验证重复刷新模式动作不会产生菜单项丢失、重复或分隔符堆积。

## Capabilities

### New Capabilities

- `image-view-reset`: 定义图像视图重置的范围、默认视图保证、状态一致性、画布与文件列表入口、反馈、国际化及数据集生命周期行为。

### Modified Capabilities

无。现有 OpenSpec 主规格中没有图像视图重置能力。

## Impact

- 主要代码：`anylabeling/views/labeling/label_widget.py`、`anylabeling/views/labeling/widgets/viewport_controller.py`、必要时新增独立的视图重置状态协调模块。
- 菜单代码：画布两套右键菜单、文件列表右键菜单和顶部 View 菜单。
- 配置交互：保留 `keep_prev_viewport` 和 `keep_prev_scale` 的现有配置含义，但重置目标的显式默认视图要求优先于继承策略。
- 国际化：更新 `.ts` 文件并重新生成 `anylabeling/resources/resources.py`；生成文件不手工编辑。
- 测试：新增纯 Python 状态测试和 PyQt offscreen 集成测试，不修改 shape、标注 JSON 或图片文件格式。
