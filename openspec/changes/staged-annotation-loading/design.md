## Goals / Non-Goals

**Goals:** 当前图不等待全目录标签；主线程只创建/更新 Qt 对象；所有结果可追溯到请求上下文；测试能够控制异步执行顺序并复现竞态。

**Non-Goals:** 本阶段不迁移 beta.4 的 SQLite、缩略图、跨图复查、Undo 延迟快照或几何缓存；不改标注协议，不建立长期监控，不创建新聊天或自动推送 GitHub。允许必要的 UI 提示与翻译。

## Decisions

### 1. 采用轻量加载控制器，分离路径、元信息和真实画布加载

建议新增独立控制器/worker 模块，使用现有 Qt 线程和信号。worker 输出普通记录（路径、存在性、审核状态、错误、上下文编号），不创建或修改 QWidget、QPixmap 或列表项。保留现有当前图 `load_file` 和 Shape/Undo 流程。

- 更改输出目录：先完成旧目录的未保存修改确认，再提交新上下文；复用完整图片路径列表，优先重载当前图对应 JSON，再分批更新其他元信息。没有 JSON 时遵循现有无标注行为，不得带入旧目录的框或误用 keep_prev 跨目录复制。
- 初次打开图片目录：后台扫描并按原规则排序；接受首图需要等待路径枚举和排序，但不等待全目录 JSON。收到路径后先建首批条目、显示首图，其余分批加入。序号搜索以完整排序列表为准，避免边枚举边确定错误序号。
- 维护完整路径集合与当前搜索结果两份视图；搜索不反复枚举同一图片目录。明确刷新/重新打开目录时重新扫描，不能让路径缓存永久掩盖外部新增图片。
- 导入/重载不得意外触发 autosave、编辑信号、保存路径重绑定或 compare/shared view 的旧状态残留。保留必要的现有会话清理。

不直接套用 beta.4：其中审核默认 False、属性筛选空分支和阻塞 wait 正是需要避免的问题。

### 2. 使用显式元信息状态，不改变 JSON 审核协议

内存记录分别包含 presence（unknown/present/missing/error）、review（unknown/unchecked/passed/failed/error）。原 JSON 仍使用 false/true/"failed"，缺字段的合法 JSON 保留未审核语义。未知和错误只存在于内存/UI，不写入 JSON。

先检查现有 Qt UserRole 和 checkbox 使用者，选择新增角色或封装映射，不能把 None 直接交给现有 `file_status_icons[checked]`。程序批量回填时阻断会触发保存的 itemChanged 信号，保留配置 `file_list_checkbox_editable` 的原有语义。

后台审核读取优先保证顶层 checked 语义准确：初版可在后台逐文件解析 JSON、提取字段后立即释放；如复用快速读取器，必须验证嵌套同名字段、跨块字段及损坏 JSON，不能靠正则命中任意 checked 就认定审核通过。不要在内存保留所有 shapes。

### 3. 分批回填并限制事件堆积

初始建议批次 200–500，按实际耗时调整；单次 UI 更新目标不超过 16 毫秒，过长则拆到下个事件循环。避免每条结果触发完整布局、全表搜索或全局刷新；用路径映射定位条目。必须有有界待处理队列/合并机制，防止 worker 生产速度超过 UI 导致无界信号堆积。

Qt Batched 布局可评估；uniformItemSizes 仅在行高确实一致时使用。默认限制并发，先一个元信息 worker；线程数量由实测调整，不能按文件数量创建任务。EXIF 保留配置行为，但延后到首帧后且避免争抢全部 IO；不是移除 EXIF 功能。

### 4. 取消、保存和过期结果隔离

每次有效目录切换有 generation，搜索有 request_id，同文件成功保存或从真实当前图读取有 revision。应用结果前检查完整上下文（图片根、输出目录、generation、搜索号及该文件 revision）。后台扫描不得覆盖本轮更晚的保存或当前图权威状态。

取消采用协作标志：每个文件/批次边界检查；旧结果立即失效，任务结束后释放对象。禁止 GUI 线程无期限 `wait()`，也禁止 `QThread.terminate()`。保留运行中任务引用直至 finished，快速反复切换时合并待启动请求并限制存活 worker 数；如旧 IO 不能及时结束，优先保证新当前图可用，后台队列明确显示等待。

普通文件 IO 无法保证中途强行取消。关闭时先停止接收结果、请求取消并通过事件循环等待；超过短暂退出宽限后保持窗口可响应并说明仍在等待 IO，不销毁运行中线程。测试用可控阻塞任务验证此路径，不承诺任意失联网络盘均可立即退出。

### 5. 搜索和审核导航使用明确的异步状态

- 文件名/正则/序号沿用现有纯匹配函数；标注属性匹配移到 worker，复用现有匹配语义，分批回传真实结果。进度期间显示“筛选中”，最终空结果与读取错误分别反馈。选择按路径恢复；后台结果不得触发当前图重复加载或丢弃未保存编辑。
- 下一张/上一张未审核按既有非环绕顺序查找；候选 unknown 时优先排队确认，从第一个未知处继续，不跳过它选择更远项。期间去重/禁用同类重复导航，普通编辑切图仍可用；用户主动切图或改变上下文时取消待执行导航，避免稍后突然跳图。
- 候选读取失败：停止此次自动定位并给出失败提示及重试入口，不把它当未审核，也不静默宣称搜索完整。批量扫描中单文件错误不终止整个任务。

### 6. 性能与正确性验收

先重跑当前基线再改代码。基准沿用 `benchmarks/canvas_drawing_20261029/benchmark_output_change.py` 的真实 MainWindow 链路，按需适配异步完成条件；不得为了拿到数字裁掉真实列表、JSON 解析或首帧绘制。

真实路径：
- 图片：`D:/A0-part2-kps-3-class-dataset/PRW/PRW_image_11792`
- 标注：`D:/A0-part2-kps-3-class-dataset/PRW/PRW_json_11792`

记录至少 3 次修改前和 3 次修改后：确认输出目录到首个带真实框的 paint、首个可编辑时刻、全列表构建完成、全状态就绪、事件循环心跳最大间隔与 P95、成功/缺失/错误数。写明 Python/Qt、机器、窗口大小、数据量、文件缓存条件；热缓存和无法控制的冷缓存不能混作公平对比。

本机同数据暖缓存目标（设计目标，尚未实现）：首个带框 paint 中位数不超过 1.5 秒，且相较同次基线至少减少 60%；目录后台加载期间心跳最大间隔不超过 200 毫秒。正常当前图解码和原有单图操作单独列出；不能以持续调用 processEvents 或删工作伪造响应。未达标需分析残余瓶颈并在 tasks 保留未完成项。

结构验收比绝对秒数更重要：注入每个后台文件额外延迟时，当前图仍先显示；后台没有读完也可保存和撤销。全状态完成时间单独报告，即使首屏加速也不得隐去总体扫描变慢。内存至少记录峰值或队列上限，确认不会缓存全目录 Shape。

真实数据测试保留写入审计保护，关闭会写原数据的测试设置，并对比前后图片/JSON size、mtime及当前 JSON 哈希。新增框/审核/保存/损坏文件实验使用临时副本。不可用的环境要明确报告，不能拿 AST 或 mock 耗时冒充完整 GUI 实测。

## Risks / Trade-offs

- 后台完整 JSON 读取可能比旧 checked 快速扫描更费总 IO → 首屏优先、逐个释放、限制并发，分别报告首屏和总耗时；只有证据支持才另行优化读取器。
- 外部程序修改文件无法实时获知 → 重新打开/明确刷新重新读取；当前图加载真实 JSON，不用旧元信息替代。
- 程序化回填触发编辑/保存 → 阻断相应信号并验证后台加载零写入。
- 异步改变原有回调时序 → 稳定路径身份、上下文验证、保存 revision 和可控乱序测试。
- 大目录排序仍需扫描完成 → 扫描移到后台保响应，输出目录切换复用已知列表；此阶段不改变自然排序规则换取假首屏。
