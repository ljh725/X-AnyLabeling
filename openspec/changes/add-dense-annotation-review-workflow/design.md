## Goals / Non-Goals

**Goals:**

- 默认一批一次确认，编辑次数与确认次数解耦；正确对象零额外逐项确认。
- 类别判断和调框可在一次聚焦中完成，也可保留部分确认；不强制对所有图片执行多遍固定流水线。
- 当前图全部存活对象都可追踪，改类不丢对象，查漏与对象审核独立。
- 工作被打断后可恢复可信进度；编辑、撤销、外部修改或规则改变不会保留过期确认。
- 视图变化可预测，有足够上下文，并可验证实际减少缩放、拖动、重复观察和疲劳。

**Non-Goals:**

- 不训练/接入新模型，不由置信度自动通过，不自动补全遮挡框，不评价生成图片的版权。
- 不承诺绝对精度或某个提效百分比；不是眼动跟踪系统，也不能证明用户确实注视了每个对象。
- 不将任意格式的多边形、掩膜或视频轨迹编辑纳入首版；首版聚焦图片矩形。遇到其他形状仍计入全图待处理并可进入现有编辑流程，不能静默忽略并宣称完成。
- 不进行多用户同时编辑合并，不做跨图片目标重识别；外部冲突检测后交由明确重载/保存决策。
- 不替换现有 JSON、旧审核字段或原生画布编辑能力，不默认强迫所有用户进入新工作区。

## Decisions

### D1. 一个可选工作区，四个相互联动的区域

采用可伸缩的主画布、类别批次面板、对象卡片列表、全图导航。小窗口时收起卡片栏或导航，仍允许使用现有画布与批次完成操作。

```text
批次：A/B  | 本批12，疑难1，手动隐藏1 | 类别+框 | 全图待审18
┌──────────────────────────┬─────────────────────┐
│ 主画布：当前学生与周围场景 │ 卡片 #17：当前B     │
│ 突出当前框，保持原始像素   │ 类别待审 / 框待审   │
│ 一键看全图并返回原位置     │ 卡片 #18 ...        │
├──────────────────────────┴─────────────────────┤
│ 疑难 / 返回 / 确认10个并下批（2个保留待审）      │
└────────────────────────────────────────────────┘
```

卡片一屏默认目标为 4–6 个，可随窗口和用户偏好调整。显示带上下文的图块、短编号、直接类名和简短状态；颜色仅辅助，不再要求从颜色反查类别。可临时将两个混淆对象并排比较，但不创建复制标注或改变对象身份。

替代方案：仅换色板无法减少类别映射和框归属负担；把 30 个图块全部压成微型缩略图会损失动作证据；因此选用有限卡片与主画布联动。

### D2. 混淆组合只组织顺序，全部对象先入账

- 单图开始本轮时收集所有存活 shape_id，按用户配置的混淆批次顺序分配。类别组合在本轮须互斥；若一个类别出现在多个批次，进入前提示配置冲突并要求修正，不暗中重复分配。
- 未配置类别、未知类别和不支持形状进入“其他待处理”，不会丢弃。错误分到 C 的真实 A 对象仍会在 C 所属批次出现。
- 队列与批次成员关系在本轮稳定，允许所有合法类别的改类；改 A→C 不改变当前卡片位置，不再次进入 C 批次。类名及实际类别统计实时更新，批次计数表示成员数而不是当前 A/B 标签数。
- 默认在一张图内完成各批次再进入下一张，支持中途离开；跨图切换不是确认。类内初始顺序按图像空间位置稳定排序，调框时不实时重新排序。
- 新增/复制对象追加到独立“新增待处理”队列，界面立即更新数量；不混入已经确认的批次，不继承确认。用户也可明确将它加入当前批次，界面先更新确认范围。
- 删除对象从活动计数和队列移除，撤销恢复原身份、位置及一致的状态。新增后撤销不会留下幽灵待审。
- 更换组合不改变已保存的内容确认；重建剩余队列必须显式进行并保留当前对象定位，不因 UI 配置自动重审已完成对象。

替代方案：根据当前 label 每次重新筛选会在改类时丢失位置，且把错误预标注作为排除依据；因此使用全对象账本与稳定批次。

规则资料不假定现有软件已有结构化项目规范。首版提供可选本地复核配置：类别组合、类别判断简述、可见框/完整框/未知策略、补充框规则和版本；在当前类别面板提示对应简述。未配置时按规则未知运行，不阻止基本复核，也不推断两类的框规范等价。规则等价必须依据完整规则签名，不能仅依据同属“可见框”。配置更换需显示影响并按 D6 失效，不能把显示名当成内容版本。

### D3. 默认批次一次确认，范围始终可见

“修改过”“显示/访问过”“用户已确认”是不同事件。任何编辑、悬停、普通选中、普通下一项、翻页或关闭都不构成确认。

默认审查范围为“类别+框”；允许在批次开始前选择“仅类别”或“仅框”。按钮旁持续显示范围和人数，不要求每个对象选两次复选框。

正常批次结束一次点击“完成本批并进入下一批”，包含本批未修改但用户已检查的对象。该操作是用户对明确整批范围的主动声明，**不要求逐卡点击或自动视线证明**。卡片滚动到屏外不改变成员资格；按钮表明“本批12个，包含屏外8个”，可一键展开成员列表，不增加默认确认弹窗。

确认候选集合 = 本批存活成员 − 疑难/暂跳成员 − 手动隐藏/临时用户筛选排除成员 − 源图/对象数据加载失败或已知无法呈现/不支持编辑的成员。画布的自动单目标聚焦隐藏仅属于显示策略，不算用户排除。虚拟列表屏外卡片尚未生成缩略图不算加载失败，不要求先把每张卡滚进视口；原图和标注数据可供用户检查即可。实际呈现失败者明确提示并保留待处理，不能用懒加载名义吞掉已知错误。

有排除时按钮明确显示“确认10个并下批，2个仍待处理”；确认完成后该批为“部分完成”，剩余成员汇入待处理视图。用户可先取消筛选或显示隐藏项，重新纳入范围；不得偷偷解除手动隐藏。确认时固定候选 ID 与内容版本，若操作途中对象或范围变化，取消此次提交并刷新人数，防止确认未展示的新范围。

重复确认同一内容版本为幂等操作。确认命令不改变类别/几何，也不自动解除几何锁定；锁定只禁止编辑，不妨碍明确检查确认。疑难原因可留空，快捷键一次标记即可。

替代方案：逐对象打勾增加正确对象成本；仅凭编辑推断通过会把中间状态当结论；根据“访问过”自动通过不能代表判断；因此采用范围明确的批次主动确认。

### D4. 可选逐框模式不改变普通导航语义

在用户主动进入逐框审核时提供“完成并下一个”和“暂跳下一个”。前者确认当前选择的审核范围，后者保留待审并标记本轮暂跳，避免后续批次完成误收。直接点另一张卡、现有循环查看和翻页仍仅导航。

数字键映射在全部批次固定；A/B 仅视觉突出常用类别，不重排数字。新导航/疑难快捷键进入既有快捷键配置和冲突检测，首版不硬占当前数字、Shift 单点拟合、方向键、撤销或已有创建键。

### D5. 上下文裁切与单目标编辑

- 卡片依据框和可调上下文边距裁切，至少展示当前框范围；不严格截断在预框边界，避免把错误框外的手臂等证据裁掉。裁切贴近图像边界时保留原图边界提示，不生成不存在像素。
- 主画布按框宽、高与上下文共同适配，使用有限稳定倍率档位和最大倍率；相邻目标尺寸接近时尽量保持倍率。倍率只改善观察，不声称恢复缺失细节。
- 默认突出当前框、降低其他标注干扰，原图人物与环境不变；提供临时显示相邻框/全部框及无标注原图的动作，切换后恢复先前状态。
- 卡片、画布、列表通过 shape_id 联动。固定当前编辑目标，只有显式切换才转移；尊重既有锁定和不可见约束，按 Esc 取消预览后可返回通常编辑。
- 全图查看是临时导航，返回恢复目标、倍率、中心点和当前批次，不把未提交拖框带到另一目标。
- 卡片采用虚拟列表、可见项优先与有界 LRU 图像缓存；源像素缓存与类别/状态文字分离，不能在每次鼠标移动时重裁全部对象。小型缩略图可后台处理，Qt 图像对象使用须符合线程约束；提交到 GUI 前检查图片、输出目录和视图代际。

### D6. 两种确认维度，自动保守失效

对象类别确认、几何确认分别保存版本签名；疑难/暂跳单独表示，不能拿旧 `review_status` 代替。界面可合并显示“待审/部分完成/已完成/疑难”，详细状态只在需要时展开。

| 事件 | 类别确认 | 几何确认 | 其他影响 |
| --- | --- | --- | --- |
| 连续调框，尚未确认 | 维持待审 | 维持待审 | 无弹窗、无逐步打勾 |
| 已审对象发生实际几何变化 | 撤回 | 撤回 | 框可能移到另一人，首版保守处理；样式、缩放不算几何变化 |
| 类别变化 | 撤回 | 规则明确等价时保留；不同或未知时撤回 | 批次成员、当前选择不变 |
| 改显示颜色、选择、隐藏、视图倍率 | 不变 | 不变 | 隐藏影响本次确认候选范围，不改变既有结论 |
| 规则变更 | 撤回受影响维度 | 撤回受影响维度 | 无法确定影响时全部失效；不静默套用新规则 |
| 新增/复制/身份被修复 | 待审 | 待审 | 新对象不继承源对象确认 |
| 显式确认相应范围 | 写入当前签名 | 写入当前签名 | 不自动清除疑难；需明确解除后再次确认 |

已审框仅移动一像素也保守撤回两项，是首版可靠性取舍；用户可以在本轮一次确认恢复，不弹额外问题。未来如引入保持对象身份的精细规则，需另行验证，首版不猜测移动是否换了人。

### D7. 独立空间查漏及完成判定

按图像坐标生成可调网格区域，边缘有重叠，覆盖整幅图像；不按当前框生成覆盖区，否则无框目标可能永远不出现。网格计划创建后固定，窗口变化只改变显示，不改变区域身份；改变网格粒度需显式重建覆盖计划。

用户在清晰倍率下自由检查区域，可切换原图/框显示；“完成区域并下一区”一次记录，普通平移、缩放或显示某区域不算完成。允许回看、暂跳和疑难。覆盖表示用户完成过该区域的检查，不表示机器保证无漏标。

查漏中新加框进入新增待处理，不会立即变为已审。新增、删除或几何变更使相交受影响区域失效，几何移动取旧框与新框区域并集；保留其余完成区域。当前区域的修改先提交，再明确完成区域即可。确定不影响标注覆盖要求的纯改类不撤回覆盖；规则改变影响哪些对象应标时重置相关覆盖，影响不明则全部重置。

本流程图片完成条件：全部存活对象的类别与框确认均有效、没有疑难/暂跳/隐藏待处理残留、全部区域显式完成且无待处理查漏问题。没有框的图片仍需查漏；对象数不等于真实人数。混合非矩形图片首版仅允许部分复核，本流程整体显示“不支持完整复核”，原有编辑与正式验收仍独立可用；不能暗示用户应删除真实非矩形对象来获得完成状态。

该“流程完成”不自动覆盖旧图片 `checked`；界面分别显示工作进度与原有验收结论。用户仍可按现有规则作正式验收。完成后发生失效自动撤回本流程完成状态。

### D8. 数据契约、保存与恢复

建议在标注 JSON 顶层加入可选 `xanylabeling_dense_review`，版本 1；在内存中由 `other_data` 传递，实际 JSON 不增加 `other_data` 子对象。进度整体与现有标注同次原子保存，不增加 sidecar 双文件一致性问题。

| 字段组 | 设计内容 |
| --- | --- |
| version / context | 模式版本、图像像素内容与尺寸指纹、规则配置版本；路径只用于会话隔离，不作为跨文件自动继承依据 |
| objects | 以持久 shape_id 为键的类别/几何当前签名、各自确认签名、疑难维度/原因、暂跳状态 |
| batches | 固定批次身份、类别快照、成员 ID、处理顺序、当前批次和对象 ID；新增待处理名单 |
| coverage | 区域计划版本、图像坐标范围、各区域完成/疑难及有效内容基线；基线含对象 ID 与旧规范化边界，以定位外部移动/删除前的受影响区域 |
| completion | 由当前有效状态计算，不信任磁盘上的孤立 true 标志 |

签名依赖：类别签名包含类名、影响类别判断的属性、几何内容及相关规则；几何签名包含 shape 类型、坐标、框规则。未知框规则将类名纳入几何签名。为避免撤销把失效状态错误复活，内容签名之外仍通过统一编辑/审核历史保存真实状态变迁。

矩形几何签名使用规范化 xmin/ymin/xmax/ymax 与稳定数值表达，忽略等价顶点顺序、整型与浮点 JSON 表达差异。当前保存会规范化矩形点序，保存重开不得仅因此失效；真正坐标变化仍必须被识别，不以粗糙取整掩盖微调。图像指纹在加载/验证阶段生成并缓存，不在鼠标移动热路径计算；与画布实际使用的方向和尺寸保持一致。

只读打开不写文件；首次进入工作区可建立临时队列，直到产生编辑/确认/需要持久保存的进度变化才标 dirty。保留现有自动保存策略，不增加逐鼠标移动磁盘写入；明确确认仅修改内存并沿用保存机制，界面区分“已确认未保存”和“已保存”。

重开时先核对图像指纹、规则和每个对象内容；缺少元数据按尚未开展流程处理，不从旧 checked/review_status 推断通过。身份重复或修复的对象按待审处理，不猜测状态属于哪一个对象。仅图像像素变更时重置本图对象确认和空间覆盖；只有标注改动时按对象及区域保守失效。

外部移动/删除通过保存的覆盖基线定位旧边界，与现存新边界一起确定失效区域；新增对象只有新边界。若缺少可信旧边界、身份关联或基线版本，撤回整图覆盖，不能只处理新位置而把旧位置错误保留为已查漏。

输出目录切换重新加载对应 JSON 与独立进度，不能带入上一输出目录状态。未知版本/损坏的新命名空间保留原内容并显示“不兼容/不可恢复”，不宣称完成；用户明确重建前不覆盖该命名空间。旧字段和其他扩展字段原样保留。

如果磁盘 JSON 在会话期间外部变化，保存前检测版本变化并走现有或新增的明确冲突处理，不能用审核数据覆盖外部标签。重新加载后重新验证所有签名。失败保存保留 dirty 与内存结果，原文件保持有效；取消切图保持当前对象和队列。

替代方案：sidecar 会要求跨文件事务并容易与输出目录错配；直接扩展旧 review_status 会改变已有数据含义；因此选用顶层独立命名空间。

### D9. 撤销、控制器与异步隔离

新增小型纯状态模型负责队列、确认候选、签名失效和覆盖；协调器连接现有编辑、加载、保存与视图。批次确认作为一个可撤销命令，undo 恢复此前状态和游标，不回滚用户在该批之前的标签内容。

所有几何/类别/新增/删除命令将相应进度变化纳入同一事务；undo/redo 恢复完整一致状态，不出现框恢复而确认不匹配。清空历史、加载文件和既有快照策略需显式适配，不能只给新 UI 做独立撤销栈而造成两个 Ctrl+Z 含义。

图片与输出目录组合为会话键；加载、缩略图、状态回填均携带代际标识。旧结果只能被丢弃，不改变新图选择、计数或确认。纯布局变化不产生标注编辑历史。

### D10. 首版分阶段交付与验收门槛

任务按模型与存储 → 批次/卡片/聚焦 → 低成本确认 → 查漏 → 验证的依赖实施。工作区先以默认关闭的可选入口落地；批次与空间查漏都完成前不得展示全流程完成。阶段中间态只供开发/试用，不冒充最终交付。

验收数据至少覆盖：30 人/6 类密集图、小目标、遮挡规则不同、错误框截掉手臂、错分到第三批、所有预标注正确、部分疑难、无标注图片。使用公开、自制或获准素材；写操作测试使用副本。

硬行为门槛：普通编辑零额外状态确认；全正确的 N 对象批次一次显式动作即可确认并前进；未审/疑难对象零自动误通过；保存重开、撤销、跨目录、身份冲突和外部修改零状态串用。

性能目标（待测，不是已实现结果）：固定环境重复至少三轮，卡片暖缓存切换到画布可编辑首帧 p95 ≤150ms，交互期间 GUI 心跳延迟 p95 ≤50ms；密集图拖框 p95 相比同环境基线不得回退超过10%。分别报告冷启动、暖缓存、对象数、图像尺寸、缓存峰值和卡片后台负载，不以单函数耗时代替整条 GUI 路径。

人工减负验收：两位实际使用者在难度匹配且顺序交叉的图片组中各试用至少两轮，记录每百对象缩放/拖动/重复访问/确认次数、总耗时、错误与返工，以及同等时长后的疲劳自评。独立复核并记录分歧，不只看对象/分钟；明确安全指标无退化、两人均愿意采用且至少一项主要负担指标改善，才标为减负已验证，否则保留试验状态并调整。小样本结果不得推广为普遍收益。

## Risks / Trade-offs

- [批次一次确认可能涵盖未认真检查的对象] → 明示固定范围及屏外人数；疑难/排除项保留；把此动作定义为用户主动声明，保留整图查漏和独立抽查，不伪装为自动验证。
- [主画布聚焦失去空间关系] → 保留原始背景、上下文边距和全图返回，临时展示邻框，稳定倍率与位置。
- [冻结批次使当前类别数与成员数不同] → 分开标注“本批成员”与“当前类别统计”，提供跨类修改标记，不静默重新排序。
- [保守失效增加少量返查] → 按对象/受影响区域失效，批量一次恢复；不得用不可验证的自动正确判断换取表面速度。
- [状态模型扩大撤销与保存复杂度] → 纯模型测试先行、统一命令事务、同文件原子保存、恢复签名检查。
- [卡片后台负载破坏现有拖动优化] → 有界缓存和代际丢弃、可见项优先、基线对照；不在鼠标移动热路径做全量扫描或重裁切。
- [小目标本身无足够证据] → 支持疑难与人工规则澄清，不强迫确认，放大不宣称生成细节。

## Migration Plan

1. 未来实施前记录工作区基线、未提交改动和已有失败测试；按本项目定制台账规则创建本功能的独立“方案/实施中”记录。
2. 添加默认关闭的工作区及版本化可选元数据。旧 JSON 不做目录级批量迁移，用户有意产生进度并保存时才写入。
3. 在测试副本验证旧/新文件往返、旧审核字段、其他扩展字段与既有导出路径兼容；训练导出仍输出原标签语义，不把本流程元数据作为类别/属性。
4. 通过行为/性能门槛后，由两位用户在授权样本上试用；记录未通过项并修复，再讨论启用默认值。
5. 回退先关闭工作区并恢复代码；保留新命名空间而不解释为旧审核通过。回到旧程序后若标签被编辑，新程序再次打开必须重新核对签名并使过期确认失效；不得要求删除用户标签来回退功能。
