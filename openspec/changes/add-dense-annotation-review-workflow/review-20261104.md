# 密集标注复核工作流：任务与验收证据复核

日期：2026-11-04（Asia/Shanghai）

范围：本变更的 proposal、design、三份增量规格、tasks、verification，以及相关工作区、缩略图、会话、测试和性能脚本的只读核对。本轮仅修改本目录 OpenSpec 文档，不修改应用、测试、脚本、翻译、样本或历史报告，不执行新的 GUI、性能或人工试用。历史通过结果不能视为当前工作树重新运行的结果。

结论：首版实现及部分自动化证据存在，但不能认定全部功能或交付门槛完成。原清单仅剩三项未勾选，遗漏了已知实现缺口和证据不足项。本轮保留已确认的历史成果，撤回证据不足的整项勾选，并补充明确验收条件。下列实现问题来自静态检查，未在本轮运行 GUI 复现；不能据此声称已修复。

## DR-01：跨批次导航的会话与列表可能不同步（P1）

- 证据：`workspace.py::_navigate_to` 先调用 `session.set_current`，再调用 `refresh_all`；`_refresh_batches` 优先采用旧 `batch_list.currentItem()` 对应批次，`_refresh_cards` 又按列表选择取成员。会话已经进入下一批时，批次高亮和卡片可能继续显示上一批；`_focus_current` 则按会话对象聚焦。历史性能报告的 Limitations 也明确记录了这一现象。
- 影响：画布目标、卡片、批次范围提示及确认入口可能不一致；不能把“会话已前进”当作整个导航完成。
- 文档处理：重开 4.4，在工作区规格中加入跨批次一致性场景。
- 验收：至少配置两个非空批次，分别通过整批完成、逐框完成和暂跳跨越批次边界；断言会话、列表高亮、卡片成员、画布目标及下一次确认范围一致，且不增加额外确认。

## DR-02：切批后卡片请求与并排比较缺少完整异步链路（P1）

- 证据：`workspace.py::_on_batch_selected` 重建占位卡片后，没有明确调用或调度 `_request_visible_thumbnails`；是否因布局/滚动事件偶然触发请求不能代替确定保证。历史报告也记录切批后缓存图标未恢复。`_compare_selected` 仅在创建对话框时读取 `cached_latest`，缓存未命中时写“图块准备中…”，没有为比较视图发请求或订阅迟到成功/失败；`_on_thumbnail_ready` 只更新主卡片。
- 影响：冷批次可能停留在占位图；比较视图可能一直显示准备中，即使主列表随后已取得图块。
- 文档处理：在 4.4 与 5.5 补充修复和测试要求，重开 5.5；新增冷缓存比较、失败恢复与切批图块场景。
- 验收：直接点击冷/暖批次，无需额外滚动、缩放或再次选择即呈现当前可见图块；比较时即使缓存为空或被淘汰，也能请求、更新或明确失败并恢复。迟到结果必须符合图片、对象内容、上下文和代际，关闭比较窗口后不得更新已销毁控件。

## DR-03：懒生成缩略图不能等同完整卡片虚拟化（P2）

- 证据：`workspace.py::_refresh_cards` 为当前批全部成员创建 `QListWidgetItem`；`_request_visible_thumbnails` 遍历 `_shape_items` 判断可见性。provider 的图像 LRU 有界，但卡片项、图标和可见性遍历并不因此受相同上限限制。`verification.md` 已承认完整虚拟列表未实现，却将其排除出验收门槛，与设计 D5、任务 5.3 相矛盾。
- 文档处理：重开 5.3，撤回“不属于验收门槛”的说明；保留已实现的懒生成、缓存版本键和代际检查，不降低原范围。
- 验收：证明可见卡片及预取范围有界；分别统计 provider 图像、卡片持有的 QIcon/QPixmap、请求/完成队列及进程内存，而非仅统计 LRU 条目。虚拟化不能改变屏外成员的明确批次确认资格。

## DR-04：小窗口收起辅助区域尚无实现与验收证据（P2）

- 证据：对象页 `QSplitter.setChildrenCollapsible(False)`；现有布局适配和整个工作区关闭不能证明可单独收起卡片/导航辅助区域。验证记录明确写“小窗口专用收起控件”未完成。规格首条及设计 D1 已承诺该行为。
- 文档处理：重开 4.1；5.5 的小窗口部分仍须验收。
- 验收：在约定窄窗口和系统缩放下收起、展开辅助区域，保留主画布、待处理数量及批次动作；焦点、当前对象、进度和手动显示状态保持，不把退出整个工作区当作替代。

## DR-05：翻译和打包验证被过早合并为完成（P2）

- 证据：`test_translations.py` 主要检查 Redo、中文工作区和中文新文案，没有完整覆盖日/韩工作区主体；验证记录承认日/韩主体回退英文以及资源内嵌 `.qm` 仍旧。历史“413 条”是当时统计，不能作为本轮重新计数结果。
- 文档处理：重开 7.8，区分源码磁盘 `.qm`、打包资源路径和真实屏幕验收；本功能主体文案不能因与其他历史未翻译项合计而排除。
- 验收：按本功能所有用户可见文案和实际 Qt 上下文核对中英日韩；覆盖状态模型、失败提示、配置及快捷键，无障碍名称和键盘可达性；源码与打包入口分别运行，附窄窗口结果。其余无关历史翻译不并入本变更范围。

## DR-06：性能“通过”的计时终点缺少正确性断言（P1）

- 证据：`benchmark_dense_review.py::measure_switch` 仅执行 `navigate()` 和一次 `pump()` 后停止计时，返回绘制计数；它不直接证明目标身份正确、目标首帧已经完成且此时可编辑。批次路径还受 DR-01/02 影响。历史数值分别是图内对象/批次切换，不是加载另一张图片的耗时。
- 文档处理：重开 10.1，保留 10.2 未完成；历史暖切换数值仅作原口径测量，不能据此完成“目标首帧可编辑”验收。心跳数据也不代表正确目标已呈现。
- 验收：先断言目标/批次/卡片一致，再以正确目标首帧完成并可接收编辑为计时终点；超时、错误目标和未完成样本单列，不能删除或作为快速通过。区分图内导航、真实切图、冷启动、缓存及后台负载；同环境至少三轮，记录样本数、代码版本和配置。
- 门槛保持：暖切换 p95 ≤150 ms、心跳 p95 ≤50 ms、拖框相对基线回退 ≤10%。30 对象历史拖框 +18.9%/+24.8% 仍未通过，绝对耗时较小不能豁免既定门槛。本轮不重跑也不修改阈值。

## DR-07：对象遍历及 generation 清空不足以证明连续切图内存有界（P2）

- 证据：`_probe_cache` 在同一张图上遍历对象；`_cache_report` 直接递增 generation 并手工清空部分映射，随后将结果命名为 `image_switch_reset`。这些证据证明部分缓存行为，不能代替真实切图/切输出目录的生命周期。历史峰值主要是 provider QImage 字节，不是全部图形资源或进程峰值。
- 文档处理：重开 10.3，明确区分对象切换、模拟代际清空和真实图片切换。
- 验收：经正常加载路径反复切换不同图片和输出目录，包含迟到任务、关窗重开和取消；记录各类资源、未完成任务及进程峰值与稳态，检查不随轮数持续增长。每次鼠标移动无全量重裁及无指纹计算的历史成果单独保留。

## DR-08：场景映射及保存/恢复证据尚不完整（P2）

- 证据：verification 的映射为主题级，包含 `test_payload_round_trip...` 和“GUI 批次测试”等不可直接定位的指代，未逐条列出三份规格的 Scenario。8.3 自述“重开回到区域未单独自动化”；3.4 未测自动保存写入次数；`test_external_change_is_detected_before_save` 只断言检测函数，没有执行保存冲突对话框的完整选择路径。
- 文档处理：重开 8.3、9.1，新增 3.8（保存频率/失败/取消）、3.9（外部冲突交互）。未验证表示缺少证据，不等同已经证实产品失败。
- 验收：每条 Scenario 对应完整 pytest node ID 或明确人工步骤、环境、预期、实际结果和证据；覆盖查漏区域重开定位、疑难/暂跳恢复、自动保存写入边界、冲突重载/取消及实际提供的覆盖保存选择。不能以函数存在或文档链接代替行为结果。

## DR-09：假 worker 与历史分文件通过不足以完成当前集成回归（P2）

- 证据：延迟注入用假 executor/future 验证代际过滤，这是有效逻辑测试，但不证明真实线程退出、取消和 Qt 对象销毁安全。验证记录还保留 settings 目录合跑的原生访问冲突；后续设置持久化、画布恢复等工作树改动使 2026-11-02/03 结果不等同当前结果。9.6 自述关闭后的主要操作未完整覆盖。
- 文档处理：重开 9.3、9.6，新增 9.7 当前工作树集成复验；历史数据按日期保存，不直接归因崩溃属于本变更，也不记成通过。
- 验收：保留假 worker 确定性测试，并补真实 executor 的切图、取消、关闭、重开和任务退出验证；关闭工作区后覆盖数字改类、拟合、拖边、保存、快捷键、撤销/重做。记录当前修订和定向回归，对原生退出记录复现命令及基线对照，未定责时明确未决。

## DR-10：试用与交付判定需可复现且不能由文档校验替代（P2）

- 证据：10.4/10.5 尚无实际用户试用；现有文字未固定图片复用、难度匹配、质量分母及空图统计方式。11.3 在“所有承诺有实现和证据”尚未满足时已勾选，strict 只证明文档结构有效。
- 文档处理：保留 10.4/10.5 未完成，补充试用协议；重开 11.3。更新 proposal、design 与 verification 的过时“自动化通过/仅三项剩余”等状态。
- 验收：两位真实使用者各至少两轮、交叉顺序，优先使用互不重复且难度匹配图片组；复用图片时披露记忆效应。事先记录规则、设备、主要指标和质量判定口径；统计空图每图耗时/漏标，不能除以零。独立复核保留分歧及裁决，并同时报告错类、框错误、漏标、误检和返工的计数与分母。只有约定范围质量未退化、两人愿采用且主要负担改善才记录有限样本通过。
