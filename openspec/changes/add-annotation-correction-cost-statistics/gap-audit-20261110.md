## 2. 实测结论（纯服务层探针，全部通过）

- 2.3：反序点序+取整/浮点混写 → `geometry_changed=0, unchanged=1`；真实微调 1e-7 → `1`；同对象同时改类改框 → `modified_original=1, C=1, G=1`；新增对象 → `added=1, modified_original=0`；**新建后再删除 → added=0, deleted=0**；纯重排 → 全 0、unchanged=2；B 空 → 两率为 None、added=1；非有限坐标 → `invalid-geometry` 且不入 G。**无固定像素容差**（符合 design D3「不使用可吞掉小目标真实微调的容差」）。
- 2.4：一批两对象 → `(transactions=1, touches=2, unique_objects=2)`；重复 tx ID → 返回 False 且计数不变；内容不变提交 → 不计数；撤销后 → `undo_count=1, transactions 仍=1(仅 edit), ops={'edit':1,'undo':1}, touches=3`，**净结果回落 (added,deleted,G,unchanged)=(0,0,0,1)** ——过程与净结果分离正确。
- 2.5：合并（A,B→X）→ `comparable=False, C=None, modified_original=None, unchanged=None`，而 `geometry_changed=0` 仍展示；`alias={'B':'B2','A':'A2x'}` 链式映射正确记录；拆分（传 list）→ `isinstance(str)` 失败 → `unique=False` → 标 `class-incomparable`（**不会静默当空集**）。
- 3.x：见总览表逐项实测。

## 3. 缺陷（与 spec 冲突 / 会静默丢数据）

### M1（必须补）`comparable = not issues` 把“来源未知”当“不完整”，静默排除全部历史轮次
- 位置：`core.py:228-229` 把 `unknown-origin` 加入 issues；`:257` `"comparable": not issues`；`reporting.py:77-85` `exclusion_reasons` 把 issues 全量当排除理由；`:97-109 outcome`、`:124-129 density_groups`、`:155-160 class_groups` 全部据此过滤。
- 复现（实测）：任意 `origin="unknown-existing"` 的新轮次 `row(draft=True)["comparable"]` 即 `False`，`issues=['unknown-origin']`。→ 汇总页/CSV/密度分组/类别分组**一条历史标注轮次都进不去**。
- 冲突：baseline spec「对历史标注开始统计…显示未知来源，仅统计启动后的过程成本」，并未要求排除完整对照；events spec 只允许 **范围/类型转换/日志计时缺口** 使完整比较失效。来源未知是**披露项**不是**阻断项**。
- 修复建议：把 issues 分为 blocking（partial-scope/type-conversion/storage-gap/interrupted-time/shape-identity-conflict/invalid-geometry/external-annotation-change/unobserved-content-change）与 disclosure（unknown-origin），`comparable = not blocking`；`exclusion_reasons` 只吃 blocking。

### M2（必须补）个人改类后再做全局一对一改名 → 幻影改类（C 虚增）
- 位置：`core.py:434-441` alias **只从 baseline 标签出发**（`old_names` → `mapping.get(previous)`）；`:442-449` 却用 mapping 的 **key 直接匹配当前 draft 标签**（`mapped[label]=mapping.get(label,label)`）。两处坐标系不一致。
- 复现（实测）：baseline `r1:A` → 个人改为 `A2`（tx1）→ `taxonomy({"A":"A2x"})`：`alias={'A':'A2x'}`，但 draft 标签仍是 `A2` → `class_changed=1`（幻影），期望 **C=0**（A→A2x 即个人改动后的语义终点）。
- 冲突：events spec Scenario「改名前已有个别改类…保留该对象从 B 到 A2 的语义改类和此前操作成本，不因映射消除既有修正」。
- 修复建议：tomapping 按**类别版本**表达（`{version, mapping}`），应用时对 draft 标签沿 alias 逆链归一化（`A2 → A → A2x`），并让 alias 与 draft 重命名共用同一函数。

### M3（必须补）无归属故障永不可见 → 预测来源静默丢失
- 位置：`storage.py:107-114` `_fault(round_id, ...)` 允许空串；`:198` 写异常时 `kind!="write"` 传 `""`；`:327-338` `record_prediction` 队列满 → `_fault("", "prediction record unavailable")` 后**返回 None**；`:112-114` `gaps("")` 不被任何轮次读取（`core.py:298-299` 只查 `round_id`）。
- 后果：预测运行记录丢失、`run_id/model/ai_count` 缺失，但轮次 issues 里**没有任何 storage-gap**；调用方若不检查 None 即为静默丢数据。
- 修复建议：无归属故障写入一条 `pending gaps`（持久化），在该数据集下次 open/row/iter 时挂到受影响轮次；`record_prediction` 失败必须落到具体 image/label 的缺口。

### M4（建议补，1 行）B 为空时类别明细分母输出 0 而非 N/A
- 位置：`core.py:176-178` `denominator=counts[("initial", old, "")]`，B 空时为 0；`export.py:87-89` 只把 None 转 "N/A"。
- 实测：B 空 → `[('added',0), ('final',0)]`。冲突 design D3/CSV 契约「分母为零时输出 N/A 而非零或无穷」。修复：`denominator or None`。
