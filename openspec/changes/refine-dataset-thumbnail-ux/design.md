## Context

数据集导入通过 `LabelingWidget._attach_existing_dataset_index()` 调用共享控制器的 `attach_existing()`；控制器默认策略为 `DatasetIndexAutoRefreshPolicy.ON_CACHE_ATTACH`，并在兼容缓存挂接后调用 `schedule_auto_refresh()`，默认延迟 1500 ms 后执行增量刷新。缩略图窗口构造本身没有启动扫描，但常与这次延迟刷新在时间上重叠。

共享控制器同时服务数据集筛选，不能把默认自动刷新策略全局改为禁用。当前缩略图裁剪严格使用 bbox，缓存键也只包含图片状态、对象身份、bbox 和输出尺寸。delegate 只有普通选中边框，没有独立的反向定位状态。

## Goals / Non-Goals

**Goals:**

- 让缩略图窗口拥有明确的手动扫描入口和可见进度，同时保留共享控制器的默认自动刷新策略。
- 用确定性的水平 padding 改善对象上下文，并保证缓存自动失效。
- 分离“主画面定位目标”和“改标候选选择”两种视觉语义。

**Non-Goals:**

- 不取消已经运行的共享索引任务，不建立第二套索引控制器或扫描器。
- 不增加自动标注、删除、任意字段编辑、跨页选择队列或新的撤销机制。

## Decisions

### 1. 使用可恢复的自动刷新暂停租约

共享控制器增加窄接口：暂停尚未触发的自动刷新计时器，以及在缩略图窗口关闭时按原策略恢复调度。打开缩略图前由主界面取得该租约；按钮仍调用共享控制器的 `refresh()`/`rebuild()`。接口不改变 `auto_refresh_policy`，也不取消已经运行的任务，因此不会全局关闭筛选功能的自动刷新能力。

如果窗口打开时共享任务已经运行，窗口只观察并显示现有任务进度，不重复启动任务。

### 2. 一个按钮映射两类现有扫描操作

窗口只显示“开始扫描”：存在可读缓存时调用增量刷新；索引缺失或连接不可用时调用重建。窗口复用 `progress_changed(int, int, str)`、busy 和终态信号更新进度，READY 转换继续走现有标签与首页加载路径。

### 3. 水平 padding 固定为 bbox 宽度的 15%

渲染前计算 `pad_x = bbox_width * 0.15`，只修改 x 最小/最大值，再沿用 floor/ceil 与图像边界裁切。此决策定向修订归档设计中的“首版不增加自动 padding”：仍不做垂直 padding、智能构图或按 Shape 类型变化的策略。

缓存键增加显式裁剪策略版本，而不是依赖隐含代码版本；这使既有无 padding 缓存必然失效，也为以后兼容性判断提供稳定边界。

### 4. delegate 分层绘制两种边框

模型保存单个可选的定位对象身份，并暴露 FocusRole。delegate 先绘制普通/选中卡片边框，再为 FocusRole 额外绘制白色内框。改标候选使用更粗、更亮的蓝色外框；白色仅表示主画面反向定位目标。

程序化反向定位设置白框时使用内部选择更新门禁，避免被 selectionChanged 当作用户操作清除；普通用户选择变化则清除白框。

## Risks / Trade-offs

- [自动刷新计时器可能在窗口打开前已经触发] → 不取消共享运行任务，窗口显示其进度；测试保证窗口不会新增第二个任务。
- [selectionChanged 无法天然区分程序化与用户操作] → 在 `focus_object()` 的清选/选中过程使用短生命周期内部门禁。
- [padding 策略变化导致一次性缓存未命中] → 这是预期迁移，旧缓存保持可丢弃且不会污染数据集。

## Migration Plan

无需数据迁移。发布后新裁剪策略通过缓存版本自动旁路旧 PNG；回滚代码即可恢复旧裁剪行为，派生缓存可直接删除。
