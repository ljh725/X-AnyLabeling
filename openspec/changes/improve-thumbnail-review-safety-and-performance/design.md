## Context

动机与范围见 proposal.md。2026-09-07 静态检查确认：

| 当前实现 | 对计划的影响 |
|---|---|
| 主画面 selection_changed 调用反向同步，focus_object 会切标签、换页、清选择 | 普通选择不能触发导航；显式定位与改标候选分离 |
| 单标签查询，每页最多 100 对象，普通选择翻页后清空 | 保留既有边界，核心是统一展示某一类标签筛选后的对象 |
| 多对象改标已有确认、备份、原子提交、恢复清单、刷新屏障 | 不另造批量撤销，也不删除已有安全设施 |
| 单对象也走批量改标事务 | “单对象可撤销”需增加明确入口和字段级反向修改语义 |
| 打开窗口不自动扫描；扫描已有文件进度；可见区域生成已有占位和逐项回填 | 保留既有边界，补齐生成阶段进度 |
| 每批同一原图解码一次、2 个并发、512 条内存缓存；request 同步 stat/读磁盘缓存 | 先测量主线程阻塞和大图解码，不能预设裁剪最慢 |
| invalidate 仅拒收旧结果，不停止旧任务 | 快速翻页可能积压无用工作，需调度取消和可见区优先 |
| 键盘释放裸访问 shapes_backups；延迟备份只在鼠标路径冲刷 | 风险文档与代码吻合，修复覆盖所有程序化选择入口 |

用户列出的经验正文共 9 项，本计划逐项覆盖。文档中的 IndexError 与用户感知的“卡死”分别记录；复现前不把所有卡顿归因于同一异常。

## Goals / Non-Goals

**Goals:**

- 普通选中零导航；显式定位一次完成；某一类标签的对象统一展示，继续支持本页多选。
- 以对象数量区分单对象与多对象，给出清晰的修改、撤销和异常恢复语义。
- 窗口尽早可操作，计算进度真实，优化有分阶段计时与相同数据集的前后对照。
- 先恢复安全的键盘编辑，再开展窗口与批次交互改造。

**Non-Goals:**

- 本期不做几何、group_id、属性、删除、自动标注等缩略图编辑。
- 不做多步骤批量撤销/重做栈、跨会话单对象历史、多用户冲突合并。
- 不扩展多标签并集查询、混合展示、跨标签/跨页保留普通选择或独立已选对象视图。
- 不全量预裁剪数据集，不把用户的复核进度与机器生成进度混为一谈。
- 上一页的新定位规则留到用户讨论后单独补充，本期不擅自改动。

## Decisions

### 1. 导航必须由明确动作触发（经验 1、7、8）

- 主画面普通单选、多选和类别变化不调用缩略图反向定位，也不清除缩略图当前页选择。
- 增加“在缩略图中定位”菜单/按钮和可配置组合键。默认按键在实现时查现有绑定后确定，不占用数字标签键或已有快捷键。
- 主画面定位要求恰好一个有效对象；无对象、多对象、失效身份时禁用或给出非模态说明。
- 缩略图单击只选择；双击、Enter 及显式菜单保留到主画面导航。定位焦点单独绘制，不能自动把定位目标加入批次。显式反向定位需要切标签或换页时，沿用既有页面切换的选择清理规则；同页定位保留本页选择。
- 两向定位保留重入防护、数据集/请求代次检查、未保存修改守卫。对同一目标的连续请求合并，旧请求不能覆盖新定位。

仅增加延时防抖仍会误跳，故不采用；保留自动跟随开关也不纳入本期默认行为。

### 2. 修复修改前快照与可靠收尾（经验 5、8）

- 在第一次有效键盘几何修改前确保初始快照存在；不要等到按键松开后才保存“修改前”状态。
- 抽取或复用一致的快照准备语义，避免直接调用现有 store_shapes 导致重复初始快照；一次连续键盘编辑只形成一次可撤销动作。
- 释放阶段处理空备份、短备份、对象消失/重排及切图，不盲用当前数组下标匹配旧对象；身份无法确认时进入明确的安全收尾。
- 完成实际修改时正确记录备份、发送 dirty/移动/旋转通知；无变化不制造撤销条目。所有退出分支清理 moving/rotating 状态。
- 覆盖 Inspector、缩略图、标签列表、Ctrl+A，以及按键尚未释放时切图/关闭窗口。

只补边界判断能避免部分异常，但可能丢失通知和可撤销性，因此必须与修改前快照一并完成。

### 3. 保留单标签筛选后的统一展示（经验 4）

- 浏览条件仍为一个标签，统一展示数据集中命中该标签的具体对象，包括来自不同图片的同类对象；按图片/对象顺序稳定分页，每页最多 100 项。
- 保留本页对象多选，不新增多标签并集查询、混合网格、跨页普通选择集合或已选对象汇总页。
- 切换标签或翻页时清除普通当前页选择；仅沿用现有机制，恢复仍位于目标页的失败、冲突或取消对象。数字键和按钮只提交本页有效选择。
- 同一页的异步图片回填不得改变选择；定位标记与改标候选保持独立。
- 继续按完整永久对象身份生成改标快照，不使用数组位置猜测目标，也不合并主画布的跨图标记集合。

### 4. 单对象轻量撤销，多对象明确确认（经验 2、3、5）

| 项目 | 单对象 | 多对象 |
|---|---|---|
| 判定 | 冻结快照只有 1 个不同对象 | 冻结快照有 2 个及以上对象，哪怕都在同一图片 |
| 写入范围 | 仅该对象 label | 仅所选对象 label |
| 提交提示 | 原标签、目标标签、立即写盘、单次撤销入口 | 本页所选对象/涉及文件数、原标签、目标标签、立即写盘、不进入普通撤销栈 |
| 普通撤销 | 结果条提供最近一次成功单对象改标的撤销按钮 | 不提供普通撤销/重做 |
| 安全基础 | 共享预检、暂存、原子提交、刷新屏障 | 同左，保留既有备份和事务恢复 |

- 单对象记录完整身份、原 label、新 label 与版本/指纹；撤销是通过共享事务对当前数据实施 label 反向修改，不恢复整个旧 JSON。
- 执行撤销前重新读取并唯一定位，验证 label 及冲突令牌，校验到提交之间保留文件版本守卫；不覆盖其他对象或本对象后续几何/字段改动。无法安全证明时拒绝并解释。
- 会话内保留最近一次可撤销记录；后续新的成功改标（包括批量）、相关外部/画布标签冲突、关闭窗口或切数据集使其失效。取消、失败、无变化操作不消费有效记录。
- 当前文件有未保存内容时仍走保存或取消守卫。撤销后的索引和当前画布必须同步，失败时维持刷新屏障，不能伪报成功。
- 本期不绑定全局 Ctrl+Z 到磁盘事务，避免与画布几何撤销混淆。普通画布撤销不应重放过期 label，实施中须测试共享刷新路径是否清理/重建旧画布历史。
- 批量确认框提供本页所选对象清单。快照以用户确认的范围为准，执行中新增选择不进入该批次。
- 已有“恢复本次…”是应急事务恢复，不是普通撤销；维持该入口及其版本检查，不新建复杂历史栈。仅警告用户不能替代原子写入、预检和错误反馈。

采用两套写盘逻辑会使一致性与故障处理复杂化，故只区分交互与反向变换，底层复用同一事务。

### 5. 明确扫描、生成和显示三个阶段（经验 6）

```text
开始扫描 → 读取标注/构建或刷新索引 → 可分页查询
查看一页 → 可见对象元数据 → 命中缓存或后台读取/解码原图
                            → 裁剪 → 缩放 → 编码/缓存 → 卡片显示
```

- 扫描不是全量裁剪。其进度沿用已处理文件数/总文件数/当前文件；索引未 ready 时继续禁止修改，不开放半成品索引写入。
- 生成进度采用“当前视图请求 N，完成 X，失败 Y”，包含缓存命中，并说明按需加载；滚动扩展请求集或换页时计数按当前代次更新。
- 扫描时可见文件进度；索引 ready 后立即出现占位卡片，生成完成逐项显示；不等待全部缩略图完成，不显示无法可靠估算的剩余时间。
- 错误项可重试，失败计入已结束任务，不能让进度永久停在最后一项；低优先级预取单独计数或不计入前台分母。

### 6. 分阶段测量并优化主线程路径（经验 6、7）

先建立以下场景基线，再按占比决定优化量：

| 场景 | 必记指标 |
|---|---|
| 首次打开且缓存为空 | 请求到窗口可见、首卡片、首屏完成、事件循环最大阻塞 |
| 已开窗口重新激活 | 请求到可交互；是否重复查询/重载 |
| 显式定位到其他标签或页面 | 查询、布局、滚动定位、首屏完成与请求代次 |
| 快速连续翻页/关闭窗口 | 队列峰值、取消数、旧任务耗时、关闭延迟 |
| 同图多目标、大分辨率图片 | 解码次数与峰值内存、每对象裁剪/缩放/编码耗时 |

分别记录 SQL、stat、磁盘缓存读取、源图读取/解码、crop、scale、PNG 编码、缓存写入、主线程应用结果/绘制的 wall time。并发任务耗时不能简单相加解释端到端耗时。记录图片大小、对象数、磁盘、冷/热缓存、样本量、p50/p95。

优先措施：

1. 先显示窗口壳和状态，再异步准备查询/缓存数据；SQLite 工作线程用合适的独立连接，不能把当前连接直接跨线程使用。
2. 将 stat、磁盘缓存读取放到后台；同一路径同批次复用文件状态，避免同图逐对象重复 I/O。
3. 清理尚未启动的旧代次任务；运行任务在对象之间协作取消，解码器执行中不承诺强制中断。关闭窗口不在 UI 线程等待工作完成。
4. 当前可见项优先于预取，后台任务数与内存有界；保留同图一次解码，不无上限缓存整图。
5. 对未变化卡片避免重复 PNG 解码、重复 layout/reset；主线程结果应用采用有界批次，保留选择、焦点、滚动锚点。

首轮建议验收预算（待 P0 基线记录设备后固化，以下不是已测结果）：有效索引下窗口壳/热激活 p95 ≤ 200 ms；热缓存显式定位 p95 ≤ 300 ms；常规场景事件循环单次阻塞 ≤ 100 ms。冷缓存首屏以分辨率/磁盘分组报告，不设置脱离数据条件的统一秒数；主要瓶颈场景 p95 目标较基线下降至少 30%，同时不得以扩大内存或漏图换速度。

### 7. 下一页回首行，位置与选择分开（经验 9）

- 新页数据和布局可用后显式回到顶部，把键盘 current index 放到首个可用卡片；该动作不勾选它、不导航主画布。普通选择按既有翻页规则清理，不跨页保留。
- 空页不设置无效索引；末页缩短时先夹紧页码；加载失败保留可解释状态。
- 上一页本期保持原行为。建议后续考虑恢复该页上次滚动与焦点，但未经用户决定不写成当前强制行为。

## Risks / Trade-offs

- 分页定位被误当作多选 → 键盘当前位置与候选边框分开，翻页不得自动选择首项。
- 改标导致对象从单标签筛选结果消失 → 成功/无需修改项移出本页批次，失败/冲突项沿用既有恢复规则；只刷新受影响页/文件。
- 不增加批量普通撤销降低交互复杂度，但误操作成本仍存在 → 明确确认，复用已有受保护事务恢复。
- 单次标签撤销与画布快照冲突 → 统一文件刷新与历史协调测试，不将整个旧文件覆盖回去。
- 仅禁用跟随掩盖底层异常 → P0 单独通过键盘备份回归后才能验收风险修复。
- 后台取消和销毁存在竞态 → 所有回调检查数据集/窗口/代次；避免访问已销毁 Qt 对象。
- 阶段进度频繁重置让用户困惑 → 明示“当前视图”，前台与预取计数分离，失败明确终结。

## Migration Plan

按 P0 安全与基线、P1 显式导航/单标签浏览回归/分页、P2 改标语义、P3 性能/进度、P4 集成验收推进；P0 可先独立实施，上一页讨论不阻塞它。主规格在实现验收后再同步/归档。

正式标注 JSON 格式不变；只有必要时升级可重建索引结构。已有事务恢复清单保持可读。若回退 UI 改造，保留已验证的画布根因修复；本计划不授权自动回退任何用户标注数据。
