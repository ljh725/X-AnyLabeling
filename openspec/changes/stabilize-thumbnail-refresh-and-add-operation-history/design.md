## Context

动机见 proposal.md。静态排查已确认以下入口，实施前按相关测试复现，不把静态结论当作实测性能数据：

- `browser.py::_on_file_refresh_finished` 忽略文件路径；75 ms 定时器只合并次数，不判断影响范围。
- `_load_page` 使整个渲染代次失效，`ThumbnailItemModel.set_items` 重置模型并清空图片；改标结果和复核状态变更都会进入这条路径。
- 主画面 `set_dirty → save_labels → label_saved` 在自动保存时触发上述通知。不得通过停止索引同步修复界面闪烁。
- 既有关闭书签和启动恢复不能代替每次变更的实时阅读锚点；保留两条既有书签的原语义。
- `object_relabel` 已提供事务清单和最近一次单对象撤销；`label_batch.restore` 是检查提交后文件指纹的整文件恢复。`ReviewStore` 只覆盖保存最新状态，没有历史。

## Goals / Non-Goals

**Goals:** 对不变视图做到零卡片重建；变化视图局部更新且阅读位置可预测；把每次实际操作变成持久可检索记录，并安全撤回指定字段。

**Non-Goals:** 不增加任意字段编辑、删除或多标签混合；不记录单纯选择、悬停、预览和翻页为修改历史；不做全局 Ctrl+Z、多步骤自动重做、多人冲突合并或全量原图历史快照。不把历史浏览选择作为当前页改标候选。

## Decisions

### 1. 查询差异与渲染差异分离

新增纯 Python 差异计算单元，输入旧页、新页及当前数据集身份，输出增删、移动、元数据和图像变化。视图键为完整永久对象身份，数组下标仅参与排序。图像复用依据原图状态、bbox、显示尺寸、裁剪与叠加绘制选项；纯 label/复核文字变化不触发裁剪，绘制中实际使用的标签或属性变化则更新对应图像。

模型使用 Qt 行增删/移动和 `dataChanged` 应用差异；相同项保留 QImage 和错误/选择状态。不对普通自动更新调用整页 reset 或全局渲染 invalidate。后台回填校验对象身份和请求内容版本，移动后的行不能接收原行其他对象的结果。数据集切换、显式新查询/全量扫描可使用原有完整加载边界。

替代方案：仅加缓存或延长防抖仍清空画面；只恢复滚动条数值不能抵消对象重排，均不足以解决问题。

### 2. 文件通知合并后重新核对查询

保留文件路径，按数据集和同步批次合并通知。首版允许合并后重查当前有界页面与总数、比较新旧结果，这是正确性优先的起点；不扫描或生成全数据集缩略图。不能仅以文件是否在旧页面判断无关，因为页外对象可能进入当前标签或改变排序。后续可用变更前后标签/排序键摘要减少查询，但无需为了首版引入复杂订阅索引。

总数/标签选项只更新对应控件；当前标签归零保持该筛选的空状态，不自动跳到其他标签。新旧页相同不触碰卡片视图。针对相关文件完成同步、查询和差异应用后才解除当前操作屏障；屏障依赖数据新鲜度，不依赖全屏图片生成完成。同步失败保留现有失效状态与重试语义。

### 3. 用对象和屏幕偏移保持阅读位置

自动更新前记录当前查询、页码、可见范围首个将保留对象、该卡片顶部相对视口的像素偏移、焦点与当前页选择。若首项在本批被移除，按旧顺序选择其后的最近保留对象，再选前一保留对象；焦点对象消失采用相同承接规则但不自动勾选。

通过锚点定位查询重新计算其所在页，遵守每页最多 100 项，布局后恢复像素偏移。页边界/滚动极限无法完全保持时做最小夹紧；整页被移除且无保留对象时停在原逻辑位置最近的有效页并提示位置已调整；无结果显示空状态。显式翻页仍沿用既有规则，不能被迟到自动刷新拉回。一次更新绑定查询版本，用户滚动或切查询后不得应用旧锚点覆盖新动作。

### 4. 持久事件与当前状态分开

新增独立于缓存的版本化 SQLite 历史存储，沿用数据集隔离和 ReviewStore 持久目录策略。纯 Python 存储/查询逻辑与 Qt 面板分层。记录分为操作头与逐对象明细：操作 ID、事务 ID、来源、时间、类型、终态、父操作 ID；完整对象键、图片/JSON 路径、label/复核状态前后值、对象/文件版本、逐项结果、恢复清单引用；操作前查询、锚点和偏移用于返回位置。

从冻结操作请求开始登记；成功、部分失败、无变化和请求后的取消各有真实终态，回调重入按操作 ID 幂等。未选择目标就关闭菜单不建立修改记录。记录 label、复核状态、单对象旧撤销、历史撤回和文件恢复，普通画布修改暂不新增历史，但其后续变化参与恢复检查。

改标前后字段元数据写入可持久事务日志，历史数据库作为可检索投影；提交后历史更新失败不能谎报 JSON 写入失败或重复提交，显示“标注已保存，历史待补全”，重新打开时按事务 ID 对账。复核状态和对应历史记录共用数据库事务，迁移保留现有 marks 数据。启动中断记录按已确认的文件结果补全，无法证明的部分标记待核实，禁用对应恢复。

历史列表分页按需读取；小图按需生成并明确是当前原图预览，文件缺失保留文本记录。无需复制全量原图来实现可查找历史。旧备份没有完整逐对象信息时只显示可验证内容和文件级恢复，不推断对象级撤回资格。

### 5. 面板交互与导航

在缩略图窗口增加可停靠、可浮动的「操作历史」面板和可见入口，默认不抢焦点。列表显示时间、动作、数量、结果，展开显示逐对象前后值与失败原因；按时间、文件、原/目标标签和结果检索。

提供「定位对象」「返回处理位置」「从备份恢复文件」「撤回所选对象本次修改」。定位使用现有显式导航及未保存内容守卫；已不符合旧筛选的对象仍可在主画面定位，无法唯一匹配时只打开/提示文件，不猜测对象。返回位置恢复筛选和最近锚点，不恢复旧多选；现有两条关闭/单击书签不被历史浏览伪造。

### 6. 恢复分两阶段而且明确范围

阶段 B 复用已有准确清单恢复：显示涉及文件范围，在执行时检查数据集、备份存在性、dirty 状态和提交后文件指纹；有冲突的文件跳过，其余正常恢复。旧记录保留，新增恢复操作关联原操作，重复点击不能再次覆盖数据。

阶段 C 新增纯 Python 字段反向计划，可选择一次历史操作中一个或多个成功对象。label 从记录的 after 恢复到各自 before（可能不同原标签），只通过现有 JsonTransactionEngine 暂存与原子写盘；复核状态通过 ReviewStore 的事务修改并记录历史。单个历史操作不混合两种存储写入。

恢复前唯一匹配永久身份，验证当前被撤回字段仍等于 after，且没有已知后续同字段修改或撤回关系；同对象后续几何/其他字段变化允许保留。原图/JSON 外部变化无法判定是否发生同字段改动时采取保守冲突，不凭相同字符串推断从未被改过。预检到提交继续检查当前文件版本，防止检查后变化；身份重复按文件隔离，其余字段冲突可逐对象跳过。重复撤回根据历史关联标记为已撤回，不创建第二次有效反向操作。每次撤回生成新的备份、结果和历史，不覆盖原记录，不提供自动重做栈。

## Risks / Trade-offs

- Qt 移动行和异步回填错位 → 永久身份/内容版本校验，覆盖删除、重排和迟到结果测试。
- 页码变化影响视觉承接 → 锚点优先、边界最小夹紧；页面无保留对象时明确提示降级。
- 文件写入与历史投影无法跨存储原子提交 → 持久事务日志、幂等对账和待核实状态，禁止把未核实条目当可恢复。
- 文件级恢复可能影响同文件其他内容 → 保留整个文件的提交后指纹检查，UI 明确文件范围；日常选择性纠错由阶段 C 承担。
- 历史不断增长 → 分页和索引、预览按需生成，不自动删除用户记录。备份缺失不删除历史，只禁用依赖它的恢复动作。
- 已完成未归档变更与主规格重叠 → 以当前代码和现有规范并集核对；归档时保留缩放、复核、单页选择及两条书签要求，避免旧变更覆盖本次更严格刷新契约。

## Migration Plan

按 A（局部同步）、B（历史与备份恢复）、C（字段撤回）执行并分别验收；全部完成前不把本变更标记完成。历史 schema 和事务元数据均版本化，迁移保留旧复核状态和旧清单；历史损坏隔离报告，不删除原备份或自动修改标注。

回退应用版本时保留新增历史和备份文件；回退功能不等于恢复用户标注。验证仅使用隔离临时数据集，最终人工验收覆盖连续处理卡片的实际窗口行为。
