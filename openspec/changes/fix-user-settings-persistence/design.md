## Context

动机见 [proposal.md](proposal.md)。隔离探针已确认：保存数字映射后直接重读能够保留，但随后保存通用设置会将映射覆盖为 `null`；旧配置整份写入能够同时清空映射并还原快捷键。无法由现有日志确定用户那次普通快捷键还原的具体写入者，不能将时间先后视为密集审核直接重置的证据。

现有 `SettingsController` 在主窗口启动时复制 `_working_config`，保存时整份回写并替换 `_config`；数字管理器、显示菜单、模型管理及退出路径还会各自调用 `save_config`。后者固定写工作目录 `.xanylabelingrc`，忽略文件型 `current_config_file`，直接截断文件且吞掉异常。现有部分测试已隔离 YAML/QSettings，但缺少统一约束及子进程覆盖。

## Goals / Non-Goals

**Goals:**

- 单进程共享已提交状态，草稿提交字段差异；跨进程基于持久版本检测冲突。
- 完整文件原子提交、可定位备份和明确的失败/冲突反馈，消除无条件退出回写。
- 保持现有 YAML、数字键数据结构、显式保存、取消和预览语义，兼容全局配置调用方。

**Non-Goals:**

- 不迁移到数据库，不将 QSettings、审核进度或标注 JSON 并入此存储。
- 不自动恢复无备份的历史数字映射，不改已有快捷键含义和冲突校验规则。

## Decisions

### 1. 启动时解析持久目标，区分磁盘基线与临时覆盖

引入小型配置上下文及存储协调器，记录规范化目标路径、最近磁盘基线、文件指纹、已提交有效配置和启动覆盖层。路径只在启动上下文确定，不由保存时的 cwd 或 UI 草稿推断。

| 启动方式 | 持久目标 | 临时覆盖 |
| --- | --- | --- |
| 默认 `Python anylabeling/app.py` | 用户工作目录 `.xanylabelingrc` | 其他 CLI 参数 |
| `--work-dir D` | `D/.xanylabelingrc` | 其他 CLI 参数 |
| 文件型 `--config P` | 规范化后的 P，优先于 work-dir | 其他 CLI 参数 |
| 内联 YAML 型 `--config` | work-dir 对应 `.xanylabelingrc` | 内联字段及其他 CLI 参数 |

先读取持久目标，再合并默认值与启动覆盖。默认模板加载只读；首次默认配置创建走同一受锁保护的初始化事务，不因指定其他文件而额外创建/改写用户默认文件。内联字符串不当成可写路径；普通保存只提交 UI 实际修改字段，不将全部运行有效配置作为磁盘 payload。

备选是继续使用全局 `current_config_file` 字符串兼任路径和 YAML，但它无法可靠表达保存目标及启动覆盖来源，故采用显式上下文并保留读取兼容适配。

### 2. 一份进程内状态，多个字段草稿

所有全局配置入口共享协调器；`_config` 作为兼容的已提交有效视图，尽量原位更新并通知依赖方。数字管理器接受后作为对 `digit_shortcuts` 的显式更新提交，成功后同步 `drawing_digit_shortcuts` 和其他界面，失败不提前显示保存成功。

设置会话打开时从最新状态建立基线和工作草稿；外部更新只刷新草稿中未修改字段，保留已编辑字段的原基线以检测冲突。保存从最新有效配置合成待提交字段，不使用启动时整个副本；无修改时不写文件。关闭/取消仅丢弃本会话草稿并撤销其预览，不触碰其他入口已提交内容。

粒度采用稳定字段路径：普通设置按 schema 叶字段，快捷键按动作键，数字映射按 0～9 各条映射整体，列表型自定义模型配置按整个列表。数字键在加载时规范成现有整数键；明确清空生成删除/空值操作，不能把缺省 `null` 解释为用户要求清空。重置生成其管理范围内的显式补丁。

备选是仅在打开设置时刷新副本，仍会被设置窗口打开期间的其他入口更新击穿；因此必须同时改提交粒度与基线管理。

### 3. 跨进程比较与合并在同一锁内完成

使用现有 PyQt6 的 `QLockFile` 为规范化目标建立进程间锁，不新增依赖；锁定范围覆盖磁盘重读、合并、备份和替换。GUI 保存仅有限等待，忙时返回可重试错误，不无限阻塞；不盲删未知来源锁。

每个补丁字段比较草稿基线 B、最新已提交值 C、拟提交值 P：C 等于 B 时可提交；C 等于 P 时视为幂等；C 同时不同于 B 和 P 时整次提交拒绝并返回冲突字段。不同字段变化保留 C，不能把兄弟快捷键整个字典替换。原始磁盘映射保留未知扩展键，默认合并和 legacy 归一化不应顺带删掉未编辑字段。

同字段冲突只提供重新载入最新值、保留草稿供参考并重新编辑的流程，不提供默认覆盖按钮。重读到外部修改后，保存前再次核对指纹；非协作编辑器不能被应用锁完全约束，发现变化时拒绝提交并说明。最终检查与替换间的外部极短竞争窗口记录为文件系统限制，不承诺对不遵循锁的外部写入提供事务隔离。

只用 `os.replace` 能防止半文件但不能避免丢更新，只做无锁指纹比较也有竞争窗口；因此采用锁内三方字段比较。

### 4. 原子写入和有效备份，失败不吞没

先序列化并验证候选，在目标同目录建立临时文件，写入、flush、fsync 并关闭，再执行 `os.replace`。替换前把最近一份可解析的旧原始内容以同样的临时替换方式存为目标旁的 `.bak`；备份无法可靠生成时本次保存失败，不继续覆盖原文件。首次新建没有旧内容时允许无备份提交。

原文件损坏时拒绝自动覆盖，保留原文件与有效 `.bak`。提供错误中的路径与恢复说明；用户明确选择恢复时先独立保存损坏内容，再通过同一锁与原子流程恢复。旧 `.anylabelingrc` 迁移同样遵循目标缺失检查与原子提交，禁止覆盖已存在的新配置。

统一返回结构化结果或抛出明确的保存异常，区分写入失败、锁忙、冲突与不兼容数据。保存成功后才清除 dirty、推进基线、刷新运行状态并发成功信号。若磁盘已提交但 runtime callback 失败，应提示“已保存，当前会话应用失败”，保留磁盘成功事实并提供重新加载，不能误报原文件未变。

### 5. 迁入全部全局 writer，退出不再保存旧快照

逐一迁入 settings、数字管理器、共享视图/显示保持、矩形尺寸规则、自动标注模型管理等全局用户配置写入者；密集审核的独立 `save_config(root, ReviewConfig)` 不属于此 writer。对旧 `save_config(config)` 调用保留短期适配时必须携带可验证基线/字段补丁，缺少来源不能猜测默认模板代表用户要求全量替换。

退出仅提交明确标记的运行偏好变更，无变更不写。保存失败或冲突时设置对话框保持草稿可重试；应用退出前让用户明确重试或放弃，不把普通关闭等同于放弃失败保存。只在成功、明确取消或明确放弃后结束相应会话。

### 6. 验证使用隔离上下文及真实持久化边界

统一测试 fixture/harness 在构建窗口或服务前设置临时配置上下文及 QSettings INI 路径，生命周期结束后恢复全局上下文，即使原值为 None。截图、benchmark 和子进程都显式传入独立工作目录，不使用真实用户目录作为默认保存目的地。

回归先复现数字映射被覆盖，再验证完整窗口保存重启；双进程使用屏障安排相同基线的不同字段合并/同字段冲突。故障注入覆盖序列化、备份、写入、替换、锁忙、损坏原文件与运行时应用失败。对隔离环境之外的配置路径设置写入防护和内容哨兵，验证工具运行不改写宿主配置；不通过临时备份再还原真实用户配置来掩盖污染。

## Risks / Trade-offs

- [旧调用方仍整份写入] → 记录全部 writer，迁入后搜索复核并用交错保存回归覆盖，不只修控制器。
- [设置草稿与启动覆盖混淆] → 分开磁盘、有效配置和草稿基线，持久化只取显式修改。
- [原子替换遭 Windows 文件占用] → 同目录临时文件关闭后替换，失败保留原件和待保存状态。
- [备份包含用户偏好] → 与原配置同目录同访问范围，仅保留最近有效版本；诊断日志记录路径、字段和指纹，不输出完整敏感配置。
- [并发合并验证出新增快捷键冲突] → 合并后的有效配置再次执行原冲突检测，失败不提交。
- [配置在网络共享盘] → 仅在经验证的文件系统上声明锁/替换保证；不虚构对不支持相应语义的存储支持。

## Migration Plan

1. 在独立配置目录固化覆盖反例及路径矩阵；备份当前实现与受影响用户配置，备份实际配置需遵守执行时目录权限，不在测试中写真实配置。
2. 实现上下文、字段事务、锁、原子存储和备份，保持 YAML 格式兼容并验证旧键迁移。
3. 迁入全部全局 writer、设置草稿、数字管理器和退出流程，补齐必要四语种提示。
4. 统一测试与开发脚本隔离，执行单进程、多进程、故障及真实窗口回归。
5. 与恢复变更联测导航、亮度/对比度保持、数字映射及快捷键交错保存重启，记录实际结果并单独提交。
6. 回退只撤销本变更的源码差异，保留现有 YAML 和备份；旧程序缺少并发保护，回退前关闭多余实例，不自动拿旧备份覆盖新配置。
