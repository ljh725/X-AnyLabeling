## Why

设置控制器保留启动时的完整配置副本，数字映射另行保存后，通用设置再次保存会把映射覆盖为 `null`；旧窗口整份保存也能还原自定义快捷键。需要把配置保存改为可合并、可检测冲突且能报告失败的事务，确保用户已保存的设置在重启后保留。

## What Changes

- 通用设置只提交实际修改字段，保留数字快捷键管理器及其他入口更新的值；统一进程内配置状态和写入入口。
- 统一读取与写入目标，覆盖默认启动、`--work-dir`、文件型 `--config`；明确内联配置与命令行临时覆盖的持久化边界。
- 在进程间锁内读取最新配置并合并字段，检测同字段冲突，避免旧窗口或旧进程静默覆盖。
- 使用同目录临时文件与原子替换，保留最近一份有效备份；保存失败反馈到界面并保留待保存修改。
- 删除退出时无条件整份回写的覆盖风险；建立测试、截图和性能脚本的统一隔离规则。
- 补充真实保存/重开、多入口交错保存、双进程并发与故障注入回归。

## Capabilities

### New Capabilities

- `settings-session-consistency`: 多设置入口共享有效状态，草稿只提交修改字段，取消及重置有明确范围。
- `user-settings-persistence`: 确定的配置目标、可合并并发保存、原子落盘、失败反馈、备份与重启保持。

### Modified Capabilities

无。当前主规格没有对应的配置持久化行为契约。

## Impact

- 涉及 `anylabeling/config.py`、`app.py`、settings controller/dialog/runtime、`label_widget.py`、数字快捷键管理器，以及模型管理等全局配置写入调用方。
- 继续使用 YAML 与 PyQt6，不引入新运行时依赖；不把 Qt 窗口布局、密集审核 JSON 或标注 JSON 合并进用户配置文件。
- 检查项目内测试、截图和 benchmark 的 YAML 与 QSettings 隔离；校验过程不得写入真实用户配置或注册表设置。
- 不自动猜测已经丢失的数字映射，不把缺少写入历史的那次快捷键还原断言为密集审核直接重置。
- 与 `restore-v430-canvas-controls` 独立提交；最终联测验证新恢复的导航及亮度/对比度保持配置也能可靠保存。
- 本轮仅创建方案，不修改源码、实际用户配置或既有变更完成标记。
