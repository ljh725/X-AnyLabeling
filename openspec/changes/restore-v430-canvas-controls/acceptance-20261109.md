# 真实系统缩放验收（8.4，2026-11-09）

> 本文关闭 2026-11-05 保留未完成的 8.4。上一轮证据中的 1.5× 由 `QT_SCALE_FACTOR` 在应用内模拟，没有改变真实 Windows 系统缩放，也没有多屏 DPI 场景。本轮在 Windows 显示设置里真实切换缩放，并用 Qt `QScreen` 与 Win32 `GetDpiForWindow` 双路取证。

## 1. 环境与矩阵

- 系统：Windows，中文界面；两块屏 `Q27G2S`（2560×1440，主屏）与 `2490W1`（1920×1080，副屏）。
- 窗口：940×720 窄窗口（8.4 指定场景），隔离配置 + 合成图片，不改动用户标注与配置。
- 矩阵：**3 个真实缩放状态 × 2 块屏 × 2 个主题 = 12 组**。

| 真实状态 | 主屏 | 副屏 |
| --- | --- | --- |
| 100% | DPR 1.0，`GetDpiForWindow=96`，逻辑 2560×1440 | DPR 1.0，96，1920×1080 |
| 125% | DPR 1.25，120，逻辑 2048×1152 | 100%，96，1920×1080（真实混合 DPI） |
| 150% | DPR 1.5，144，逻辑 1707×960 | 100%，96，1920×1080（真实混合 DPI） |

缩放切换通过 Windows 设置 → 系统 → 显示 → 缩放完成；屏幕逻辑分辨率随真实缩放同步变化（2560×1440 → 2048×1152 → 1707×960），与 `QT_SCALE_FACTOR` 模拟有本质区别。

## 2. 检查项与结果（12/12 通过）

| 检查项 | 结果 |
| --- | --- |
| 面板完全在 viewport 内 / 窗口内 / 屏幕内 | 12/12 全部 True |

| 940×720 窗口是否被裁剪 | 12/12 未被裁剪，也未被 clamp（150% 主屏逻辑 1707×960 仍可容纳） |

## 3. 与旧证据的区别

旧证据以 `QT_SCALE_FACTOR=1.5` 只缩放应用自身，系统/屏幕逻辑分辨率不变，也不存在两块屏不同 DPI 的情况。本轮：

- 真实修改了 Windows 显示缩放，屏幕逻辑分辨率同步变化；
- Qt 侧的 `QScreen.devicePixelRatio()` 与 Win32 侧 `GetDpiForWindow` 数值一致（96 / 120 / 144）；
- 125%/150% 档副屏保持 100%，构成真实的**混合 DPI** 跨屏场景。

## 4. 局限与说明

- 注册表 `AppliedDPI` 在本次会话中仍为 96（Windows 只在登录时写入该值），因此不作为证据；改用实时 `GetDpiForWindow` 与 `QScreen` 指标。
- 本轮 agent 侧图像阅读工具不可用，因此客观证据为 12 张截图 + 自动几何/字体度量；人工目视由用户在 2026-11-09 对 4 张代表性截图（100%/125%/150% 深色 + 150% 浅色）确认，结论为“面板完整、无裁剪/重叠、工具栏正常”。
- 未覆盖：175%/200% 缩放、屏幕旋转、HDR、远程桌面会话、每应用 DPI 覆盖设置。

## 5. 结论

8.4 的真实系统缩放与双屏混合 DPI 验收通过，任务清单更新为 31/31。
