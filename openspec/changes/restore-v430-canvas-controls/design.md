## Goals / Non-Goals

**Goals:**

- 将可验证的本地适配实现按职责合并到当前工作区，同时保留后来增加的审核、编辑及性能改动。
- 先保全可恢复内容，再恢复功能，交付源码、测试和保存点能够互相对照。
- 为与配置修复共享的字段及文件建立明确接口和集成验收。

**Non-Goals:**

- 不把旧源码整份覆盖到当前版本，不回退分支，不清理工作区或 Git 对象。
- 不用本次恢复替代配置持久化修复，不把历史离屏通过视为当前人工或性能验收通过。

## Decisions

### 1. 实施前保全工作区和恢复对象

在项目内独立备份目录保存 HEAD、分支、状态、已暂存/未暂存二进制补丁、未跟踪源码清单及内容、文件哈希；必要数据和生成文件按清单明确处理。使用 Git bundle 保存已提交历史，并用独立目录的重建与哈希比较验证备份覆盖当前修改；标签和 bundle 不能单独承担未提交文件备份。

按二进制字节导出上表对象，避免 PowerShell 文本重定向改变编码或行尾。对其他面板、工具栏、shape、配置、测试及资源候选记录路径、blob、指纹和识别依据。先导出和校验，再进行任何恢复编辑；不得运行会回收对象或丢弃工作区的命令。

备选是直接从旧标签恢复，但旧标签已经缺少实现；直接引用孤立对象也可能被回收。因此采用独立导出与完整工作区备份。

### 2. 用三方职责对照恢复，保留当前版本为主线

对照迁移前本地基线 `57679338`、可恢复本地适配代码及实施时当前版本，按功能提取差异。固定上游 `74407f633b61a8ff6adc0e7eafbafa6856825759` 仅作缺失片段参考，不整体 cherry-pick 或替换大文件。候选缺失或指纹不符时记录差异，依据固定来源和规格重建对应片段后重新验证，不冒充原字节恢复。

保留当前 Dense Review 的统一编辑/审核历史、重做、异步代际、卡片节流、画布覆盖与 Inspector handoff；保留矩形拖边、拟合、四极值、尺寸提示、锁定、对象身份、仅选中标签及共享视图。冲突按行为契约解决，不能以旧文件较完整为理由删除当前新增方法。

### 3. 沿用原迁移交互决策并补齐已知边界

- 工具栏复用现有 QAction，恢复八类显示开关、适应窗口/宽度、成组/解组及横向溢出浏览；菜单、设置与快捷键共用状态。
- 导航沿用原 [设计](../migrate-canvas-controls-from-v430/design.md) 的明确映射：裸滚轮按模式导航，Ctrl 缩放，Alt 调笔刷或允许编辑的单个未锁定矩形，Alt+Shift 调对比分割。一次事件只执行一个行为，保留 pixel/angle 增量边界。
- 模式切换以图像坐标中心和倍率为快照，传统模式仅按边界夹紧；拖动、拟合、四极值草稿、绘制和平移期间延迟到结束/取消后应用最新请求。
- 三态审核面板复用图片顶层 `checked`、既有保存及元数据版本保护，不覆盖密集审核进度或对象审核字段。
- 透明度只作为临时填充 alpha 乘数，普通填充与掩码各应用一次；边框、文字、交互提示和原颜色数据不变。
- 三项保持与重置按钮保持独立。透明度会话内默认保持；亮度/对比度复用既有缓存及持久保持键。成功跨图才应用策略，先处理旧图节流值，避免将未触发的滑块新值丢弃；同图重载、失败与取消不提前重置。

这比重新设计 UI 或再从最新上游迁移更容易限定恢复范围，并能复用当时的专项反例。

### 4. 配置修复采用独立责任边界

恢复负责 `canvas.wheel_navigation_mode` 的默认值、校验、schema/runtime 和菜单/面板连接；亮度、对比度继续使用原有保持键，不增加第二套存储。`fix-user-settings-persistence` 负责这些修改如何合并及落盘，本变更不另造配置 writer。

建议先完成可恢复对象导出，然后实施配置修复，再合入恢复功能。允许先完成恢复的独立行为验证，但两项都完成后必须联测导航、保持按钮、数字映射及通用快捷键的交错保存与重启。

### 5. 以当前行为和独立恢复验证交付

先恢复专项测试并记录当前失败，再逐项恢复实现；历史报告只用于定位。新增/恢复的测试重点验证渲染结果、动作互通、跨图结果和保存重开，避免仅断言内部方法存在。

至少覆盖：透明度 0/50/100% 像素往返；工具栏末尾可达且滚轮不穿透；审核失败保存；模式切换与四极值草稿结束/取消；极大/极小图、同异尺寸共享视图；滑块节流间隔内切图；16 位灰度；中英日韩资源与真实中文窄窗口/系统缩放。性能采用同环境固定样本前后对比，沿用原拖框基准，缺少真实屏幕条件时如实保留待验收。

## Risks / Trade-offs

- [孤立对象被回收] → 实施首先导出并校验，源码恢复前不执行 Git 清理。
- [历史候选包含混合开发状态] → 三方职责对照，逐项保留当前工作流并建立验证矩阵。
- [大文件冲突或性能回退] → 小范围合并，沿用当前热路径与缓存，固定条件回归拖框/切图。
- [快捷键用户习惯受滚轮迁移影响] → 同步工具提示及迁移说明，明确旧 Ctrl 工具滚轮改为 Alt；鼠标单点拟合键位保持原义。
- [重复规格发布] → 本变更为恢复交付入口，原迁移保留历史来源与失效说明；未来同步/归档时同名五项规格只发布一次，本轮不归档任何变更。

## Migration Plan

1. 保存完整当前工作区、独立验证备份、导出恢复对象与指纹清单。
2. 恢复专项反例及配套模块，按五项能力分段合并并验证。
3. 接入配置修复后的保存入口，补齐资源、界面和兼容回归。
4. 新建恢复验证记录，给原迁移添加“历史通过、当前丢失、由本变更承接”的事实说明；只按新证据更新任务状态，不覆盖原复验记录。
5. 提交可审查的恢复差异，建立功能—源码—测试—提交对照；在独立目录还原提交并验证关键入口。
6. 回退时仅反向撤销本恢复变更的差异；共享文件使用按功能补丁，保留密集审核、Inspector 及配置修复；数据不做逆向转换。
