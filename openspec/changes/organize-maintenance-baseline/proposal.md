## Why

暂停功能扩展后，需要明确当前代码的维护起点、验证边界和历史变更归属。仅归档 OpenSpec 无法证明代码稳定；任务勾选、人工验收、行政关闭和代码合入必须分别记录。

## What Changes

- 顺序执行四步：固定候选代码基线 → 整理状态入口 → 建立同一提交上的验证基线 → 分批同步既有规格与归档。
- 以本变更的 tasks.md 作为唯一执行清单；其他 agent 从 HANDOFF.md 进入，按批次保存提交并记录证据。
- 修正当前状态索引、错误关联和导航链接；历史报告及机器快照保留原始含义。
- 保留暂停、停止、待验证和已验证的区别；不以清空活跃列表为完成目标。

## Capabilities

### New Capabilities

无。本项是仓库管理、文档整理和验证协调，不新增产品能力；使用 `skip_specs: true`，不创建占位规格。

### Modified Capabilities

本交接方案不改产品需求。实施阶段对既有变更的规格同步仍遵守各自契约及归档流程，不能沿用本变更的 skip_specs 跳过它们。
