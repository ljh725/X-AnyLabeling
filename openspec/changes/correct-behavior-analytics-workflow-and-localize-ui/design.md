## Context

参见 [proposal.md](proposal.md) 的动机。现有代码已经具备版本化事件、`ActionSpan`、`ActivityTracker`、对象 episode、后台导出和 Qt 对话框等基础设施，但实际导出表明这些部件尚未形成闭环：程序化标签列表更新进入用户动作流；episode 内只保留最后一个已归属事件而非真实关闭边界；时间分解忽略 `started_monotonic_ms`；焦点/空闲跟踪器存在但运行期事件覆盖不足；对话框文案大多为未经过翻译 API 的英文常量。

本设计必须保持记录默认关闭、仅本地运行、不写回标注数据、旧日志只读兼容，以及 `label_widget.py` 大文件的窄范围批量编辑约束。

## Goals / Non-Goals

**Goals:**

- 让用户意图、程序化 UI 更新和批量选择在记录层可区分。
- 让对象周期关闭事实成为统计的唯一边界来源，可靠支持“选中对象到下一对象或翻页”的耗时分析。
- 让动作段、焦点和空闲区间使用统一半开区间运算并通过守恒检查。
- 将质量门从单一布尔值扩展为按指标依赖分级，同时保留汇总状态。
- 让简体中文用户看到完整中文行为分析工作流，并继续支持 Qt 多语言资源。
- 将分析包恢复为紧凑、可校验且不重复内嵌全量动作的数据产品。

**Non-Goals:**

- 不根据本次日志直接修改顶点热区、拖动阈值或标注业务交互。
- 不上传日志、不调用外部模型、不记录图片内容、原始 points、用户名、自由文本或绝对路径。
- 不删除或重写历史 v1/v2/v3 日志；不承诺用缺失边界恢复历史精确 focused/active 时间。
- 不把中性剩余时间解释为低效、浪费或记录丢失。

## Decisions

### 1. 使用新版事件契约承载纠正后的语义

将事件 envelope 升级为 v4，并继续读取 v1-v3。v4 保留现有 `started_monotonic_ms`、`ended_monotonic_ms`、`object_episode_id`、`correlation_id` 和 `context_version`，新增或规范化选择来源、选择批次、未归属原因及显式 `object_episode_ended` 事实。事件的 `monotonic_ms` 仅用于全局排序；动作区间始终由 started/ended 字段构造。

选择升级版本而不是静默修正 v3，是因为 v3 数据已经包含系统性语义错误，跨升级比较必须能识别测量断点。备选方案是保持 v3 并只升级算法版本，但这会让同一 schema 下的相同字段具有两种含义，难以诚实降级。

### 2. Telemetry 状态机是 episode 身份和关闭事实的唯一来源

UI 只向 telemetry 报告经过归一化的用户意图及生命周期边界。`SessionTracker` 负责幂等开始/结束 episode，并在结束时发射包含开始、结束、原因、对象和图片身份的关闭事实。分析器优先消费关闭事实，不再通过“episode 内最后一个事件”猜测结束时间；历史 v1-v3 才使用回放推断并标记低可信。

程序化标签更新使用最小作用域 guard 或信号阻断，用户点击入口单独调用 telemetry。选择回调携带 `selection_source` 和 `selection_batch_id`，批量同步只产生一个可审计选择事实。备选方案是在分析阶段过滤高频事件，但它无法可靠区分真实快速操作，也会继续浪费存储和污染实时健康计数。

### 3. 动作、焦点和空闲统一使用区间代数

动作段使用 `[started_monotonic_ms, ended_monotonic_ms)`；episode 使用 `[selected_at, boundary_at)`。重叠动作先做并集，再与 focused/active 区间求交。`ActivityTracker` 继续作为焦点和空闲状态机，通过窗口激活事件和低频观察定时器接入运行期；任何缺失边界只降低对应时间层可信度，不回退为 `active = wall`。

该方案复用现有区间工具和活动跟踪器。备选方案是按相邻事件时间差估算活跃时间，但隔夜挂机和长时间阅读会被错误纳入，无法满足可审计要求。

### 4. 质量状态按指标依赖形成矩阵

保留汇总 `quality_gate` 供兼容消费者使用，同时新增按指标的 `available/pass/degraded/fail` 状态、覆盖率、分母和结构化原因。对象周期依赖选择与关闭边界；动作耗时依赖 started/ended；focused/active 依赖焦点/空闲；功能比较依赖上下文和两组有效样本。UI 和导出均展示这些独立状态。

备选方案是继续使用单一总门禁，但 `context_coverage=0` 会错误遮蔽仍然完整的几何耗时，无法指导用户判断哪些结论可用。

### 5. 汇总文件只保存汇总，明细通过受限表输出

`summary.json` 保留版本、质量、核心聚合、表级索引和省略诊断，不再内嵌 `action_spans`、`semantic_actions` 与重复维度副本。CSV/JSONL 明细继续受行数和字节上限约束，manifest 记录哈希、总行数、导出行数和 `other` 汇总。需要重建代表性轨迹时使用已有两遍扫描机制。

备选方案是只提高 bundle 字节上限，但这会保留118 MB级重复数据并使外部分析更易误用多个近似事实源。

### 6. 中文界面使用英文源字符串加 Qt 翻译映射

行为分析对话框、菜单及 `label_widget.py` 中相关进度/错误文案全部通过 `self.tr()` 或 `QCoreApplication.translate()`。简体中文翻译进入 `zh_CN.ts`，随后运行 `scripts/compile_languages.py` 生成 `.qm` 和资源模块；不手工编辑生成文件。动态原因使用稳定代码到翻译模板的映射，内部异常仅作为日志详情，不直接替代用户提示。

选择标准 Qt 翻译链而不是硬编码中文，可保持英文、日文、韩文环境兼容。中文验收以加载 `zh_CN.qm` 后的实际控件文本为准。

### 7. 用故障模式回归而非仅验证理想路径

纯 Python 测试覆盖事件风暴、动作区间、同毫秒顺序、边界关闭、焦点/空闲和混合版本；PyQt offscreen 测试覆盖程序刷新 guard 与中文 UI；bundle 测试断言汇总不含全量重复副本并验证哈希。日志分析中的基线数据只作为固定夹具或合成等价样例，不把用户本地日志提交到仓库。

## Risks / Trade-offs

- [程序化更新 guard 范围过大，吞掉真实用户事件] → guard 只覆盖列表重建和状态同步，并对真实点击入口做正向测试。
- [v4 与历史数据形成统计断点] → 输出版本分布和算法版本，跨版本比较默认标记为观察性或不可比较。
- [显式关闭事件增加少量写入] → 每个对象周期只增加一个低频事实，换取可审计边界并显著减少 attribute 风暴，总体写入量下降。
- [空闲观察定时器带来运行期开销] → 使用低频 Qt 定时器，只读取单调时钟且不扫描对象或图片。
- [中文动态文案过长导致布局变化] → 保留自动换行和可伸缩布局，并在 offscreen 测试中检查按钮可见性。
- [旧 v3 无法恢复精确结束或 focused/active] → 保留原始事实、输出低可信状态，不用启发式结果冒充精确值。

## Migration Plan

1. 先扩展读取器、schema 校验和版本常量，使 v1-v4 可并存读取；旧写入路径仍可回滚。
2. 实现 v4 记录状态机、程序化更新 guard、显式 episode 关闭和焦点/空闲接线，并以配置开关保持记录默认关闭。
3. 切换统计器到显式边界和真实动作区间，更新质量状态与导出版本；使用合成 v3/v4 混合夹具验证降级。
4. 精简 bundle 并验证行数、字节、哈希和取消语义。
5. 完成中文翻译、编译资源和离屏 UI 验收后一起发布。
6. 发布后重新采集一段小样本，确认程序化 `attribute_edit` 消失、episode 正常闭合、动作守恒和 focused/active 覆盖率。

回滚时关闭 v4 写入并恢复旧统计入口；已经写入的 v4 分片保持只读，不删除、不降写为旧版本。中文资源可独立回滚而不影响事件数据。
