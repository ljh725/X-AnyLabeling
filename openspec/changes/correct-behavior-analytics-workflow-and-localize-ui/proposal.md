## Why

2026-08-25 的实际导出日志显示，行为分析虽然能够保留几何调整等有效信号，但程序化 `attribute_edit` 事件风暴、对象 episode 结束时间失真、动作区间起点错误、同毫秒重复选择以及缺失焦点/空闲边界，使动作次数、对象周期和活跃时间无法使用同一可信口径。与此同时，行为分析对话框仍以英文为主，不符合当前中文标注工作流，增加了配置、导出和质量诊断的理解成本。

## What Changes

- 阻止列表重建、可见性刷新等程序化 UI 更新被记录为用户 `attribute_edit`；真实属性修改必须携带对象身份、字段类别和安全的变化摘要。
- 建立显式的对象工作流周期：从用户选中对象开始，以选择下一个对象、翻页、删除当前对象、关闭项目或取消选择为结束，并记录真实结束时间、结束原因和选择来源。
- 区分用户单选、程序化选择和批量/多选同步，避免同一毫秒内的程序化选择生成多个伪 0 ms 工作流。
- 统一动作段的开始、结束和提交时间语义，修复时间分解使用提交时间作为区间起点的问题；将保存、缩放、平移和翻页关联到当前对象 episode 或明确标记为未归属。
- 记录窗口聚焦、失焦、空闲和恢复边界，使 wall、focused、active 和明确动作耗时保持可区分、可守恒的统计口径。
- 调整质量诊断，使各指标按自身依赖字段判定可信度；上下文缺失不得掩盖仍然有效的动作耗时和工作流边界统计。
- 精简分析包，避免在 `summary.json` 中重复内嵌大规模动作副本，并保留旧版 v1/v2/v3 事件的只读兼容与明确降级说明。
- 将行为分析功能的菜单、对话框、范围选择、进度、质量状态、错误提示、导出结果和清理确认等用户可见英文文案改为中文；所有文案通过 Qt 翻译机制维护，不直接修改生成的资源文件。
- 增加基于已发现故障模式的回归测试，并以“对象选中到下一对象或翻页”的周期分位数作为验收样例。

## Capabilities

### New Capabilities

- `behavior-event-integrity`: 约束真实用户事件、程序化 UI 更新、动作身份、对象归属、上下文和版本兼容，消除事件风暴与错误归属。
- `object-workflow-cycle-timing`: 定义对象周期边界、wall/focused/active/动作区间、时间守恒、异常停顿和可信度输出。
- `behavior-analytics-chinese-ui`: 规定行为分析功能全部用户可见界面的中文化、Qt 翻译资源和回归验收要求。

### Modified Capabilities

无。当前 `openspec/specs/` 中没有已归档的行为分析主规格；本变更以新的纠错能力规格承接现有实现，不修改 Inspector 现有主规格。

## Impact

- 记录入口：`label_widget.py`、`label_list_widget.py` 及对象选择、保存、缩放、平移、翻页和窗口生命周期信号。
- 行为分析服务：事件模型、recorder、session/replay、metrics、`statistics_v3.py`、质量门、bundle 导出和兼容读取器。
- UI 与国际化：行为分析对话框/后台导出提示、`QCoreApplication.translate` 调用、`.ts` 翻译文件、重新生成的 `.qm` 与 `resources.py`。
- 测试：程序化刷新不记录、对象边界、同毫秒选择、动作区间守恒、焦点/空闲、旧版本兼容、紧凑导出和 PyQt offscreen 中文 UI 测试。
- 不修改标注 JSON、图片、`group_id` 或 shape 几何数据；记录继续默认关闭并仅在本地运行。
