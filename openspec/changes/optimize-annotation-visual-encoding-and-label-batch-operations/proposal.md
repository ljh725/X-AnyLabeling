## Why

当前标注颜色在浅色或复杂图像上对比度不足，并在存在多个
`group_id` 时同时展示大量高饱和颜色，显著增加三框审核的视觉
判断复杂度。与此同时，标签管理器把颜色/可见性等视觉元数据修改
与标签重命名/删除等数据集迁移绑定，甚至仅改颜色也会在 GUI 主
线程逐个重写 JSON，造成界面卡死和部分写入风险。

## What Changes

- 新增统一的标注外观策略，支持 `focus`、`label`、`group`、
  `instance`、`uniform` 五种颜色模式，并分别配置普通/选中填充
  透明度、高对比外描边、标签文字与 GID 徽标。
- 将颜色选择、交互状态、质检提示和矩形边精修反馈分配到不同视觉
  通道，明确绘制优先级，避免多个语义竞争同一种颜色。
- **BREAKING（默认视觉行为）**：带 `group_id` 的对象不再永久强制
  按组全场着色；默认使用聚焦模式，仅突出当前组并弱化无关对象。
  用户仍可显式切换到 Group 总览模式。
- 新增 group 聚焦生命周期：单框选择建立焦点、同组对象同步突出、
  无关对象变暗，并在切图、清空选择、删除对象、虚拟复核目标变化
  和模式切换时按确定规则更新或退出。
- 重构标签管理器为“视觉元数据操作”和“标注数据迁移”两条事务
  路径：颜色/可见性修改不得读取或写回标注 JSON；重命名/删除在
  可取消的后台任务中执行，并提供进度、原子写入、错误汇总和恢复
  信息。
- 使用数据集索引或等价候选筛选，仅处理真正包含目标标签的 JSON；
  未发生内容变化的文件不得重写。
- 将标注外观持久化到用户/项目视觉配置，保持正式标注 JSON、undo、
  dirty 和质检报告格式不变，并兼容迁移现有颜色配置。

## Capabilities

### New Capabilities

- `annotation-appearance`: 定义颜色模式、高对比矩形绘制、透明度、
  标签/GID 显示、状态优先级及视觉配置持久化契约。
- `group-focus-visualization`: 定义当前组聚焦、同组突出、无关对象
  弱化、总览切换和跨选择/切图/复核场景的生命周期。
- `safe-label-batch-editing`: 定义视觉元数据即时修改与标签重命名/
  删除后台迁移的分流、进度取消、候选筛选、原子写入和失败恢复。

### Modified Capabilities

无。现有主规格只覆盖 Inspector 规则与导出可靠性，本变更不修改其
行为要求。

## Impact

- 标注绘制：`shape.py`、`widgets/canvas.py`，以及建议新增的纯 Python
  外观策略/绘制上下文模块。
- 标注主控：`label_widget.py` 的颜色解析、选择/切图状态、设置应用与
  单次批量刷新路径。
- 标签管理器：`widgets/label_dialog.py` 的草稿事务、后台迁移 worker、
  进度/取消/错误反馈与完成后 UI 提交。
- 配置：`xanylabeling_config.yaml`、settings schema/runtime applier、
  用户配置迁移及项目级视觉元数据存储。
- 数据集索引：复用只读标签查询以缩小批量迁移候选文件集合；JSON
  仍是唯一真实标注数据源。
- 测试：新增纯策略、配置迁移、Qt offscreen 绘制/聚焦、后台批量
  修改、原子写入、取消和失败恢复测试；不引入新的运行时依赖。
