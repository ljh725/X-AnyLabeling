## Context

参见 `proposal.md`。当前 `LabelingWidget` 持有主 `Canvas`、标签列表、文件加载/保存和撤销入口；`Canvas` 自行维护 `shapes`、选择列表与形状备份，并把选择视觉状态写入 `Shape.selected`。现有 `shape_changed`、`shapes_changed`、`shape_edit_started` 和 `shape_edit_finished` 信号可作为增量同步边界，但直接让两个 Canvas 共享相同 `Shape` 引用会让选择状态和撤销快照互相覆盖。

当前主画布已经通过 `main_visible()` / `is_shape_interactive()` 统一门控绘制与命中，且支持独立可见性谓词。用户配置由 YAML 默认值与 `QSettings` 运行时状态共同承载；主窗口已有单一文件保存和图片导航流程，必须继续作为唯一持久化入口。

## Goals / Non-Goals

**Goals:**

- 将空间分轮实现为可脱离 Qt 测试的确定性纯 Python 模型。
- 在不复制主窗口业务面板的前提下提供第二个完整矩形编辑画布。
- 保持主文档、文件保存和全局撤销的单一权威来源。
- 让所有巡检可见性与窗口状态均为可撤销、不可写入标注 JSON 的瞬态状态。
- 把对高成本文件 `label_widget.py` 和 `canvas.py` 的改动压缩为少量适配点。

**Non-Goals:**

- 不增加模型推理、错误候选生成、IoU/交叉率拆轮或已完成图片数据库。
- 不把轮次、边界、窗口选择或编辑锁写入 shape、JSON 或 Dataset 索引。
- 不在第二窗口复制自动标注、Inspector、视频、转换器或主工具栏。
- 不扩展非矩形编辑投影。

## Decisions

### 1. 纯 Python 分轮模型持有冻结会话

新增独立模块定义不可变的 `RoundPartition` 和有界状态机 `RoundReviewSession`。输入为图片尺寸、矩形稳定身份、原始顺序和中心点；输出为有序轮次、shape ID 到轮次的映射、冻结边界和当前/待生效上限。

轮次数为 `ceil(N / limit)`，使用商和余数生成差值不超过 1 的连续分组。排序主轴由图片宽高比决定，最终以原始顺序或稳定 shape ID 决胜。分区只在图片进入会话时创建；编辑期间只允许显式新增/删除成员，不执行再平衡。相比在 Canvas paint 中临时截取前 N 个对象，该模型能保证导航、直接跳转和测试结果一致。

### 2. 主文档权威，第二 Canvas 使用 ID 映射的编辑投影

主 `LabelingWidget.canvas.shapes` 继续作为当前图片的权威内存文档。第二窗口为当前图片建立仅含普通矩形的 `Shape.copy()` 投影，并以 `xanylabeling_shape_id` 映射回主对象。这样两个 Canvas 可以保留独立的 `selected_shapes`、hover、缩放和临时编辑状态，而不会争用共享的 `Shape.selected` 标志。

`RoundReviewCoordinator` 负责双向同步：

- 主对象增量改变时，把几何与元数据复制到对应投影并重绘第二画布。
- 第二画布编辑开始时，在主 Canvas 建立全局撤销基线并取得对象锁；编辑中的增量变化复制到主对象并触发主画布重绘；结束时由主 Canvas 写入一次完成快照、标脏并释放锁。
- 成员新增、删除、复制和改类别统一调用 `LabelingWidget` 的现有业务入口，再重建受影响投影，避免第二窗口复制标签列表、颜色、保存和遥测逻辑。
- 撤销/重做动作始终委托主窗口；主撤销完成后按持久 shape ID 重建投影与轮次成员引用。

直接共享 `Shape` 引用的方案被否决，因为现有 Canvas 会写 `Shape.selected`，也会独立复制整表撤销快照。建立第二套独立标注文档的方案也被否决，因为会产生保存覆盖和冲突合并问题。

### 3. 用协调器实现对象级事务锁

协调器维护 `shape_id -> owner_canvas` 的瞬态锁表。鼠标拖动、边调整、标签对话框和删除事务开始前申请锁；另一窗口的命中候选和编辑入口查询锁表，拒绝非所有者编辑。选择和只读绘制不需要锁。完成、取消、窗口关闭和图片切换均通过统一清理路径释放锁。

Qt GUI 线程本身会串行处理事件，但显式锁仍用于覆盖“一个窗口保持标签对话框打开、另一个窗口继续操作”的可重入情况，并让行为可测试。

### 4. 可见性采用独立巡检覆盖层，不修改 shape 可见字段

为 Canvas 增加可选、瞬态的巡检可见/交互覆盖策略。主画布在巡检期间绕过类别过滤、对象列表隐藏及冲突隔离层，以绘制全量对象；第二画布仅允许当前轮次投影通过。按住 `V` 只放宽第二画布的绘制门控，不放宽交互门控。

`RoundReviewCoordinator` 在进入模式时拍摄现有筛选、隐藏和隔离状态，暂停冲突动作并在退出时原样恢复。该状态不进入 `Shape.other_data`、保存序列化或撤销历史。相比批量写 `shape.visible=True`，独立覆盖层不会污染文档，也不会丢失用户原状态。

### 5. 选择是窗口本地状态，通过持久 ID 非对称同步

第二画布正式选择后，协调器立即把对应主对象选入主 Canvas，并清除主窗口待同步状态。主画布的普通选择只记录为 pending，不驱动第二窗口；`Ctrl+J` 校验所选矩形均属于同一冻结轮次后才切换第二窗口并映射选择。跨轮多选返回可见错误，不做部分同步。

轮次切换清空第二画布选择并通过同步路径清空主高亮。由于两个 Canvas 不共享 `Shape` 实例，pending 与第二画布选择能够短暂并存而不会破坏视觉标志。

### 6. 第二窗口是轻量顶层窗口

新增非模态顶层 `DensityRoundReviewWindow`，仅包含 `QScrollArea + ReviewCanvas` 和精简巡检栏。巡检栏持有文件名、上次关闭文件提示、上一轮/下一轮、可选择进度、当前/待生效上限以及矩形编辑动作。标签编辑复用主 `LabelDialog`，所有外部动作通过协调器委托主窗口。

窗口几何与屏幕信息写入 `QSettings`；启用状态永不跨启动恢复。关闭窗口等价于退出巡检并记录当前图片 basename。显示器不可用时使用 Qt 屏幕几何校验回退到主窗口屏幕。

### 7. 图片和视口生命周期保持单向权威

主窗口加载图片成功后通知协调器共享 pixmap、重建投影和第 1 轮；两个窗口不得各自加载不同文件。第二窗口换轮只改变绘制/交互成员，不改变滚动条或缩放；换图后执行适应窗口。跨图导航委托主窗口现有 `may_continue` / 自动保存流程，失败或取消时不推进轮次状态。

快捷键进入现有配置体系，默认 `F10`、`[`、`]`、`Ctrl+J` 和按住 `V`。焦点位于输入控件、标签对话框活动或编辑事务未结束时，协调器拒绝导航动作。

### 8. 配置与国际化遵循现有机制

YAML 增加默认每轮上限和快捷键键名；设置 schema/runtime applier 只暴露适合运行时更新的快捷键。当前应用值属于图片会话，待生效值属于窗口控件并在首次加载不同图片时提交为默认。

所有新增用户可见字符串通过 Qt 翻译 API 包装，更新 `.ts` 后使用仓库脚本重新生成 `.qm` 和 `resources.py`，不直接编辑生成资源文件。

### 9. 第二窗口显示镜像与数字重命名复用主窗口能力

协调器增加单向的显示状态同步：主 Canvas 仍是显示配置的权威来源，第二 Canvas 同步标签、文字、分数、属性、关系、矩形尺寸提示、类别颜色和外观设置。掩码是唯一强制例外，第二 Canvas 在创建、换图及主窗口显示参数变化后都把 `show_masks` 固定为 `False`。这不会改写主窗口的掩码开关。

第二窗口为 `0`-`9` 安装窗口本地快捷键，并继续使用输入控件焦点保护。快捷键只在第二画布已有选择时转交 `DigitRenameManager.trigger_rename()`；由于第二选择已映射为主 Canvas 选择，现有标签校验、标签列表、颜色、历史标签和状态提示逻辑可直接复用。成功改名后协调器补写完成态快照、刷新投影并接入共享重做栈，不建立第二套数字映射。

## Risks / Trade-offs

- [投影同步遗漏某条编辑路径] → 将第二窗口能力限制为明确的矩形操作集合，并为移动、缩放、创建、复制、删除、改类别、撤销逐项编写双窗一致性测试。
- [主 Canvas 现有撤销以整表副本替换 Shape 引用] → 每次撤销、图片加载和成员变化后均以持久 shape ID 重建第二投影，禁止缓存主 Shape 对象地址。
- [大量现有未提交改动与集成点重叠] → 以预实现 Git 快照为回退点，新增模块优先，`label_widget.py` / `canvas.py` 仅做小型适配，并运行窄范围回归测试。
- [临时全量预览误操作隐藏对象] → 绘制谓词与交互谓词分离，`V` 只改变绘制。
- [窗口在显示器布局变化后落到不可见区域] → 恢复前校验可用屏幕交集，无交集时回退到主窗口屏幕。
- [标签密集但每轮仍互相重叠] → 第一版保持数量上限可预测，用户可调低上限；不以不可解释的重叠阈值改变轮次数。

## Migration Plan

1. 以默认关闭的新增动作发布，不改变普通标注路径。
2. 首次启用时从当前主文档建立瞬态会话，不迁移 JSON 或用户数据。
3. 若需要回滚，关闭/移除巡检入口和新增模块即可；新增 YAML 键由现有配置合并机制安全忽略。
