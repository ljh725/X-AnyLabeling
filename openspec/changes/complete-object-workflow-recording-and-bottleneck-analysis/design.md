## Context

参见 [proposal.md](proposal.md) 的动机。当前几何鼠标拖动已通过 Canvas 开始/结束信号接入 ActionSpan，但矩形滚轮编辑等分支直接修改对象后返回，创建和标签编辑只在完成时发射零时长动作，zoom burst 仅保存次数和单调时间。分析层可以生成动作和 episode 聚合，却从 summary 排除完整语义动作，仅输出少量代表轨迹；`object_episodes.csv` 使用不含动作序列的 episode 行，序列耗时和 idle/focus 区间还存在口径错误。

现有行为记录必须继续默认关闭、非阻塞、匿名、隐私最小化并兼容旧 schema。`label_widget.py` 和 `canvas.py` 体积很大，实施时必须通过小窗口定位并批量修改，避免无关重构。

## Goals / Non-Goals

**Goals:**

- 让动作目录成为“已支持行为”的唯一覆盖合同，并以回放证明每个入口一次用户意图只产生一个终态事件。
- 复用 Canvas 已有命中和编辑状态，不在记录或分析层根据几何坐标猜测动作目标。
- 为编辑与创建建立可关联但边界不同的对象工作流。
- 生成全部对象的压缩时间线、逐对象摘要和可守恒的项目瓶颈事实。
- 使所有耗时结论具有明确样本量、覆盖率、版本和排除原因。

**Non-Goals:**

- 不记录逐次鼠标移动、原始滚轮采样、图片内容或完整几何快照。
- 不使用操作系统级全局输入监控，也不通过截图或模型识别用户动作。
- 不在本变更中增加仪表盘、数据库、云端上传或应用内大模型。
- 不把无输入间隔自动解释为视觉辨识、犹豫或效率损失。
- 不为旧日志补造不存在的创建起点、缩放比例或标签编辑时长。

## Decisions

### 1. 以动作目录驱动入口覆盖和测试

扩展现有 `action_catalog.py`，使每个条目同时声明形状适用性、用户入口、动作模式（span、instant 或 burst）、必需目标、必需上下文、允许终态和回放 ID。测试从目录参数化生成最低覆盖断言，目录条目没有接入或入口没有目录条目都视为失败。

选择此方案是因为单纯搜索 `_behavior_action` 只能证明存在调用，不能证明所有分支、形状和终态均被覆盖。备选方案是全局监听 Qt 输入，但它无法可靠获得对象身份、净变化和业务结果，因此不采用。

### 2. Canvas 只发布已判定的语义事实

Canvas 继续负责命中测试和几何修改，在已有 `shape_edit_started/finished` 基础上统一发布结构化动作通知：动作名、shape 引用、edit_target、input_source、起始摘要和提交摘要。LabelingWidget 作为适配层获取匿名对象身份、安全上下文并调用 telemetry；Canvas 不直接写日志。

普通拖动采用 press/release span；点击提交采用 instant；滚轮、方向键和连续平移采用 burst。任何直接修改后 return 的分支必须在同一分支提交语义通知。

### 3. 对动作目标采用稳定低基数枚举

通用目标使用 `move`、`vertex`、`edge`、`label`、`attribute`。矩形在画布已经知道时细化为 `left`、`right`、`top`、`bottom` 和稳定角枚举；其他形状不保存原始顶点编号或坐标。这样足以区分操作类别且不扩大隐私面。

### 4. 创建使用临时 workflow token 跨越对象身份生成点

已有对象编辑以真实用户选择创建 object episode。创建流程在 R、数字快捷键、复制粘贴、AI 或导入入口生成 `creation_workflow_id`；绘制和标签阶段先关联该 token，对象提交并获得 shape ID 后，由协调器将 token、创建事件和后续编辑绑定到一个对象工作流。

创建方式使用稳定枚举。R 路径记录 intent、draw、label；数字预置路径记录 intent、draw，不虚构 label span。取消时关闭临时流程且不创建对象成功事实。

备选方案是仍从 `shape_created` 开始，但它无法测量绘制和标签输入时间，不能满足瓶颈目标，因此不采用。

### 5. 标签编辑采用编辑会话而不是 textChanged 计数

标签输入在 focus-in、对话框打开或编辑命令开始时创建 span，在 editingFinished、确认、取消或对象/图片切换时结束。中间字符变化只更新内存摘要，不写事件。属性点击继续使用提交时 instant 动作，但必须具有真实用户 guard 和净变化判断。

### 6. burst 保存业务起止摘要

扩展 burst 聚合器，使调用者可提供安全的 start/end summary。zoom 保存开始/结束百分比；矩形滚轮保存目标、输入数及净变化；pan 保存方向类别而非原始位置。burst 在静默、对象切换、切图、失焦、关闭和模式冲突时 flush，且绑定 burst 开始时的图片和对象身份，避免 flush 时错误归到新对象。

### 7. 时间线构建器先产出逐轮事实再做聚合

新增纯 Python 时间线构建步骤，按 `(app_session_id, sequence_no, monotonic_ms, event_id)` 排序事件，使用显式工作流边界生成每轮记录。每条记录保存有序动作、相对起止时间、阶段、间隔、时间层和完整性，不复制图片或自由文本。

所有后续对象摘要、序列和项目瓶颈必须以该统一时间线为输入，避免不同统计函数各自重建边界并产生不同口径。代表轨迹从时间线选择，但不作为全量指标输入。

### 8. 用状态机配对 focus/idle 并用区间代数分解时间

focus 和 idle 使用显式状态机形成闭合区间，false 恢复事件关闭对应等待，而不是从 true 一直延伸到 episode 结束。动作区间先裁剪到工作流边界并求并集；系统等待与动作相减；剩余 active 区间按以下确定顺序分类：

1. 工作流开始到首个明确动作：`pre_action_gap`；
2. 相邻动作之间且不超过版本阈值：`inter_action_gap`；
3. 其余：`unattributed`。

图片加载到首次输入和轮次之间的间隔作为图片级 `image_to_first_operation` / `target_search_gap` 输出，不重复计入多个对象。每轮和项目都执行时间守恒断言；重叠动作在动作级仍保留，在时间贡献分母中只计算区间并集一次。

### 9. 固定新增三份全量导出契约

- `object_workflow_timeline.jsonl`：每个有效轮次一行，动作数组有界于该轮实际语义动作；超长轮次不静默截断，改为分片行或明确 `truncated` 与外部明细引用。
- `object_workflow_summary.csv`：每轮固定列的阶段和质量摘要。
- `project_bottlenecks.csv`：按阶段和动作的项目贡献、对象分位数、返工和覆盖率。

现有文件继续保留一个兼容周期，但 `object_episodes.csv` 必须补齐动作构成或明确指向新时间线。manifest 独立记录全量表行限、字节数、截断数和哈希；代表轨迹的 24 条默认上限只约束样本文件。

### 10. 瓶颈排名由确定性非重叠时间贡献产生

排名主键依次为 `total_ms` 降序、`object_coverage` 降序、稳定阶段/动作名升序。输出 total、share、cumulative share、count、object coverage、median/P75/P90/P95、rework time、duration coverage 和版本。程序不生成“功能导致慢”之类因果标签。

序列耗时按每个 n-gram 的首动作开始到末动作结束，并在规则允许时扣除系统等待；不再为每个窗口累加整轮动作总和。

### 11. 版本断点和兼容采用能力级降级

升级事件 schema、分析算法、阶段映射、序列规则和 bundle schema。读取器继续接受旧版本；每项输出根据自身依赖字段判断可用性。旧记录可以参与动作次数或兼容序列，但缺创建起点、scale 或真实 action span 时不得进入相应精确耗时。

## Risks / Trade-offs

- [Canvas 入口多，仍可能漏接] → 动作目录同时声明入口和回放，增加目录到信号、信号到终态的双向覆盖测试。
- [同一动作被通用和专用路径重复记录] → 每次交互使用唯一 action ID，并禁止旧 `shape_edited` 进入新版精确统计。
- [创建提交前没有 shape ID] → 使用临时 creation workflow token，只有提交后关联对象；取消流程保持独立事实。
- [全量时间线增大分析包] → 一轮一行、仅保存语义动作、使用低基数字段和压缩 JSONL；在 manifest 明示大小与任何分片，不以静默抽样替代全量事实。
- [标签编辑边界受多个 UI 入口影响] → 统一编辑会话适配器并在确认、取消、对象/图片切换和关闭时幂等终止。
- [多选对象导致时间重复归属] → 当前主对象轮次仍只选择一个主体；批量动作单独记录参与对象集合摘要，不把同一 active 区间重复计入项目贡献。
- [旧日志与新版结果不可直接比较] → 提升版本并在对比表按能力覆盖率分组，默认禁止跨版本精确基线直接比较。

## Migration Plan

1. 先增加新版 schema、目录字段和兼容读取，不改变现有发射路径。
2. 接入 Canvas、创建、标签、zoom/pan 和生命周期入口，以受控回放验证一次性和归属。
3. 启用新版时间线构建器和三份新增导出，同时保留旧表兼容输出。
4. 使用合成回放及匿名实测日志验证时间守恒、覆盖率、文件大小和旧日志降级。
5. 提升默认分析和 bundle 版本；若发现回归，可关闭新版发射和输出而不删除旧日志或影响标注数据。
