## Why

当前本地行为分析只接入了 Canvas 的部分语义动作，并在导出阶段将多数逐对象事件压缩为全局聚合和少量代表轨迹，因此无法准确还原“进入图片、选择或创建对象、缩放、修改、保存或离开”的完整时间链，也无法可靠判断项目中真正最耗时的操作阶段。需要先补齐可审计的动作事实，再由本地确定性分析生成对象级时间线和项目瓶颈事实，避免外部大模型从缺失数据中猜测。

## What Changes

- 建立 Canvas 用户语义动作的完整覆盖契约，要求所有会改变对象几何、标签、属性或视图上下文的有效入口都向行为记录模块提交一次可计数动作，不记录原始鼠标移动采样。
- 为已有对象编辑和新对象创建建立不同的工作流入口：已有对象以用户真实选择开始；新对象以 `R`、数字快捷键、复制粘贴、AI 或导入等创建意图开始。
- 补齐鼠标整体移动、顶点/边调整、矩形滚轮缩放与调边、键盘微调、标签提交、属性提交、缩放和平移等动作的开始、结束、目标、结果和安全上下文。
- 为缩放记录起止比例、输入次数、对象选择状态和对象尺寸分桶；为创建记录 `r_then_label`、`digit_prefill` 等创建方式及绘制、标签输入阶段。
- 新增全部对象轮次的压缩有序时间线、逐对象工作流摘要和项目瓶颈事实表；代表轨迹继续作为补充样本，不再承担全量工作流证据职责。
- 使用不重叠区间确定性分解对象和项目 active 时间，区分明确动作、操作前间隔、动作间隔、系统等待和未归属时间，并修正现有序列耗时、空闲恢复和对象动作列表缺失问题。
- 升级事件、统计和分析包版本，继续只读兼容旧日志；旧版本缺失的动作或上下文必须显式标记为不可用，不补造精确时间。
- 保持默认关闭、本地处理、匿名化和隐私最小化；不记录图片内容、完整 points、自由文本、绝对路径或逐帧鼠标轨迹，也不在应用内调用大模型。

## Capabilities

### New Capabilities

- `canvas-semantic-action-recording`: 定义 Canvas、标签界面和创建入口如何生成完整、唯一、可归属且有明确时间边界的对象与视图语义动作。
- `object-workflow-timeline-analysis`: 定义全量对象工作流时间线、阶段时间分解、逐对象摘要、项目瓶颈事实及其导出和可信度要求。

### Modified Capabilities

- 无。主规格目录当前没有行为分析能力；本变更以新能力形式承接并收紧历次已完成变更中的行为分析要求。

## Impact

- 记录入口：`anylabeling/views/labeling/widgets/canvas.py`、`anylabeling/views/labeling/label_widget.py` 及相关标签、属性、快捷键和创建入口。
- 行为模块：`anylabeling/services/behavior_analytics/action_catalog.py`、`telemetry.py`、事件 schema、上下文、burst 和对象轮次协调逻辑。
- 分析与导出：`metrics.py`、`statistics_v3.py`、`analysis.py`、`bundle.py`、manifest 与新增 JSONL/CSV 契约。
- 测试：动作目录契约、所有支持形状的受控回放、创建方式、滚轮路径、标签编辑、区间守恒、全量时间线、瓶颈排名、旧版本兼容、隐私和 PyQt offscreen 集成测试。
- 不新增网络、数据库或大模型依赖，不修改标注 JSON 的业务内容。
