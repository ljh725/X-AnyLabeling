# 数据集跨文件目标复核队列（wf-011）使用说明

> 对应 OpenSpec 变更：`add-cross-file-virtual-review-queue`。本文面向
> 使用者，说明工作流、`.xreview.sqlite3` 边车文件的规则、复核结果与
> 过期语义、调和（reconcile）与重建（rebuild）的区别，以及首版未做
> 的事情。

## 1. 功能定位

前两阶段的"目标复核"只在单张图片内生成虚拟任务页。本阶段在其上增加
第三层**数据集队列**：

```text
有序数据集文件
  → 每文件 JSON 快照 → 原子任务（组/单体）
  → 图片内智能拼页（1–3 个任务/页）
  → 冻结的队列修订（revision）
```

- 队列条目永远指向**单张图片内的页面**，不存在跨图片拼页。
- 复核进度按**原子任务**粒度持久化，重建换页后进度跟随任务而非页面。
- 进度保存在评审者自选的 SQLite 边车文件中，**绝不写入标注 JSON**。

## 2. 典型工作流

1. 在检查器（Inspector）「目标复核」标签页下方找到「数据集复核队列」
   区块；上方表单继续作为任务条件与拼页参数来源。
2. 点击「创建队列」，选择 `.xreview.sqlite3` 保存位置。若当前文件有
   未保存修改，会先弹出保存/放弃/取消守卫；取消则不创建队列。
3. 扫描在后台线程进行，可随时「取消扫描」；取消不会影响任何现有
   会话。存在无法解析/缺失的文件时，会先列出排除清单，需显式
   「排除并发布」或「取消」。
4. 队列激活后自动定位到上次游标（或下一个可处理页面）。
5. 复核操作：
   - 任务列表（本页最多 3 行）中选中任务后点「完成/返工/跳过/重置」，
     仅作用于选中任务；未选中时作用于**本页全部已绑定任务**。
   - 「完成并下一页」= 先落库完成、再普通翻页；翻页失败不影响已完成
     的记录。
   - 纯翻页（访问）永不改变复核状态。
6. F2 / Shift+F2 跨图片翻页；离开脏文件时走既有保存守卫，游标仅在
   目标页成功激活后才落库。绘制/拖动/模态编辑期间导航与快捷键被阻止。
7. 完成后「关闭队列」退出，恢复进入前的视口状态并释放写入租约。

## 3. 边车（sidecar）规则

- 文件由评审者在创建时自选位置，建议与数据集同级目录存放。
- **可移植性**：内部保存相对路径 + 数据集根提示。数据集目录连同边车
  一起移动后，用「重选根目录调和」重新绑定即可，进度不变。
- **不要在可编辑状态下手工移动边车文件**（WAL 模式会临时产生
  `-wal`/`-shm` 伴随文件）；正常关闭会自动清理并 checkpoint。
- 「备份」生成经完整性校验的副本；迁移到新 schema 前会自动再留一份
  迁移前备份并记录 `migration_history`。
- 同一边车同时只允许一个可编辑实例（数据库写入租约）。第二个实例
  只能选择只读诊断或「另存副本」。租约疑似过期（心跳超时且持有进程
  不存活）时，必须显式「确认接管租约」才会接管并记录接管事件。
- 更新版本创建的边车（更高 schema 版本）会被拒绝可编辑打开且不会被
  修改，可只读查看摘要。

## 4. 结果与"过期"语义

- 任务结果：`pending / completed / needs_rework / skipped`。
- 完成时记录该任务成员内容的规范化签名。之后：
  - 同文件**其他** shape 被编辑 → 该完成保持"新鲜"；
  - 该任务自身的标签/类型/组关系/几何被修改 → 完成保留但标记
    **过期（stale）**，回到默认可处理视图，需重新显式完成。
  - 绑定不可信（见下）→ 结果保留但标记"未解析"。
- 默认过滤器 = 待处理 + 需返工 + 过期完成；已完成/跳过/全部等通过
  过滤器显式查看。翻页到队列两端会明确提示，不会静默回绕。

## 5. 绑定与调和（reconcile）与重建（rebuild）

绑定状态：就绪（文件未变快路径）/ 已变更但已解析 / 手动绑定 / 孤儿 /
歧义 / 缺失。调和阶梯：快路径 → 精确组 → 精确成员指纹 → 高置信打分
（硬性形状类型门控 + 几何/组/标签软证据 + 置信阈值 0.65 与领先差
0.15）。**歧义目标绝不自动继承进度**；多个存储任务争抢同一候选时全部
降级为歧义。歧义任务可选中后「手动绑定所选」。

| 操作 | 调和 | 重建 |
|------|------|------|
| 成员/顺序/页面 | 冻结不变 | 重新生成新修订 |
| 路径/可用性/绑定/新鲜度 | 刷新 | 重建后按需调和 |
| 进度 | 绝不转移 | 仅精确匹配或显式确认的任务携带；未匹配旧修订行保留为历史 |

新文件加入数据集后，仅通过显式调和/重建报告，不会自动进入队列。

## 6. 写入失败与恢复

任何进度写入失败（磁盘不可写、租约丢失、逻辑修订冲突）都会进入
**持久化受阻**状态：界面保持最后有效状态、禁止继续改结果，可
「重试写入」「另存副本」或明确关闭（关闭时会提示存在未保存进度，
绝不谎称已保存）。标注保存成功而进度写入失败时，标注保持已保存，
并明确提示"完成未记录"。

## 7. 首版非目标（non-goals)

- 不跨图片合并页面；不把复核元数据写进标注 JSON。
- 不做多评审者云端合并；不替代 L1/L2 质检复核队列。
- 不自动接受模型预测/改标签/编组号。
- 队列激活期间不自动插入新文件、不自动重新拼页（只能显式重建）。
- 过滤查找为线性扫描（~3000 页约 50ms/次），增量索引留待后续优化。
