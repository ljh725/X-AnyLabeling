# CUSTOM-001：数据集标签扫描进度与界面响应

- 状态：方案，尚未修改业务代码。
- 日期：2026-10-29（Asia/Shanghai）。
- 项目版本：X-AnyLabeling 4.2.1；当前 HEAD：`4043583b06d765875e263442920ddfe574b2cf20`。
- 实现提交：无。HEAD 仅作定位，本方案依据当前含未提交修改的工作区检查。
- 已有相关修改：`label_widget.py`、目录分阶段加载工具及测试存在未提交改动；实施时应兼容这些修改并单独归集本项差异。

## 已定位的问题

| 入口 / 函数 | 当前行为与问题 |
| --- | --- |
| `label_widget.py::overview()` → `OverviewDialog.init_ui()` | 初始化时即 `populate_table()`，窗口进入 `exec()` 前开始同步扫描。 |
| `overview_dialog.py::get_label_infos()` | 已有 `QProgressDialog`，但文件读取、JSON 解析和统计仍占用 GUI 线程。缺失文件直接跳过进度更新；范围扫描的最大值仍为全列表长度，`setValue(i)` 也不保证最终达到最大值。 |
| `OverviewDialog.toggle_info()` / `update_range()` / `export_to_csv()` | 切换标签/形状、改变范围和导出都会再次扫描；取消扫描返回部分数据，调用方仍可能把它当完整统计或继续导出。导出在扫描前先关闭总览窗口。 |
| `label_dialog.py::LabelModifyDialog.__init__()` → `init_label_info()` | 先遍历和解析所有对应 JSON，再创建界面，因此大数据集时窗口迟迟不出现；扫描中还更新父窗口的类别列表和 `label_info`。 |
| `LabelModifyDialog.confirm_changes()` → `modify_label()` | 改名、删除时还存在同步遍历写入；只改颜色、可见性或会话锁时已有跳过 JSON 修改的逻辑，应保留。 |

## 建议实现

### 1. 共用后台扫描组件

新增 `anylabeling/views/labeling/utils/dataset_scan.py`（拟定），以独立 worker + `QThread` 执行文件读取、JSON 解析、类别收集和统计。界面线程创建任务、接收信号、更新进度和表格；后台不得读写 QWidget 或父窗口的可变状态。

任务输入为固定快照：有序图片路径、输出目录、扫描范围、支持的形状类型和请求编号。保留当前“文件列表及其顺序”作为扫描范围，不静默扩大为磁盘上的所有图片。路径映射仍优先使用 `output_dir`，否则使用图片同名 JSON。

当前目录列表已支持异步分批构建：若列表尚未完成，先显示“正在准备文件列表”，异步等到对应目录/筛选代次和列表回填完成，再冻结完整候选；不能直接截取尚未建完的 QListWidget。等待过程中目录或筛选改变则使旧请求失效。

组件输出进度、结果、失败和取消等独立状态。每次请求带编号，范围切换、重新扫描、关窗后丢弃旧请求的迟到结果。同一对话框只保留一个活动扫描，协作取消后启动最新请求。

### 2. 进度准确且可以取消

- 先显示完整窗口，再以 `QTimer.singleShot(0, ...)` 启动任务；窗口内显示进度条和取消按钮。
- 显示“正在扫描标签：350 / 2000（17%）”，可附当前文件及缺失/错误数。总数为本次选中范围的图片数。
- 每访问一张图片都计数，包括缺失标注、空 shapes 和读取失败；正常结束显示 100%。空数据集显示明确空状态。
- 约每 50–100 ms 合并一次进度反馈，结束时强制发送最终状态；不要为每个 shape 发送 UI 信号。
- 取消在文件间及长 shapes 循环中检查；不强制终止线程。单次阻塞读取/JSON 解析无法立即中断，显示“正在取消”并等待安全退出。
- 扫描和表格准备期间禁用修改、导出等依赖完整结果的按钮；窗口保持可重绘、可取消。关闭时先取消，保留 worker 所有权直到线程退出，避免销毁仍运行的 QThread。
- 失败文件单独记录并汇总，区分“缺失”与“读取失败”。带错误的统计明确标为不完整，禁止按完整结果导出；标签管理器存在扫描错误时禁止提交修改，修复后重试。取消保留先前完整结果，首次扫描取消则回到空状态。

### 3. 统计总览

让 `get_label_infos()` / `get_total_infos()` 的文件读取和聚合进入后台；纯表格转换与 UI 展示分离。保留标签排序、形状过滤、difficult 高亮、范围语义和双击定位映射。

一次成功扫描同时产生标签汇总、形状信息及图片对应关系，标签/形状视图切换复用本次结果。范围改变重新扫描；增加明确的重新扫描入口读取外部变动。缓存仅限当前对话框和本次成功任务，不作为跨会话的标签源。

大表格仍可能卡住 GUI：用 QTimer 按时间预算分批填充，例如每轮约 8 ms，批次大小以实测调整；批量更新时阻断信号、暂停重绘，避免每插入一行就自动调整所有列宽。结果队列设上限，避免后台生产速度超过界面消费速度。

保留当前导出全文件列表的语义，不能误导出当前范围。导出先后台扫描完整快照，再后台写 CSV/ZIP，并显示“扫描 / 导出”阶段；取消或失败不生成成功结果。ZIP 使用独立临时路径，完成后再发布最终文件，清理本任务临时文件；全程保留对话框直到成功。大量 shapes 的内存峰值需实测，必要时使用任务临时存储和分页/流式导出。

### 4. 标签管理器

将 `init_label_info()` 拆为后台收集类别、主线程合并类别与构建界面。扫描中只维护局部结果；完整成功后才合并到父窗口，取消或失败不提交部分结果。

合并时继续纳入当前类别列表已有类别，保留颜色、透明度、可见性、自然排序及会话锁。后台只接收这些状态的快照；新增 Qt 列表项和表格行始终在 GUI 线程分批创建。

打开时的扫描与点击 Go 后的改名/删除分成两类任务。建议分两步交付：先完成两个入口的只读扫描与总览导出，再为标签批量改写增加独立后台任务和进度，避免把写入取消与扫描取消混用。

批量改写需要先快照修改指令，保留锁定类别的删除保护、范围和仅改会话属性不重写 JSON 的行为；每个 JSON 用临时文件再替换，成功后才更新对应会话状态。写入阶段取消只在文件边界生效，明确报告已改/未改/失败文件，不宣称全数据集回滚。当前 `confirm_changes()` 在落盘前更新父状态的顺序需要同步调整，失败时不得显示全成功。

## 拟修改文件与边界

| 文件 | 计划修改 |
| --- | --- |
| `utils/dataset_scan.py`（新增） | 快照输入、任务状态、后台扫描、进度节流、协作取消、请求编号。 |
| `widgets/overview_dialog.py` | 窗口先显示、异步扫描和导出、结果复用、表格分批填充、取消/失败处理。 |
| `widgets/label_dialog.py` | 仅改 `LabelModifyDialog` 的初始化扫描及后续写入任务；保留其他对话框职责。 |
| `label_widget.py` | 必要的列表就绪/扫描上下文接口和入口适配，与现有分阶段加载兼容。 |
| `resources/translations/*.ts` 及编译资源 | 按项目流程新增进度、准备、取消、错误等翻译，并生成实际运行使用的资源。 |
| `tests/`、本记录 | 增加实质行为回归及测量结果，记录实际实现文件、提交和限制。 |

JSON 继续作为真实标注源，不改格式、不引入持久数据库。当前画布未保存的编辑不自动写入；只读统计仍按磁盘内容。Group ID 管理器等也有同步遍历，可后续复用组件，每个扩展入口单独登记和回归。

## 验收计划（未执行，不是测试结果）

1. 对同一固定数据集比对改前/改后统计、类别、范围、双击定位与导出内容；包含自定义输出目录、缺失 JSON、空 shapes、错误 JSON、权限错误。
2. 用可控慢读取验证扫描期间 GUI 定时器继续运行，取消和关窗无崩溃，迟到结果不覆盖新范围/新目录；后台不接触 Qt 控件。
3. 检查范围进度从 0 到实际总数，缺失文件计数，取消不导出部分统计；扫描失败不允许提交类别修改。
4. 覆盖列表仍在分批加载时打开工具、连续重扫/关窗/重开、大形状表格分批填充与有界队列。
5. 保留 `tests/test_labeling/test_label_manager_locks.py` 的锁语义回归；异步初始化后让测试等待明确的完成信号。
6. 只读扫描前后比对标注哈希；批量写入在临时数据上验证取消、失败、锁保护和会话状态一致性。
7. 用约一万张图片记录窗口首次可见时间、总耗时、GUI 心跳最大间隔/P95、取消响应和内存峰值。建议本地常规样本以最大心跳间隔低于 200 ms 为优化目标；超大单个 JSON、冷缓存、网络盘另列结果，不能用暖缓存/offscreen 结果代替真实显示器体验。

## 迁移与回退

实施时先迁移共用任务组件，再迁移两个对话框和必要入口，最后迁移翻译、测试与生成资源。按函数职责重新定位，不依赖本次行号；重点检查上游是否已调整 JSON 映射、形状结构、会话锁、目录加载和导出范围。

完成后在本记录补充实际提交、最终文件列表、验证命令/结果和性能数据，并更新索引状态。回退只撤销本项组件及调用点、翻译和测试，保留此前分阶段加载等其他定制；不回滚用户数据。若已执行标签改名/删除，回退代码不会恢复已经修改的 JSON，需要使用单独的数据备份。
