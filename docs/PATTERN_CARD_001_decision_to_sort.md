## 一、一句话核心

> **把"该选谁 / 该触发谁"的决策问题，转成"给每个候选算一个可比较的分数，再排序"。**

```
❌ 过程式思维：  if(顶点) 选顶点  elif(小框) 选小框  else 选栈顶
✅ 数据化思维：  给每个候选打分  →  sort  →  取首个
```

这个"视角的跳跃"是全部精髓。记住这一句，就抓住了 80%。

---

## 二、什么时候该想到它（触发情境）

满足下面**任一**条件，就该条件反射般想起这张卡片：

- [ ] 一个触发点（点击/悬停/事件）可能命中**多个候选**，要决定"谁赢"
- [ ] 判定规则有**多个且会互相打架**（顶点优先？还是距离近优先？还是面积小优先？）
- [ ] 你正打算写一长串 `if-elif-else` 规则链，且预感"以后加规则会很乱"
- [ ] 同一套决策要在**多个地方复用**（如悬停、点击、双击都要判断"选谁"）

**一句话自检**：如果你心里冒出"这个 if-else 越写越长、改一处怕崩三处"——停，翻这张卡片。

## 三、三步操作法（照着做就行）

```
第1步  生成候选：  把所有"可能被命中"的对象收进一个列表
                  （可用空间索引先粗筛，再做精确判定）

第2步  打分：      给每个候选算一个 priority 元组 = (维度1, 维度2, ..., 维度n)
                  所有候选的元组必须【维度数相同、可比】

第3步  排序消费：  candidates.sort(key=lambda c: c.priority)  # 全升序，小者优先
                  悬停/点击/双击等消费者，统一取"排序后的首个"
```

## 四、4 维度怎么设计（4 条准则速记）

> 这是本模式唯一需要动脑的地方：维度选什么、顺序怎么排。

| 准则 | 一句话 | 记忆钩子 |
|------|--------|---------|
| **① 语义层级** | 维度按"质(离散) → 量(连续) → 兜底"排，**不要按计算成本排** | "意图优先于细节" |
| **② 语义失效** | 某维度在某场景不该起作用时，**给它填 0/常量**，让它自动平手让位，不写 if | "填个 0，零 if" |
| **③ 代理变量** | 主观语义（"更具体"）用客观可算的量（面积）来**代替** | "面积 ≈ 具体性" |
| **④ 兜底兼容** | 最后一维放"保留旧行为"的维度（如栈序），保证默认行为不变 | "能不动就不动" |

**XAL 当前实例**：`priority = (级别, 主排序值, 次排序值, -栈序)`
- 级别(离散)在前 → 抓顶点优先于抓整体（准则①）
- 顶点/边命中时主排序值=距离；整体命中时主排序值=面积（准则②）
- 用面积当"具体性"的代理，小面积对象优先（准则③）
- -栈序兜底，等同旧 `reversed` 行为（准则④）

## 五、这个模式为什么"好"（收益矩阵）

| 收益 | 原因 |
|------|------|
| 规则解耦 | 每个维度独立，改一个不影响其他（不像 if-else 耦合） |
| 可组合 | 加规则 = tuple 加一维，不改结构 |
| 可扩展 | 锁定降级、分组、3D 拾取都能加维度解决 |
| 可单测 | 核心是纯函数排序，能脱离 UI 框架测 |
| 向后兼容 | 兜底维度保证"默认行为 = 旧行为"，安全升级 |

## 六、能迁移到哪里（举一反三）

| 场景 | 候选 | 可能的维度 |
|------|------|-----------|
| 地图 POI 重叠点选 | 多个 POI | 类型优先级、距离、面积 |
| 表格单元格重叠 | 多个 cell | 层级（合并单元格 vs 普通）、行列 |
| 游戏 UI 点击穿透 | 多个碰撞体 | UI 层级、距离、阵营 |
| 数据可视化 tooltip | 多个数据点 | 距离、数据值大小、是否高亮 |
| CAD 端点/线/面拾取 | 点/线/面 | 类型(点<线<面)、距离 |
| 文件管理器多选框 | 多个文件 | 距离、是否已选、类型 |

> **自检题**：下次遇到新场景，先问自己——"这里的候选是谁？要按哪几个维度分胜负？" 能答上来，就能套用。

## 七、避坑（4 个反模式）

| 反模式 | 后果 | 正解 |
|--------|------|------|
| 维度按计算成本排序 | 便宜维度压倒语义优先级 | 只按语义层级排 |
| 不同候选 priority 维度数不一致 | sort 报错或语义错乱 | 所有候选必须同维度数 |
| 在 priority 计算里塞副作用 | 排序结果不可预测 | priority 必须是纯函数 |
| 忽视浮点精度 | 1e-16 误差导致不确定排序 | 距离量化/容差归一 |
