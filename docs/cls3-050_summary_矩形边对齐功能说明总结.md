# 矩形边对齐功能说明总结

本文档作为后续“矩形边对齐”功能扩展讨论的起点，记录当前已经确定并实现的功能边界、交互规则、代码结构和下一阶段可扩展方向。

## 1. 功能目标

矩形边对齐功能用于提高矩形框局部修正效率，解决仅靠拖动顶点或滚轮微调时操作慢、精度依赖手感的问题。

当前功能聚焦一个明确任务：

- 选择一个矩形框边作为参考边。
- 选择另一个矩形框边作为对齐边。
- 拖动对齐边时，靠近参考边后吸附。
- 鼠标释放时提交一次几何修改。

该功能只改变目标矩形框的几何坐标，不改变 label、group_id、flags、attributes 等业务字段。

## 2. 当前范围

已支持：

- 仅支持 `rectangle` 类型。
- 支持 `left/right/top/bottom` 四条边。
- 支持同轴对齐：
  - `left/right` 只能和 `left/right` 对齐。
  - `top/bottom` 只能和 `top/bottom` 对齐。
- 不允许同一个矩形框内部边对齐。
- 支持两点矩形和四点矩形输入。
- 输出统一为四点矩形，顺序为 `top-left -> top-right -> bottom-right -> bottom-left`。
- 支持拖动中实时预览，释放时提交。
- 支持 Esc 取消拖动或清除参考边。
- 支持吸附阈值，当前为屏幕像素 `8px`，内部换算到图像坐标。

暂不支持：

- 非矩形对象边对齐。
- 多目标批量边对齐。
- 自动推断一组框之间的推荐对齐关系。
- 保存“参考边/对齐边”状态到 JSON。
- 将边作为正式标注对象持久化。

## 3. 入口与交互流程

入口：

- 在视图菜单中增加可勾选功能项：`矩形边对齐`。
- 默认关闭。
- 不新增快捷键。

流程：

1. 开启 `矩形边对齐`。
2. 鼠标悬停到矩形边，显示边级高亮。
3. 第一次点击边：设置为参考边。
4. 第二次点击兼容边：设置为对齐边并进入拖动状态。
5. 按住左键拖动：对齐边实时预览移动。
6. 靠近参考边：触发吸附。
7. 鼠标释放：提交一次修改，并保留参考边，便于继续对齐下一个目标。
8. Esc：
   - 拖动中：取消本次拖动并恢复目标框原坐标。
   - 非拖动但有参考边：清除参考边。
   - 不关闭功能开关。

## 4. 边对象模型

边对象是临时编辑句柄，不是正式标注对象。

核心结构位于：

- `anylabeling/views/labeling/rect_edge_alignment.py`

核心数据结构：

- `RectGeometry`
  - 归一化矩形几何，保存 `x_min/y_min/x_max/y_max`。
- `RectEdgeRef`
  - 临时边引用，保存所属 `Shape`、边名、轴向、坐标、两个端点和对边坐标。

关键函数：

- `geometry_from_shape()`
  - 从两点或四点矩形生成归一化几何。
- `nearest_edge()`
  - 根据当前鼠标图像坐标命中最近矩形边。
- `edges_are_compatible()`
  - 判断参考边与目标边是否可对齐。
- `apply_edge_coord()`
  - 移动某一条边，并防止矩形翻转。

## 5. 坐标规则

交互中同时存在两类坐标：

- 屏幕像素坐标：鼠标在界面上的位置，用于命中体验和吸附阈值感知。
- 图像像素坐标：真实写入标注点的坐标，用于最终保存。

当前实现规则：

- 鼠标事件进入 Canvas 后，通过 `transform_pos()` 转换为图像坐标。
- 边命中、边移动、最终保存都基于图像坐标。
- 吸附阈值以屏幕像素定义，再用 `scale` 换算为图像坐标。
- 拖动使用增量坐标：
  - 拖动开始时记录鼠标轴向坐标。
  - 同时记录边的原始轴向坐标。
  - 拖动中使用 `start_edge + (current_mouse - start_mouse)` 计算新边坐标。

采用增量坐标的原因：

- 用户点击位置不一定精确落在边坐标上。
- 如果直接使用鼠标绝对坐标，第一帧可能造成边跳变。
- 增量拖动能保持“按住哪里就从哪里开始移动”的稳定手感。

## 6. 事件优先级

当前已修复一个关键交互问题：

- 原问题：边拖动期间，普通左键拖动/画布平移分支先处理事件，导致画面跳跃并失去目标。
- 修复规则：当 `rect_edge_dragging=True` 且存在 active edge 时，矩形边拖动在 `mouseMoveEvent` 中拥有最高优先级。
- 结果：边拖动事件会先被消费，不再落入 `scroll_request` 画布平移逻辑。

相关位置：

- `anylabeling/views/labeling/widgets/canvas.py`
  - 边对齐状态字段：`Canvas.__init__`
  - 拖动最高优先级处理：`mouseMoveEvent`
  - 点击参考边/目标边：`mousePressEvent`
  - 释放提交：`mouseReleaseEvent`
  - 拖动更新：`_rect_edge_drag_update`
  - 清理/取消：`clear_rect_edge_alignment`、`cancel_rect_edge_drag`
  - 绘制反馈：`_draw_rect_edge_alignment_overlay`
- `anylabeling/views/labeling/label_widget.py`
  - 视图菜单入口与开关同步。

## 7. 视觉反馈规则

当前视觉语义：

- hover：白色边。
- reference：蓝色虚线边。
- active：橙色边。
- snap：绿色边。
- invalid：红色边。

设计原则：

- 只改变参与交互的边，不改变整个矩形框颜色。
- 不把状态颜色和矩形框自身 label/id 颜色叠加。
- 降低画面要素密度，避免标注场景中过多颜色同时出现。

## 8. 保存与撤销

保存规则：

- 功能不直接写 JSON。
- 鼠标释放时，如果几何确实变化，则通过现有 `store_shapes()` 进入撤销栈。
- 每次释放形成一次撤销粒度。
- 目标框点位更新为四点矩形。

取消规则：

- Esc 取消拖动时恢复拖动开始前的点位。
- 取消拖动不提交撤销记录。
- 释放后保留参考边，以支持连续对齐多个目标。

## 9. 当前验收口径

功能可接受的最小闭环：

- 开启功能后能选中参考边。
- 能选中兼容目标边。
- 拖动目标边时画面不跳跃。
- 拖动过程中目标边实时移动。
- 接近参考边时吸附。
- 释放后目标矩形坐标变化。
- Esc 能取消拖动并恢复。
- 关闭功能后不影响原有矩形框选择、顶点拖动、画布平移。

已知关键回归点：

- 边拖动期间不应触发画布平移。
- 拖动第一帧不应因为鼠标未精确落边而跳变。
- 参考边不应被保存为正式 shape。

## 10. 后续扩展讨论入口

后续扩展建议从以下方向展开：

1. 对齐方式扩展
   - 一键对齐到参考边。
   - 点击目标边后直接吸附，无需拖动。
   - 支持边到边、中心线到中心线、框宽/高同步。

2. 操作效率扩展
   - 连续对齐多个目标边。
   - 选择参考边后，自动提示候选目标边。
   - 批量对齐同一组 head/person/face 的相邻边。

3. 视觉反馈扩展
   - 增加参考边标签或轻量提示。
   - 增加吸附距离提示。
   - 增加当前移动轴向提示。

4. 精度控制扩展
   - 可配置吸附阈值。
   - 支持细调步长。
   - 支持释放前显示最终坐标差。

5. 规则联动扩展
   - 与 L1/L2 质检结果联动，从 issue 跳转后自动进入边对齐模式。
   - 根据 `face -> head`、`head -> person` 的 QA 临时关系推荐参考边。
   - 对复核队列中的几何偏差问题提供快捷修正入口。

6. 数据闭环扩展
   - 统计人工对齐操作前后的坐标差。
   - 汇总最常被修正的边类型。
   - 反向优化质检规则阈值和问题优先级。

## 11. 后续讨论原则

后续所有扩展讨论建议继续遵守三个边界：

- 先解决人工修正效率，再讨论自动化程度。
- 先保证单次操作稳定可预期，再增加批量能力。
- 边对象继续保持临时编辑句柄，不升级为正式标注对象，除非后续有明确的数据模型变更需求。
