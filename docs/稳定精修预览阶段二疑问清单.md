## 🔴 Q1：选区变化接入策略

**位置**：`canvas.py` 的 `selection_changed` 信号（`canvas.py:77` 定义，**12 处** emit：1593/1655/1678/1689/1693/1705/1707/1720/1722/1736/1740/2321）。

**背景**：阶段二 TargetPreview 的触发依赖选区变化。文档 §6.1 建议"`selection_changed.emit` 后调用同步方法"，但 12 处 emit 分散在 press/release 的各种选中分支里。

**选项**：

| 选项 | 做法 | 优点 | 风险 |
|------|------|------|------|
| **(A) 信号监听** | `self.selection_changed.connect(self._stable_preview_on_selection_changed)`，一处接住所有 emit | 1 行接入、零回归、覆盖全部 emit | 若有"改了 selected_shapes 却忘记 emit"的漏网路径会漏响应 |
| **(B) 收敛 helper** | 把 12 处 emit 收进 `_set_selection(shapes)`，只在 helper 调预览同步 | 可控、语义集中 | 改 12 处，回归面大 |

**我的倾向**：(A) 信号监听。但需先排查 `selection_changed` 发射是否完整覆盖单选/多选/取消选中/删除 shape 全路径。

**需要你定夺**：选 (A) 还是 (B)？若 (A)，是否允许我先 grep 排查"修改 selected_shapes 却未 emit"的漏网路径（重点查 delete_shape / 程序化选中）。

## 🔴 Q2：状态拆分边界（最容易出错）

**位置**：`canvas.py:3981`（`clear_rect_edge_alignment` 末尾的 `self._stable_preview_clear()`）。

**背景**：阶段一靠 `clear_rect_edge_alignment` 里**一处** `_stable_preview_clear()` 覆盖了 release/escape/cancel/load_shapes 四路径 → 松开即隐藏。阶段二要 release 后**保留 TargetPreview**，这个无差别 clear 必须拆开（文档 §9.2 点名"最容易出错的状态拆分点"）。

**难点**：`clear_rect_edge_alignment` 同时被 4 个场景调用，但它们对 TargetPreview 的处置**不同**：

| 调用方 | 对 DragLocked | 对 TargetPreview |
|--------|---------------|------------------|
| mouse-release | 清 | **保留**（回 Target） |
| Escape / cancel | 清 | **保留**（若仍选中矩形） |
| load_shapes（切图） | 清 | **清**（切图必清） |
| load_pixmap（切图） | 清 | **清** |

**问题**：拆分后 `clear_rect_edge_alignment` 里该调哪个？
- 若调 `_clear_all()`，TargetPreview 在 release/escape 后活不下来（破坏阶段二衔接）。
- 若只调 `_clear_drag_locked()`，load_shapes（切图）会漏清 Target。

**我的设想方案**：
```
clear_rect_edge_alignment():
    ...rect_edge 字段...
    self._stable_preview_clear_drag_locked()   # 只清拖动态，保留 target

# release / escape 后额外调：
_enter_target_if_valid()   # 按选区决定：回 Target 还是 Idle

# load_pixmap / reset_state 里显式调：
_stable_preview_clear_all()   # 彻底清，含 Target
```

**需要你确认**：
1. 这个拆分对吗？
2. **load_shapes / reset_state 走的是 `clear_rect_edge_alignment` 吗？** 实测：`load_shapes`（`canvas.py:4284` 区）确实调了 `clear_rect_edge_alignment`，reset_state（`4495` 区）也补调了。若 `clear_rect_edge_alignment` 只清 drag，则**切图会漏清 Target**。因此 load_shapes/reset_state/load_pixmap 必须各自**额外显式调 `_clear_all()`**，不能依赖 `clear_rect_edge_alignment`。请确认这个边界判断。

## 🔴 Q3：安全区（safe_rect）判断的触发时机

**位置**：文档 §8.1 安全区规则。

**背景**：安全区防晃的核心是"bbox 在 safe_rect 内就不重算 target_rect"。但这个判断**在哪个事件里跑**？文档未明确。

**关键矛盾**：TargetPreview 状态下 shape 怎么会变？
- 拖动中 → 但拖动中是 DragLocked 接管，不该动 Target。
- 键盘微调 → 文档明确留阶段三。
- 外部修改（撤销/属性编辑）→ 较少。

**我的推断**：阶段二安全区**主要服务一个时刻**——从 DragLocked 松开后回到 Target 的瞬间。此时 shape 刚被拖动过、bbox 变了，需判断"要不要重算 target_rect"。

如果是这样，安全区逻辑**只需在 `_enter_target_if_valid()` 里判断一次**，不需要挂到 mouseMoveEvent。

**需要你确认**：
1. 安全区判断是否只在 `_enter_target_if_valid()`（release/escape 后回到 Target 的那一刻）触发？
2. 还是也要在选中瞬间（单选矩形 → 进 Target）每次都算一次？我的倾向：**选中瞬间算一次 target_rect，之后只在 DragLocked→Target 衔接时按安全区判断是否重算**。确认这个触发模型？

## 🟡 Q4：`stable_preview_shape` 字段是否复用

**位置**：`canvas.py` 阶段一字段（`stable_preview_shape`，press 时赋值）。

**背景**：阶段一 `stable_preview_shape` 在 press 时赋为被拖矩形。TargetPreview 也需关联一个 shape 画框。

**选项**：

| 选项 | 做法 | 评价 |
|------|------|------|
| **(A) 复用** | 选中时赋为选中矩形，DragLocked 也指向同一矩形 | 简单；衔接时无需同步两个引用 |
| **(B) 拆分** | `stable_preview_target_shape` + `stable_preview_shape`(drag) | 隔离清晰但冗余，需双向同步 |

**我的倾向**：(A) 复用。因为 Target 和 DragLocked 衔接时几乎总是同一个矩形（拖动矩形边的前提是先选中它），拆开反而要维护两个引用一致性。

**需要你确认**：复用 `stable_preview_shape` 一个字段？

## 🟡 Q5：TargetPreview 浮层显示内容

**位置**：`canvas.py:4144` `_draw_stable_preview_overlay`。

**背景**：阶段一浮层画 = 裁剪图 + 绿框 + **黄色当前拖动边高亮** + 倍率标签。TargetPreview 时无拖动（`active_edge_name` 为 None）。

**问题**：TargetPreview 浮层是否还高亮某条边？
- 候选 a：不画边高亮（只绿框 + 标签）。hover 边的高亮交由主画布 rect_edge overlay 负责。
- 候选 b：高亮当前 hover 的边（若 `rect_edge_hover_edge` 有值）。

**我的倾向**：候选 a（不画边高亮）。TargetPreview 是"观察整体贴合度"，边高亮是拖动期的辅助，主画布已有 hover 提示，浮层里再画会信息过载。

**需要你确认**：TargetPreview 只画 绿框 + 倍率标签，不画边高亮？

## 🟢 Q7：边缘贴边判断精度

**位置**：文档 §8.2 边缘放宽规则。

**背景**：§8.2 用 `target_rect.left == 0` 等精确相等判断是否贴边。但 `_clamp_rectf_to_image`（`canvas.py:3967`）算出的 left 是浮点 `max(0.0, ...)`，`==` 比较有精度风险。

**选项**：

| 选项 | 做法 |
|------|------|
| **(A) 精确** | `left == 0` |
| **(B) 容差** | `left < 1.0` 像素 |

**我的倾向**：(B) 容差 `< 1.0`。避免浮点抖动导致边缘放宽时灵时不灵。

**需要你确认**：用容差判断贴边？
