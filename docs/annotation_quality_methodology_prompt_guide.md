# 标注质量治理方法论提示词指南

这份文档用于处理比“新增一个功能”更高一层的问题：如何建立标注质量标准、发现误差模式、选择统计方法、引入模型辅助、设计人工复核流程，并在最后才决定哪些部分需要代码化。

它特别适合类似下面的场景：

```text
我有一个手动标注的三类检测框 + pose 关键点数据集。
标签数量约 15916 个 JSON 文件。
现在每天检测 150 到 260 张图片，主要依赖人工检查。
标注质量已经有较高保证，但算法工程师希望进一步提高精度，做二次校验。

三类检测框为 person、head、face，精度要求高。
pose 关键点精度不做过高要求。

当前已经完成：
1. 三类标签名检查；


我想知道还有什么方法可以进行目标水平矩形框准确度的调整。
```

这个问题不应该一开始被建模成“写一个检查脚本”或“加一个 UI 功能”。它首先是一个标注质量治理问题。

## 使用目标

这个提示词的目标是让大模型先完成方法论建模，再决定是否需要代码：

1. 明确什么叫“框准确”；
2. 建立误差类型体系；
3. 选择统计诊断方法；
4. 判断模型如何参与二次校验；
5. 设计人工复核流程；
6. 最后再决定工具、脚本或软件功能如何落地。

一句话原则：

```text
先建立质量判断体系，再决定哪些部分需要代码化。
```

## 总体分层

建议把问题拆成七个层级：

```text
业务目标层
-> 数据标准层
-> 误差建模层
-> 统计诊断层
-> 模型辅助层
-> 人工复核流程层
-> 工具化实现层
```

各层含义如下：

| 层级 | 关键问题 |
|------|----------|
| 业务目标层 | 到底要提升什么质量指标？对 person/head/face 的优先级是否不同？ |
| 数据标准层 | 什么叫框准？边界贴合、IoU、包含关系、中心偏移、宽高比例是否都有标准？ |
| 误差建模层 | 常见错误是框偏大、偏小、偏移、漏标、错标、跨类关系异常，还是 group 关系异常？ |
| 统计诊断层 | 如何从 15916 个 JSON 中找到高风险样本，而不是重新全量人工检查？ |
| 模型辅助层 | 模型是做候选框对比、异常发现、置信度排序，还是做人类标注的反向审计？ |
| 人工复核流程层 | 每天 150 到 260 张图，哪些必须查，哪些抽查，哪些只查高风险项？ |
| 工具化实现层 | 哪些规则适合脚本，哪些适合 UI，哪些适合报告，哪些适合半自动修正？ |

## 第一轮：问题重新建模

这一轮不要让模型直接给代码或工具方案。先让它把问题从“矩形框调整”提升到“质量治理体系”。

```text
我现在有一个标注质量改进问题：

【数据集背景】
- 标注文件数量：
- 每日新增或检查图片数量：
- 标注类型：
- 高精度要求类别：
- 低精度要求类别：
- 已完成的基础检查：
- 当前人工流程：
- 希望改进的目标：

请不要直接写代码，也不要只把它当成功能开发问题。

请先把它建模成一个“标注质量治理问题”，从以下层面分析：

1. 业务目标层：
   - 当前真正要提升的质量目标是什么？
   - 哪些类别的精度优先级最高？
   - 哪些问题会直接影响模型训练或评估？

2. 数据标准层：
   - 什么叫 person/head/face 框准确？
   - 应该用哪些可观察标准描述框质量？
   - 哪些标准适合人工判断，哪些标准适合程序化检查？

3. 误差建模层：
   - 请枚举可能的检测框误差类型。
   - 对每类误差说明可观察症状。
   - 判断这些误差是否可以通过规则、统计、模型或人工复核发现。

4. 统计诊断层：
   - 如何从大量 JSON 中发现高风险样本？
   - 可以统计哪些分布、比例、异常值或跨类别关系？
   - 哪些统计指标最可能暴露框不准的问题？

5. 模型辅助层：
   - 模型可以如何参与二次校验？
   - 应该用模型替代人工，还是用模型筛选人工复核对象？
   - 如何利用模型预测框与人工框的差异发现可疑标注？

6. 人工复核流程层：
   - 在每天 150 到 260 张图片的规模下，如何设计高性价比复核流程？
   - 哪些样本必须人工复核？
   - 哪些样本可以抽查？
   - 哪些样本可以通过规则或模型自动放行？

7. 工具化实现层：
   - 哪些部分适合做成脚本？
   - 哪些部分适合做成标注工具里的交互功能？
   - 哪些部分只需要生成报告，不需要改动标注工具？

最后，请给出一个从低成本到高成本的分阶段路线图。
```

## 第二轮：定义框准确标准

如果第一轮模型给出的方案太泛，下一步要逼它定义“准确”的可操作标准。

```text
请不要继续泛泛讨论质量提升。
现在请专门定义 person/head/face 三类水平矩形框的准确标准。

要求：

1. 分别定义 person、head、face 的理想框边界；
2. 说明每类框允许的误差范围；
3. 列出不合格框的典型表现；
4. 区分严重错误、一般错误、可接受偏差；
5. 说明哪些标准可以自动检测，哪些只能人工判断；
6. 如果没有人工金标准，说明如何用统计和模型结果近似发现异常。
```

这一轮的核心是把“感觉框不准”变成可讨论、可统计、可复核的标准。

## 第三轮：建立误差类型表

质量治理不能只问“准不准”，而要问“是哪一种不准”。

```text
请为 person/head/face 水平矩形框建立误差类型体系。

请按表格输出：

1. 误差类型；
2. 适用类别；
3. 可观察症状；
4. 可能原因；
5. 自动发现方法；
6. 是否需要人工确认；
7. 对训练精度的影响；
8. 建议处理方式。

请至少覆盖：
- 框偏大；
- 框偏小；
- 框中心偏移；
- 宽高比例异常；
- person/head/face 包含关系异常；
- 同一 group_id 内对象空间关系异常；
- 漏标；
- 多标；
- 类别错标；
- 遮挡或截断导致的边界争议。
```

## 第四轮：统计诊断方案

在 15916 个 JSON 的规模下，直接全量人工复查成本高。更合理的方式是先用统计方法找风险点。

```text
请设计一套不依赖重新人工全量复查的统计诊断方案。

数据条件：
- 每个 JSON 中有 person/head/face 检测框；
- 三类标签名已检查；
- 三类 group_id 已统一；
- pose 关键点存在，但精度要求不高；
- 重点是三类水平矩形框准确度。

请输出：

1. 应统计哪些基础指标；
2. 应检查哪些跨类别几何关系；
3. 应如何发现异常宽高比、面积比、中心偏移、包含关系异常；
4. 如何按图片、类别、group_id、批次或时间维度做异常排序；
5. 如何把样本分为高风险、中风险、低风险；
6. 每类风险样本应该如何复核；
7. 哪些统计结果可以转化为工具规则。
```

可考虑的统计方向：

| 方向 | 示例 |
|------|------|
| 单框统计 | 宽、高、面积、宽高比、中心点位置 |
| 类别间关系 | face 是否在 head 内，head 是否在 person 内 |
| group 关系 | 同一 group_id 内 person/head/face 是否空间一致 |
| 分布异常 | 极端小框、极端大框、比例异常框 |
| 相对位置 | head 在 person 上部，face 在 head 内部或附近 |
| 批次差异 | 某天或某批数据异常率升高 |
| 置信分层 | 模型与人工差异大的样本优先复核 |

## 第五轮：模型参与二次校验

模型不一定要替代人工。更稳的方式通常是让模型做“可疑样本发现器”。

```text
请设计模型参与标注二次校验的方法。

前提：
- 人工标注质量已经较高；
- 算法工程师希望进一步提高 person/head/face 框精度；
- pose 关键点不是当前最高优先级；
- 不希望模型直接覆盖人工标注。

请比较以下方案：

1. 用现有检测模型预测框，与人工框做 IoU/中心偏移/面积比对比；
2. 使用多个模型交叉投票，找模型之间或模型与人工之间分歧大的样本；
3. 训练一个轻量异常检测器，识别几何关系异常；
4. 只用模型做高风险样本排序，人工最终确认；
5. 对高置信模型结果与人工标注明显冲突的样本生成复核任务；
6. 基于历史修正记录迭代风险规则。

请对每种方案说明：
- 成本；
- 需要的数据；
- 可能发现的问题；
- 误报风险；
- 漏报风险；
- 是否适合当前阶段；
- 最小验证实验。
```

## 第六轮：人工复核流程设计

质量提升不是单靠规则或模型完成的，还需要复核流程。

```text
请基于每天 150 到 260 张图片的工作量，设计一个人机协同复核流程。

要求：

1. 不显著增加人工负担；
2. 优先复核 person/head/face 三类框；
3. pose 关键点只作为辅助参考，不作为主要复核目标；
4. 将样本分为必须复核、抽样复核、自动放行三类；
5. 给出每日复核顺序；
6. 给出异常样本如何回流到规则或模型改进；
7. 给出质量指标如何持续追踪。
```

推荐思路：

```text
全量规则扫描
-> 高风险样本优先人工复核
-> 中风险样本抽样复核
-> 低风险样本自动放行
-> 人工修正记录回流
-> 更新统计阈值、规则或模型
```

## 第七轮：工具化落地

只有当前面的方法论足够清楚时，才进入工具化实现。

```text
请把上面的标注质量治理方案拆成工具化落地计划。

请区分：

1. 不需要写代码，只需要形成规范的部分；
2. 适合离线脚本批量检查的部分；
3. 适合在标注工具中做成 Inspector 规则的部分；
4. 适合生成统计报告的部分；
5. 适合模型辅助排序或推荐的部分；
6. 暂时不建议实现的部分。

请按优先级输出：
- 第一阶段：1 到 2 天内可以验证；
- 第二阶段：一周内可以稳定使用；
- 第三阶段：需要模型或流程积累后再做。
```

这一轮才应该讨论代码、界面、脚本、报告、模型接口等实现细节。

## 推荐完整提示词

如果只想复制一段完整提示词，可以使用下面这个版本。

```text
我现在有一个标注质量改进问题：

我有一个手动标注的三类检测框 + pose 关键点数据集。
标签数量约 15916 个 JSON 文件。
现在每天检测 150 到 260 张图片，主要依赖人工检查。
标注质量已经有较高保证，但算法工程师希望进一步提高精度，做二次校验。

三类检测框为 person、head、face，精度要求高。
pose 关键点精度不做过高要求。

当前已经完成：
1. 三类标签名检查；
2. 三类标签 group_id 统一。

我想知道还有什么方法可以进行目标水平矩形框准确度的调整。

请不要直接写代码，也不要只把它当成功能开发问题。
请先把它建模成一个“标注质量治理问题”。

请从以下层面分析：

1. 业务目标层：
   - 真正要提升的质量目标是什么？
   - person/head/face 三类的优先级如何区分？
   - 哪些错误最可能影响模型训练或评估？

2. 数据标准层：
   - 什么叫水平矩形框准确？
   - person/head/face 三类框分别应该如何定义边界？
   - 哪些偏差可接受，哪些必须修正？

3. 误差建模层：
   - 请建立框误差类型体系。
   - 包括框偏大、偏小、偏移、比例异常、包含关系异常、漏标、多标、错标等。
   - 对每类误差说明可观察症状和发现方法。

4. 统计诊断层：
   - 如何从 15916 个 JSON 中发现高风险样本？
   - 应统计哪些几何特征、类别关系、group_id 关系和异常分布？
   - 如何把样本分为高风险、中风险、低风险？

5. 模型辅助层：
   - 模型应该如何参与二次校验？
   - 是否应该用模型与人工标注做差异比对？
   - 是否应该用模型只负责筛选可疑样本，而不是直接覆盖人工结果？

6. 人工复核流程层：
   - 在每天 150 到 260 张图片的规模下，如何设计低负担、高收益的复核流程？
   - 哪些样本必须复核？
   - 哪些样本可以抽查？
   - 哪些样本可以自动放行？

7. 工具化实现层：
   - 哪些部分适合做成离线脚本？
   - 哪些部分适合做成标注软件里的规则或 Inspector 面板？
   - 哪些部分只需要生成报告？
   - 哪些部分需要模型参与？

最后，请输出：
1. 方法体系总览；
2. 优先级排序；
3. 最小验证实验；
4. 第一阶段可落地方案；
5. 暂时不建议做的方案及原因。
```

## 与功能开发提示词的区别

这份文档和问题建模提示词的区别如下：

| 文档 | 主要用途 | 代码位置 |
|------|----------|----------|
| `problem_modeling_prompt_guide_restructured.md` | 功能扩展、工程方案、代码落地 | 代码是主线后半段 |
| `annotation_quality_methodology_prompt_guide.md` | 标注质量治理、数据标准、统计诊断、模型辅助、人机流程 | 代码只是最后的工具化环节 |

如果你已经知道要做什么功能，用功能开发提示词。

如果你还不知道应该用规则、统计、模型、流程还是工具来解决问题，用这份标注质量治理提示词。

## 使用原则

使用这份提示词时，重点不是让模型给出一个“看起来高级”的方案，而是让它帮助你建立一套可验证的质量改进路径。

建议始终坚持五个原则：

1. 先定义质量标准，再谈质量提升；
2. 先建立误差类型，再谈检测方法；
3. 先做统计诊断，再决定人工复核重点；
4. 先让模型发现可疑样本，再考虑自动修正；
5. 先做最小验证实验，再做工具化开发。

最终目标不是多写代码，而是让人工、规则、统计和模型形成一个闭环：

```text
标注数据
-> 规则与统计扫描
-> 模型辅助发现可疑样本
-> 人工复核与修正
-> 记录误差类型
-> 更新标准、规则和模型
-> 下一轮质量提升
```
