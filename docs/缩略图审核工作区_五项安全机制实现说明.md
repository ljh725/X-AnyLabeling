# 缩略图审核工作区：五项安全机制实现说明

> 本文依据当前仓库代码编写，说明缩略图审核工作区中五项值得保留的基础机制。本文描述的是已经落地的实现，不是未来方案或理想化流程。

## 1. 文档目的

缩略图审核的表面功能是“把很多矩形框裁成小图，然后批量修改标签”，但真正困难的部分不是显示图片，而是保证以下事情同时成立：

1. JSON 中 Shape 的顺序变化后，仍然能修改正确对象；
2. 用户查看缩略图以后，如果源文件又被修改，旧操作不能覆盖新数据；
3. 后台重建索引失败时，当前可用页面不能被半成品索引破坏；
4. 写 JSON 失败时有备份、可诊断、可恢复；
5. 数据量很大时，翻到后面的页面仍然稳定，不依赖越来越慢的深 OFFSET。

这五项机制共同解决的是一个更高层的问题：

> 缩略图窗口看到的是某一时刻的数据快照，但写回时面对的是可能已经变化的真实文件。系统必须用稳定身份、版本检查、事务写入和稳定分页，把“看到的对象”安全地连接到“最终被修改的对象”。

## 3. 机制一：改对象时认永久 ID，不认数组位置

### 3.1 要解决的问题

标注 JSON 中的 `shapes` 是数组。如果系统记住的是“第 5 个 Shape”，那么下面任何动作都可能让第 5 个位置代表另一个对象：

- 用户删除了前面的 Shape；
- 主画布重新排序了 Shape；
- 外部脚本重写了 JSON；
- 其他功能在数组中插入了新 Shape。

因此，数组下标只能表示某次读取时的位置，不能作为长期身份。

当前实现要求目标 Shape 具有 `xanylabeling_shape_id`，并用它定位对象。代码同时把项目、图片路径、JSON 路径加入完整身份，避免不同文件中出现相同 ID 时发生串改。
