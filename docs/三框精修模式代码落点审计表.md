```text
LabelingWidget
  -> RectRefineWorkflow

       -> RectRefineVisibility

Canvas
  -> 只暴露可见性、编辑门禁、Overlay 绘制适配
```

### 3.5 Canvas 编辑门禁

| 设计点 | 代码落点 | 审计结论 | 实现边界 | 测试落点 |
|--------|----------|----------|----------|----------|
| SELECTING 禁矩形边拖动 | `mousePressEvent()` 1792 先取 `_rect_edge_press_candidate()` | 现有边拖动会在正式选择前抢占鼠标 | 三框 SELECTING 应禁止 `_rect_edge_press_candidate()` 命中 | `tests/test_rect_edge_canvas_semantics.py` 补场景 |
| ACTIVE 只允许工作组成员边拖动 | `_rect_edge_hit_candidate()` 4577，内部用 `is_shape_interactive()` | 可通过有效可见性门控成员 | 不允许非成员 hover、pending、drag | PyQt：非成员边不可 pending |

| 禁方向键整体移动/旋转 | `keyPressEvent()` 5094，`_editing_arrow_dispatch()` 5155，Z/X/C/V 旋转 | 键盘会改 Shape 并进入 undo/dirty | ACTIVE 中 Ctrl+Enter/Esc 以外快捷键需严格分流 | PyQt：方向键不越过工作组约束 |
| Esc 分层 | `Canvas.keyPressEvent()` 5101 先处理 rect-edge Esc | 已有 drag/pending 取消能力 | Workflow 的 Esc 应在 Canvas drag/pending 之后接管工作组回滚 | workflow + PyQt：四级 Esc 优先级 |

### 3.6 undo、dirty 与 auto-save

| 设计点 | 代码落点 | 审计结论 | 实现边界 | 测试落点 |
|--------|----------|----------|----------|----------|
| auto-save 阻断 | `LabelingWidget.set_dirty()` 3296，auto-save 时立即 `save_labels()` | 这是阻断级风险 | 工作组几何变化不能直接走普通 `set_dirty()` 写盘 | test：`auto_save=true` 拖边后磁盘 JSON 不变 |
| 矩形边 release 提交 | `Canvas.mouseReleaseEvent()` 2034，changed 后 `store_shapes()` + `shape_moved.emit()` | 现有 release 会触发 dirty/auto-save | ACTIVE 下应走 workflow 几何提交入口或传递来源标记 | PyQt：ACTIVE 拖边 release 不调用 `save_labels()` |
| dirty 精确恢复 | `set_dirty()`、`set_clean()`、workflow 快照 | 不能回滚后无条件 `set_clean()` | 快照保存 `dirty_before`，回滚后恢复 clean/dirty 语义 | workflow unit test：dirty_before true/false |
| undo floor | `Canvas.shapes_backups`，`store_shapes()` 576，`restore_shape()` 702 | undo 会替换 `self.shapes`，可能使工作组 Shape 引用失效 | ACTIVE 中通用 undo 要被 workflow 限制，不能越过 floor | workflow test：Ctrl+Z 不越过建组前历史 |
| 回滚不能通用撤销 N 次 | `restore_shape()` 会整体替换 shapes 列表 | 通用撤销不适合精确恢复工作组成员 | 回滚应按工作组快照恢复仍存活成员 points，并截断新增备份 | unit test：Esc 后 points 逐点等于初始 |

## 4. 实现期阻断风险清单

以下风险在代码 Review 时应视为阻断级：

1. ACTIVE 工作组内 `shape_moved` 触发 auto-save，导致未通过几何写盘。
2. 任务可见层通过改 `shape.visible` 或 `canvas.visible` 实现，导致导航器和恢复语义污染。
3. 保存取消或失败后释放工作组。
4. Esc 回滚后 dirty 被无条件清空，丢失建组前已有修改状态。
5. 通用 Ctrl+Z 越过工作组 `undo_floor`。
6. 切图、关闭、删除、auto-labeling finish 绕过工作组回滚。
7. 临时工作组字段写入 Shape、`other_data` 或 JSON。
8. Pose overlay、label/text/mask/group/linking 绘制绕过任务可见层。
9. SELECTING 状态下矩形边 press 先于正式选择抢占点击。
10. 使用 QA 磁盘 loader 推导 UI 当前 Shape，导致读到旧 JSON 而不是内存状态。

## 5. 实施顺序建议

建议按以下顺序实现，降低回滚和可见层风险：

1. 纯 Python：`rect_refine_types.py`、`rect_refine_grouping.py`、`rect_refine_visibility.py`。
2. 纯 Python：`rect_refine_workflow.py` 的状态转移、快照、保存结果模型。
3. Canvas：有效可见性函数、编辑门禁、Esc/drag/pending 适配、Overlay 绘制。
4. LabelingWidget：菜单 action、快捷键 action、selection 监听、保存/切图/互斥入口。
5. settings/i18n：配置、schema、runtime shortcut map、翻译资源。
6. PyQt/offscreen 测试与回归测试。

## 6. 收束结论

本轮审计后，代码落点已经足够明确。后续不建议继续做“探索式审计”，而应进入实现与 Review。

实现时必须把四个边界放在第一优先级：

- 未通过不写盘；
- 任务层不污染基础层；
- 主画布和导航器可见性分离；
- Esc、切图、退出和保存失败均保持状态机一致。
