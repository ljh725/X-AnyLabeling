# 三阶段目标框质量校验方案

## 背景

当前数据集包含手动标注的三类检测框与 pose 关键点，核心检测类别为：

- `person`
- `head`
- `face`

现有标注规模约 15916 个 JSON 文件，每天新增检测量约 150-260 张图片。目前主要依赖人工检查，标注质量已有较高保证，但仍希望通过算法工程师的二次校验进一步提高三类水平矩形框的准确度。

本方案的目标不是一开始直接自动改框，而是逐步建立一个低风险、可解释、可扩展的人机协作质检闭环：

```text
阶段一：规则与统计异常筛查
      ↓
阶段二：模型辅助二次校验
      ↓
阶段三：半自动修正与闭环优化
```

## 阶段一：规则与统计异常筛查

### 目标

先不修改标注框，只找出“值得人工复查”的框。

这一阶段成本低、风险低，适合优先落地。已有的高质量历史 JSON 可以作为正常样本库，用于提取三类框的正常分布。

| 项目 | 说明 |
| --- | --- |
| 输入 | 当前 JSON 标注、图片尺寸、label、shape_type、group_id、points |
| 输出 | 问题列表：哪张图、哪个框、疑似什么问题、严重程度 |
| 是否自动改框 | 不改，只标记 suspect |
| 人的角色 | 只复查被系统挑出来的框 |

### 建议检查内容

| 检查类型 | 示例 |
| --- | --- |
| 基础几何 | 框宽高为 0、越界、点顺序异常、非水平矩形、面积过小或过大 |
| 类别形状绑定 | `person`、`head`、`face` 必须是 rectangle 或指定框类型 |
| 空间包含 | `head` 应该在 `person` 内或大部分重叠；`face` 应该在 `head` 内或附近 |
| 比例关系 | `head/person` 面积比异常、`face/head` 面积比异常 |
| 中心位置 | `head` 中心通常位于 `person` 上半部分；`face` 通常位于 `head` 中部附近 |
| group 关系 | 同一个人体实例内的 `person/head/face` 是否 `group_id` 一致 |
| pose 弱约束 | 鼻子、眼睛、耳朵关键点应大致落在 `face/head` 附近，肩膀和身体点应落在 `person` 内 |

### 规则分类

建议将规则分成两类：

```text
硬规则：明显错误
例如框越界、label 为空、points 为空、face 完全远离 head

软规则：统计异常
例如 head/person 面积比落在历史分布的极端区间
```

### 推荐产物

| 产物 | 价值 |
| --- | --- |
| `box_quality_score` | 把多条规则合成一个风险分 |
| 问题类型 taxonomy | 区分越界、偏移、过大、过小、关系异常、group 异常 |
| 复查队列 | 标注员不再逐图看，而是按风险排序看 |
| 日报统计 | 统计每天图片数、框数、suspect 数量、主要问题类型 |

### 阶段验收标准

- 每天 150-260 张图中，系统能筛出前 10%-30% 高风险样本。
- 即使存在误报，也要让标注员能快速跳过。
- 不允许自动修改原始标注。
- 每个问题都要说明触发原因，否则人工很难信任系统。

## 阶段二：模型辅助二次校验

### 目标

让检测模型参与复核，但仍不直接覆盖人工标注。

阶段一依赖规则和历史分布，适合抓结构性错误；但对于框轻微偏移、框过松、框过紧等问题，检测模型通常更有帮助。

| 项目 | 说明 |
| --- | --- |
| 输入 | 图片、人工框、模型预测框、模型置信度 |
| 输出 | 人工框与模型框的差异报告 |
| 是否自动改框 | 默认不改，只生成建议框 |
| 人的角色 | 查看人工框和模型框差异，决定是否接受建议 |

### 核心比较指标

| 指标 | 用途 |
| --- | --- |
| IoU | 判断模型框与人工框的重叠程度 |
| 中心点距离 | 判断框是否整体偏移 |
| 宽高差 | 判断框是否过松或过紧 |
| 面积比 | 判断模型框和人工框尺度是否差异过大 |
| 类别一致性 | 判断模型是否发现漏标、错标 |
| 置信度 | 判断模型建议是否值得信任 |

### 判断原则

不要简单认为“模型和人工不一致就是人工错”。更稳妥的判断方式是：

```text
人工框符合历史分布 + 模型低置信
=> 大概率模型不可靠

人工框违反规则 + 模型高置信 + 多个信号指向相似位置
=> 高优先级复查

人工框和模型框 IoU 较低，但两者看起来都合理
=> 可能是边界规范不清，需要回到标注规范层面统一标准
```

### 样本分层

| 类型 | 处理方式 |
| --- | --- |
| 高一致 | 人工框和模型框接近，低优先级 |
| 模型怀疑 | 模型与人工差异大，但模型置信一般，进入普通复查 |
| 高风险冲突 | 模型高置信且规则也提示异常，优先复查 |
| 规范不清 | 多次出现同类边界差异，需要更新标注规范 |

### 推荐界面形态

```text
左侧：原人工框
右侧：模型建议框
下方：IoU / 中心偏移 / 面积差 / 触发规则
操作：接受建议 / 保留人工 / 手动微调 / 标记规范问题
```

### 阶段验收标准

- 能发现阶段一较难发现的轻微偏移、框松紧不一致等问题。
- 模型建议必须可解释，至少显示差异指标和触发原因。
- 所有人工选择都应记录下来，后续用于评估模型二检效果。
- 不追求 100% 自动化，优先追求减少人工查看无问题图片的数量。

## 阶段三：半自动修正与闭环优化

### 目标

从“发现问题”进入“高效修正”，但仍保留人工最终确认权。

这个阶段才真正处理水平矩形框准确度调整。它应建立在阶段一和阶段二之上，否则容易变成不可靠的自动改框器。

| 项目 | 说明 |
| --- | --- |
| 输入 | 人工框、模型建议框、规则建议、历史分布、人工反馈 |
| 输出 | 被确认的新框、修改记录、质检状态 |
| 是否自动改框 | 可一键接受，但不建议无确认批量覆盖 |
| 人的角色 | 最终裁决者，从画框者变成审核者 |

### 可提供的修正方式

| 修正方式 | 说明 |
| --- | --- |
| 一键采用模型框 | 模型高置信且规则支持时使用 |
| 几何吸附 | 将 `face/head` 自动限制或吸附到合理范围，例如 `head/person` 内 |
| 边界微调建议 | 只建议左、右、上、下某条边移动，而不是整体替换框 |
| 批量同类修正 | 对同一类稳定错误生成批量建议，例如 `face` 框普遍偏大 |
| 相似样本迁移 | 对相似姿态、相似尺度的人体实例，复用历史修正模式 |
| 快捷确认流 | 使用快捷键接受、保留、微调，提高复查效率 |

### QA 状态流

建议引入 QA 状态，而不是只保存最终 points：

```text
unchecked
  ↓
suspect
  ↓
suggested
  ↓
human_confirmed
  ↓
locked
```

### 推荐附加字段

| 字段 | 作用 |
| --- | --- |
| `qa_status` | 当前质检状态 |
| `issue_codes` | 触发的问题类型 |
| `suggestion_source` | 建议来自规则、模型、统计还是人工 |
| `before_points` / `after_points` | 修改前后对比 |
| `reviewer` | 谁确认的 |
| `reviewed_at` | 什么时候确认 |
| `decision` | `accepted`、`rejected`、`adjusted` |

这些信息会让数据集从“只有标注结果”升级成“有质量过程记录”。长期看，它可以帮助回答：

- 哪类错误最多？
- 哪个规则误报最多？
- 哪个模型建议最可靠？
- 哪些图片被人工确认过？
- 哪些修改可以作为下一轮训练数据？

### 阶段验收标准

- 标注员主要做确认和微调，而不是从头画框。
- 每次修正都有来源和记录。
- 高置信建议可以批量预览，但不默认静默覆盖。
- 修正结果能反哺阶段一的规则阈值和阶段二的模型评估。

## 三阶段关系

```text
阶段一：先会发现问题
规则 + 统计异常
      ↓
阶段二：再会提出候选答案
模型二检 + 差异指标
      ↓
阶段三：最后提高修正效率
半自动调整 + 人工确认 + 反馈闭环
```

## 推荐落地顺序

建议优先做阶段一，尤其是 `person/head/face` 的 group 级空间约束和历史分布异常检测。它最便宜、最稳，也最适合接入当前 Inspector 模块。

之后做阶段二，把算法工程师的模型输出接进来，但只作为建议框和风险信号。

最后做阶段三的一键接受、边界微调、QA 状态流。这样不会破坏已有高质量标注，也能逐步把每天纯人工检查变成高效的人机协作质检流程。
