# Inspector 检查与复核

从 **工作流 → Inspector** 打开检查窗口。Inspector 查找已有标注中的规则疑点；检查清零不表示没有漏标，也不会自动把图片设为审核通过。

## 第一次用，照着做

把 Inspector 当成“帮你找可疑标注的检查员”。比如空标签、框坐标不对、两个框可能画重复了，
它会列出来，让你自己决定怎么处理。

1. 打开图片文件夹，确认标注输出目录正确。
2. 打开 **工作流 → Inspector**，方案先选“通用矩形检查”，范围先选“当前图片”。
3. 点“开始检查”。问题列表出来后，选中问题，按 Enter 定位到图上；看右侧证据。
4. 确实画错了，就回画布改框、改类或删除；没错就标“误报”或“可接受”。
5. 改完点“复查当前图”，再正常保存标注。检查结果为零也要自己看有没有漏画。
6. 单张用顺后，再把范围切到“整个数据集”做批量检查。

### 扫描进度在哪里

窗口顶部显示进度条和正在处理的文件名。先查找图片：总数还不知道时，显示“已找到 N 个”；
接着读取图片和标注清单，显示“扫描文件 N/总数”；最后执行规则，显示“检查 N/总数”。
扫描与检查是两个阶段，进入检查时计数会重新开始。进度条统计文件数，不估算剩余时间。
文件名太长时可悬停查看完整路径；取消运行不等于检查完成。

### 到底查了哪些规则，怎么改

方案下方直接显示启用的规则。点 **查看规则与参数**，可看全部规则、启用勾选和参数；
鼠标停在规则名称或参数格上可看说明。这个查看窗口不会修改方案。

想修改：**复制方案 → 给副本起名 → 编辑规则 → 勾选或取消规则、修改参数 → 保存 → 重新检查**。
内置方案是模板，不能直接改；自定义副本可以反复编辑，每次保存增加版本。
关掉一条规则只是以后不查这一项，不表示旧问题已经修好。

参数格填写 JSON，例如下面三种要分别填到对应规则，不能整段混填：

| 你想改什么 | 对应规则 ID | 参数示例 |
| --- | --- | --- |
| 要求 `person` 必须画矩形，`head` 必须画多边形 | `shape_type_binding` | `{"expected_types":{"person":"rectangle","head":"polygon"}}` |
| 要求某些类别填写分组编号 | `group_id_required` | `{"labels":["person","head"]}` |
| 设置疑似重复框检查 | `duplicate_boxes` | `{"preset":"medium","max_pairs":5000,"relations":{}}` |

把示例里的类名换成你项目中的实际类名，大小写也要一致。`{}` 代表没有额外参数，
不是所有规则都会自动猜出你的业务要求。要增加一种程序还没有的检查逻辑，需要开发新规则；
编辑参数只能调整已登记规则。

## 日常处理

1. 打开图片目录和需要使用的标注输出目录。在 Inspector 选择方案、阶段和范围，展开说明确认实际启用的规则。初次使用先选“当前图片”。
2. 点击“开始检查”。默认 `F5` 开始、问题表内 `Enter` 定位；可在设置的快捷键中修改或清空。与画布已有键冲突的绑定不会启用。
3. 查看问题证据，再选择“误报”“确认错误”“可接受”或“疑难暂存”。重复框可“保留两者”；删除、改类之前，先在画布选中要处理的具体对象。批量操作先展示准确对象集合，确认后才修改。
4. 用原有画布方式调框、改类、撤销或重做。编辑后结果变为待复查；点击“复查当前图”，只有相关规则成功完成且未截断，才能记为本次未再检出。取消、失败或停用规则都不能证明问题已解决。
5. 按正常流程保存标注。之后可“继续上次处理”或选择历史运行，恢复筛选及问题位置；数据、图片、输出目录或方案变化时，旧证据仅供查看，需要重新检查。

当前图检查读取已提交的画布内容，可以包含尚未保存的修改。整批检查读取磁盘；遇到未保存图片时，可选择先保存、排除或取消。保存失败不会继续批量检查。“已变更文件”会核对标注、图片、方向和规则配置；无法可靠判断时保守检查全部文件。

## 状态与范围

| 状态 | 含义与处理 |
| --- | --- |
| 当前 | 证据对应当前检查输入；仍需人工判断 |
| 待复查 | 内容已编辑或声明修改，需要再次执行相关规则 |
| 未再检出 | 对本次成功检查的相关来源未再命中；保留历史，不代表整图合格 |
| 过期／不可核验 | 输入、版本或来源不能对应；核对原因后重新运行 |
| 截断／部分完成 | 只覆盖已明确记录的范围；缩小范围或调整上限后继续 |

问题、对象、问题图片和请求图片分别计数。同一对对象命中多条规则时合并展示，但保留每个来源的证据。问题表每页最多 200 条，使用上一页／下一页继续，交接返回时恢复原问题位置。

## 建立项目方案

内置模板保持只读。先“复制方案”，再改名或编辑规则；每次保存形成新版本。导入内置模板或同 ID 的方案会形成新副本，避免覆盖已有方案。停用不删除历史报告。

编辑器按规则填写 JSON 参数。以“疑似重复框”为例：

```json
{
  "preset": "medium",
  "max_pairs": 5000,
  "relations": {"person|head": "allowed_containment"}
}
```

这个例子只适用于项目明确允许人框包含头框的情况，不应直接作为其他项目的规范。关系可选 `mutually_exclusive`（互斥）、`allowed_coexist`（允许共存）、`allowed_containment`（允许包含）、`unknown`（未确认）。没有配置业务关系时，跨类重叠只提示人工判断。

屏幕角点方案需填写四种角点标签、屏幕主体标签及可信实例关联；缺少配置、遮挡信息或整个实例均未标注时，不能根据数量相等认定没有漏标。

## 外部候选与密集复核

“导入候选”读取已有模型结果，不运行推理或下载模型。候选在独立覆盖层显示，正式对象数量保持不变。每条候选需要明确图片路径、尺寸、类别和矩形坐标，可附来源版本、方向与分数。

- “调整后接受”先预览、修改坐标或类别，确认后才创建正式对象；取消不改标注。
- “接受候选”创建待保存对象，“批量接受”先预览准确集合。拒绝或暂存不删除原标注。
- 接受意图先保存，正式标注成功落盘后才确认持久关联。保存失败、重复点击、撤销、重做或重新打开，都要核对对象身份；缺失对象不会自动重新画出。
- 图片被替换、尺寸或方向变化、类别不合法时，先重新核验候选；来源分数不等于正确率。

已提供密集复核工作区时，可“交接密集复核”查看对象或扩大区域，再返回原问题。不可用时仍可用普通画布处理。Inspector 判断、对象复核、独立空间查漏与正式审核分别保存，互不代替。

## 报告保存与恢复

运行报告、人工反馈、会话及候选关联保存在标注目录下的 `.xanylabeling/inspection/`，按数据集隔离；主目录不可写时程序使用本机回退位置。它们不写入训练标注 JSON。候选接受后新增的正式对象使用正常标注保存流程。

报告保存失败时，当前窗口保留结果。用“另存检查报告”选择可写目录，保存完整报告及输入清单；保留显示的保存位置。重开后使用“打开报告保存位置”选择当时的目录，核验输入后继续。导出 JSON 保留完整多来源证据，TSV 为简化格式，不能代替完整报告。

备份时同时保留图片、标注和对应检查目录。关闭或回退 Inspector 不需要删除检查记录，也不要覆盖用户已保存的标注。未知格式、损坏文件或会话冲突应保留原文件；根据界面提示重新运行或重试保存，不手动清空记录来消除提示。

两位使用者的对照试用与独立质量复核仍须另行开展；自动化测试通过不能代替减负效果或质量验收。
