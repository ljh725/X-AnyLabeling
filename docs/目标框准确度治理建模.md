## 1. 核心诊断（全文脊椎）

### 1.1 已完成的工作停留在哪一层

当前已完成的校验是：

1. 三类标签名检查（person / head / face 名字合法）；
2. 三类标签 `group_id` 统一（同一实例的三类共享 gid）。

这两项**全部属于"元数据 / 结构完整性"层**——它们只验证标签的"身份"和"分组关系"，**完全不触及框在图像里的几何位置**。

### 1.2 现有 Inspector 规则的代码事实

对 Inspector 模块现有 **11 条内置规则**逐条核对后，结论是：

> **没有一条规则做坐标几何。**

现有规则只读取以下字段：`label`、`shape_type`、`group_id`、`flags`、`points_count`（点的个数，不是坐标）。

这意味着，下面这些情况**全部能通过现有所有规则**：

- 一个 person 框整体向右偏移 200 像素；
- 一个 face 框的面积是应有值的 2 倍；
- 一个 face 框根本不在它同组的 head 框里；
- 一个 person 框宽 2 像素、高 800 像素（退化/畸形）；
- 同一图像里两个几乎重叠的 head 框。

### 1.3 根因：坐标未入库

`FlattenedRecord`（扁平记录）当前**只存 `points_count`，不存坐标本身**。坐标在扫描时被解析，取完长度后即丢弃。

因此，"框准确度"这个维度，目前在自动化校验层面是**完全未接入的空白**。

### 1.4 问题被重新定义

原本的问题表述是"还有什么方法可以调整框准确度"。经过建模，它被重新定义为：

> **当前做的是 schema（模式）校验，真正需要的是进入 position / semantic（位置 / 语义）校验。**
>
> 精度提升的空间几乎全部在这块空白里。

这个重新定义决定了后续所有分析的方向：不是"再加几条规则"，而是**补上一个全新的校验维度**。

## 第 1 层 · 业务目标层

### 1.1 真正要提升的质量目标

质量目标**不是**"违规数下降"或"问题框变少"这些过程指标。

真正的目标是：

> **person / head / face 三个框的边界，与视觉真值紧密、一致地对齐。**

对检测器而言，回归目标的系统性偏置比标签名错误危害更大：

- 标签名错只毁**一个样本**；
- **系统性的框偏移会污染整个类的回归目标**——模型学到一个稳定的"错误偏差"，这是最难发现、最难修复的伤害，因为统计分布看起来很"正常"（见第 5.3 节反直觉点）。

### 1.2 三类优先级（按维度拆开，不混在一起）

把"优先级"当作单一排序是错误的——不同错误类型对不同类的伤害不同：

| 维度 | 优先级排序 | 理由 |
|------|-----------|------|
| 边界紧密度（tightness） | **face > head > person** | 框越小，同样的像素误差 = 越大的相对误差；face 最小最敏感，松框直接打垮高 IoU 阈值下的 mAP |
| 完整性 / 是否漏标 | **person > head > face** | 漏一个 person = 整张训练样本作废（假阴性）；face 漏标危害相对小 |
| 标注员间一致性 | **face > head > person** | person 框本就允许形态多变（站/坐/躺），face 尺寸小且形态稳定，标注员间不一致最致命 |

**结论**：face 在紧密度和一致性两个维度上都是最高优先级，但 person 在完整性上最高。**不要笼统地说"face 最重要"或"person 最重要"。**

### 1.3 按危害排序的错误

| 排序 | 错误类型 | 危害机制 |
|------|---------|----------|
| 1 | **系统性偏移**（整类一致偏上 / 偏大） | 回归目标带偏置，最难发现、最难修复 |
| 2 | **系统性过松**（整类框偏大） | 模型永远学不会紧框，高 IoU 阈值下 mAP 崩塌 |
| 3 | **标注员间紧密度不一致** | 标签噪声，face 上尤其不可收敛 |
| 4 | **包含关系断裂**（face ⊄ head） | 破坏下游 grouping / re-ID |
| 5 | 漏标 / 多标 | 直接卡住 recall / precision 上限 |
| 6 | 关键点误差 | 已声明低优先级，**但见第 5.3 节**：关键点可作为校验真值 |

## 第 2 层 · 数据标准层

### 2.1 "水平矩形框准确"的可操作定义

不先定义"什么叫准确"，复核就没有判据。建议落地为：

> 一个框准确 ⟺ 同时满足：
> 1. **轴对齐且非退化**（xmin < xmax, ymin < ymax，且尺寸合理）；
> 2. **贴合物体可见外接范围**，符合该类的 margin 策略；
> 3. **满足嵌套类别的包含契约**（见 2.3）。

### 2.2 三类边界定义

| 类别 | 边界范围 | 比例规则 |
|------|---------|----------|
| **person** | 可见全身外接（头顶 → 脚底，可见肩宽），允许图像边缘截断 | **必须宽松**（站立瘦高、蹲坐方正都合法）——给 person 设窄 aspect 区间会误报爆炸 |
| **head** | 颅顶 / 头发外缘 → 下颌 / 下巴，耳到耳 | 应**大于并包含** face 框 |
| **face** | 眉 / 发际 → 下巴，颊到颊（或可见面部范围） | 应**小于并被** head 框**包含** |

### 2.3 核心契约（目前完全未强制）

> **`face ⊂ head ⊂ person`**（允许 margin）

这是本数据集**最高价值的关系标准**，而当前在自动化层**零强制**。

一旦把它写成可校验规则，能立刻捞出一大批定位问题：face 框跑到 head 框外、head 框跑到 person 框外、face 比 head 还大……这些都是典型的高价值、低误报的可疑样本来源。

### 2.4 可接受偏差 vs 必须修正

不要靠拍脑袋定阈值。原则：

- **用历史高质量库统计出每类的容差带（normal band）**；
- 带内 = 可接受偏差 → 自动放行；
- 带外 = 必须修正 → 进入复核队列。

这正是三阶段方案阶段一"软规则 + normal-sample library"的思路，成立。本文补充的是：**容差带应按"几何特征（面积比、中心偏移、IoU）"分别建模，而不是给一个笼统的容差数字。**

## 第 3 层 · 误差建模层（框误差类型体系）

将误差组织为 **5 个族**，每类标注：可观察症状、发现方法、**今天能否检测**（"今天否"的根因统一是坐标未入库）。

### 3.1 几何畸形

| 误差类型 | 可观察症状 | 发现方法 | 今天可检测? |
|---------|-----------|---------|------------|
| 框偏大 | 面积落在该类历史分布极端尾部 | 面积分位数 | 否（需 points） |
| 框偏小 | 面积落在另一极端尾部 | 面积分位数 | 否 |
| 宽高比例异常 | aspect 远离该类常态 | aspect 分布 | 否 |
| 退化框 | w/h ≈ 0、xmin > xmax、两点重合 | 坐标健全性检查 | 否 |

### 3.2 位置偏差

| 误差类型 | 可观察症状 | 发现方法 | 今天可检测? |
|---------|-----------|---------|------------|
| 框中心偏移 | 框中心 vs 关键点质心（鼻 / 眼）偏离大 | **用关键点做免费定位真值**（见 5.3） | 否 |

### 3.3 关系异常

| 误差类型 | 可观察症状 | 发现方法 | 今天可检测? |
|---------|-----------|---------|------------|
| 包含关系异常 | face ⊄ head / head ⊄ person | per-group IoU + 中心包含 | 否 |
| 面积比异常 | face/head 或 head/person 比值越界 | per-group 比值分布 | 否 |
| 同组空间错位 | 关键点落到 person 框外 | keypoint-in-box | 否 |

### 3.4 完整性

| 误差类型 | 可观察症状 | 发现方法 | 今天可检测? |
|---------|-----------|---------|------------|
| 漏标 | person 组缺 head/face；场景有人无框 | 组完备性 + 密度 | 部分（group 层有结构信息） |
| 多标 | 同类近重复框、幽灵框 | 同组 / 同图 IoU | 否 |
| 类别错标 | 空间上像 head 却标 face（name 校验抓不到） | 尺寸 + 位置启发 | 否 |

### 3.5 边界争议

| 误差类型 | 可观察症状 | 发现方法 | 今天可检测? |
|---------|-----------|---------|------------|
| 遮挡 / 截断 | 框合理地贴边或伸入遮挡物 | 边缘触碰检测 | 否 |

> ⚠️ **"边界争议"不是错误**——它应走"规范不清"通道去更新标准（见第 6 节、反直觉点 3），而不是当 bug 修。混为一谈会浪费复核工时并污染 normal library。

## 第 4 层 · 统计诊断层

### 4.1 目标

从 15916 个文件里捞出高风险子集，**不全量复检**。

### 4.2 应统计的特征

- **单框**：面积、aspect、边缘触碰（截断）、中心坐标
- **per-group**：`IoU(face⊂head⊂person)`、面积比、关键点是否落在对应框内、中心对齐度
- **per-image**：框数、各类计数、密度、每个 person 是否三类齐全

### 4.3 流程

用历史高质量子集建立 normal 分布 → 当前样本落在尾部即为可疑 → 这正是三阶段方案阶段一的"normal-sample library"思路，成立。

### 4.4 风险分级

| 级别 | 触发条件 | 处置 |
|------|---------|------|
| **高风险（硬异常）** | 退化框 / 出界 / face ⊄ head / head ⊄ person / face > head / 重复框 / 组缺成员 | **必须复核** |
| **中风险（统计尾）** | aspect / 面积 / 比值在极端分位、中心偏移超带、与邻居高 IoU | **抽样复核** |
| **低风险** | 带内 + 结构干净 | **自动放行** |

### 4.5 一个提醒

三阶段方案提出的 `box_quality_score`（复合风险分）有用，但**单一分数会掩盖具体问题**。

优先做 **issue-coded（按问题类型编码）的分级 → 优先级队列**，复合分只作为排序辅助。否则复核者看到一个"质量分 0.62"并不知道该看什么。

## 第 5 层 · 模型辅助层

### 5.1 角色定位（强调）

> 模型是"第二意见 / 怀疑生成器"，**不是真值，不覆盖人工标注**。

三阶段方案阶段二已定调，本文完全认同，不再展开 6 个比较指标（IoU / 中心距离 / 宽高差 / 面积比 / 类别一致性 / 置信度）。

### 5.2 三种判据（解读模型分歧的规则）

明确反对"模型与人工有分歧 = 人工错"。判据如下：

| 情形 | 判定 |
|------|------|
| 人工框符合历史分布 + 模型低置信 | 信人工，模型可能不可靠 |
| 人工框违反规则 + 模型高置信 + 多信号指向同一位置 | 高优先级复核 |
| 低 IoU 但双方都合理 | **规范不清**，回到数据标准层（反直觉点 3） |

### 5.3 反直觉点：关键点作为免费定位真值

这是本文相对三阶段方案的**关键补强**。

虽然 pose 关键点作为"质量目标"优先级低，但作为**校验真值**极其有用：

- **鼻 / 眼关键点落在 face 框内** → face 框定位正确的强证据；
- **耳关键点落在 head 框附近** → head 框定位正确的强证据；
- 关键点落到对应框**外** → 框可疑。

这比模型 diff **更便宜、更可信**，专门解决 face / head 定位问题。

**含义**：把"关键点 vs 框"的一致性检查，做成一个**不依赖模型**的离线校验项。它翻转了"pose 低优先级"的认知——关键点作为目标不重要，但作为校验工具极其有用。

### 5.4 多模型投票先缓

多模型投票成本高，性价比第一步是：**一个好检测器 + 关键点 oracle**。

## 第 6 层 · 人工复核流程层

### 6.1 规模约束

150–260 张 / 天是硬约束。流程设计原则 = **最小负担、最高信号**。

### 6.2 三队列

| 队列 | 来源 | 处置 |
|------|------|------|
| **必须复核** | 第 4 层高风险硬异常 | 全做（量少、信号强） |
| **抽样复核** | 中风险尾部 + 模型分歧 | 抽 10–20% |
| **自动放行** | 低风险、带内、结构干净、模型同意 | 不看 |

### 6.3 降负担的三个关键

1. **给复核者直接看原因**。例如："face 框中心比 head 框中心高 40px；鼻关键点在 face 框外"——别让复核者重新推导问题。三阶段方案"每个问题必须解释触发原因"是对的，这里再细化到具体话术。
2. **队列按问题类型聚类排序**。同类问题连看，复核更快，且能嗅出**标注员的系统性偏差**（反直觉点 2）。
3. **键盘驱动的 接受 / 保留 / 微调**。从画框者变成审核者（三阶段方案阶段三的提法）。

## 第 7 层 · 工具化实现层

### 7.1 最关键的技术前置（必须先讲）

> `FlattenedRecord` 当前不存坐标、不存图像尺寸。
>
> **不补这个字段，第 3–6 层没有任何一条能落地。**

这是地基。好消息是这只是给记录加 `points` + `width` / `height` 几个字段，低风险改动。

### 7.2 落地分工

| 载体 | 适合做 | 对应阶段 |
|------|--------|---------|
| **离线脚本** | 跨文件分布统计、normal library 提取、日报、模型 diff 批算 | 阶段一 / 二，最先做，跑 15916 很快 |
| **Inspector 规则 / 面板** | per-group 硬关系（face⊂head⊂person、面积比、关键点落框）、退化框、出界 | 阶段一，**完美契合现有 `check_all` + `_by_group` 索引** |
| **报告** | 复合风险分、风险分级队列、每日统计 | 无需做成实时规则 |
| **模型参与** | 模型框 vs 人工框 diff | 阶段二，最后 |

### 7.3 推荐顺序（对齐三阶段方案）

1. 补 `FlattenedRecord` 的坐标 + 图像尺寸字段；
2. 加 per-group 关系硬规则（face⊂head⊂person）+ 退化 / 出界检查；
3. 离线统计与报告；
4. 再上模型 diff；
5. 最后半自动修正。

### 7.4 架构兼容性

现有引擎的 `check_all(self, index)` 模式 + `_by_group` / `_by_file` 索引，**天然支持关系规则**，不需要结构性重构。

## 三个反直觉点（单独成节）

这三点是最容易被团队忽略、也最影响决策质量的认知：

### 反直觉点 1：关键点是免费真值，不是低价值目标

原始诉求声明"pose 关键点精度不做过高要求"。这个声明对**质量目标**成立，但被错误地延伸到了**校验工具**层面。

关键点作为校验真值校验 face / head 框定位，**成本为零、可信度高于模型 diff**。翻转这个认知，能多出一个不依赖模型的校验维度。

### 反直觉点 2：系统偏差对统计检查隐形

当一个类整体一致地偏大 / 偏移时，统计分布看起来很"正常"——因为偏差是系统性的，不构成离群点。

这意味着：**统计检查干净 ≠ 没有系统偏差**。

这是"为什么统计筛查之后仍需要模型辅助"的硬理由。系统偏差只能靠**外部参照**（模型 diff 或关键点 oracle）发现，单靠自身分布抓不到。

### 反直觉点 3："规范不清"不是 bug，是治理动作

反复出现的同类边界分歧（例如多个标注员对 face 下边界画在哪不一致），本质是**标注规范未定义清楚**，不是标注员的错误。

如果把它当 bug 一个个修，会：
- 浪费复核工时；
- 污染 normal library（带主观判断）；
- 修完后同类问题继续出现。

正确做法：把它路由回**数据标准层**，更新契约，让后续标注与复核有统一判据。
