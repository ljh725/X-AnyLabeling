# 跨图对象标记与对象级改标

本文档说明「先标记、后改标、再确认」的对象级批量改标流程。入口位于
**Tool（工具）菜单**，包含三个动作：

| 动作 | 行为 |
|------|------|
| 跨图对象标记（可勾选） | 开启/暂停标记手势；关闭开关**不清空**已有标记 |
| 清空跨图标记 | 移除全部活动标记，不修改任何标注文件 |
| 修改已标记对象的标签…… | 唯一的改标入口，走统一预检与安全提交流程 |

## 使用流程

1. **标记**：勾选「跨图对象标记」后，在画布上单击对象即可加入标记，
   再次单击取消。橙色虚线外框表示当前图片的标记对象。标记跨图片保留：
   切换到其他图片再返回后，标记视觉自动恢复。标记仅存在于当前软件会话，
   **不会写入标注 JSON**。预选、悬停或缩放引起的重复重绘不会改变外框
   尺寸，也不会修改对象几何。
2. **改标**：选择「修改已标记对象的标签……」：
   - 若当前图片有未保存修改，先弹出保存提示；保存失败或取消会中止
     整个改标并保留全部标记。
   - 选择一个目标标签（候选来自项目标签列表，也可输入新标签）；取消
     选择不会创建任何事务。
   - 系统读取磁盘上的目标 JSON 做严格预检，显示目标标签、快照对象数、
     涉及文件数、可修改、已是目标标签、已删除、身份冲突、读取失败数量。
     确认后才进入暂存与提交。
3. **提交**：提交阶段为原子替换且不可取消；预检与暂存阶段可以取消，
     取消不写任何文件、标记全部保留。预检确认期间进度框会暂时隐藏；
     流程结束后进度框关闭，结果只提示一次。

## 与全局标签重命名（Label Manager）的区别

| | Label Manager 重命名 | 跨图对象改标 |
|---|---|---|
| 选择单位 | 标签（字符串） | 具体对象（`xanylabeling_shape_id`） |
| 影响范围 | 数据集中**所有**该标签对象 | 仅被标记的对象 |
| 匹配依据 | `label` 字段相等 | `(project_id, image_id, xanylabeling_shape_id)` 完整键 |
| 同标签邻居 | 一并改名 | 不受影响 |

即使对象在标记后被移动、改名、改属性或数组重排，改标仍按持久
`xanylabeling_shape_id` 定位；对象已被删除则报告「已删除」并跳过。
同文件出现重复/非法目标 ID 时整文件报告「身份冲突」并保持不变。

## 结果与重试

结果按对象分类：成功、无变化（已是目标标签，同样移除标记）、已删除
（移除标记）、身份冲突 / 失败 / 取消（保留标记，可直接重试）。结果对话
框显示恢复清单（manifest）路径。

从恢复清单回滚有两种方式：**Tool → 从恢复清单还原对象改标…**
（选择事务目录中的 manifest.json），或直接调用
`LabelingWidget.restore_object_relabel_manifest(manifest_path)` /
`JsonTransactionEngine.restore()`（与全局标签迁移共用同一事务恢复机
制；旧版 manifest 同样兼容）。

## 并发边界

- 同一数据集同时只允许一个批量写事务：对象改标与 Label Manager 全局
  迁移通过 `BatchWriteGate` 互斥；提交阶段另持有数据集写锁
  （`DatasetWriteCoordinator`）。
- 项目根使用导入目录（或图片集合的规范化共同根），因此递归多目录数据集
  的对象改标和全局迁移使用同一个互斥键。
- 提交前会复核源文件指纹；预检后被外部修改的文件将被拒绝覆盖并报告
  失败，对应对象标记保留以便重试。
- 从恢复清单还原前会先处理当前图片的未保存内容，并在恢复后刷新成功文件
  对应的 Dataset Index。

## 已知局限

- **Shape Manager 的区间删除**仍是历史直写路径（无事务、无写锁），但
  操作完成后会扫描并清理已经不存在的跨图对象标记；对象改标提交期间仍应
  避免使用该功能修改受影响文件。
