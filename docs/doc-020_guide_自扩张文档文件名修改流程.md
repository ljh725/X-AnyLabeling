# 自扩张文档文件名修改流程

> 适用范围：`docs/` 中由二次开发、报错修复、功能扩展、AI 协作生成的文档。
> 不适用范围：项目原生用户文档，例如 `docs/en/`、`docs/zh_cn/`。

## 一、目标

在不做大规模文件夹分类的前提下，通过文件名编码让同一功能、同一系列、同一阶段的文档在文件管理器中自然靠近，便于人工浏览、版本追溯和 AI 检索。

核心原则：

1. 文件名承担“主分类 + 排序 + 文档类型”的职责。
2. 跨分类信息放到索引文档中，不强塞进文件名。
3. 改名必须保留 git 历史，优先使用 `git mv`。
4. 每次只处理一个功能域，避免一次性大规模重命名失控。

## 二、推荐命名格式

```text
<领域码>-<三位序号>_<类型码>_<版本或日期>_<中文标题>.md
```

目标文件名中的英文字母统一使用小写；旧文件名按真实原名记录。

示例：

```text
qc-040_spec_v0_阶段一l1_l2质检规则阈值与输出规格.md
qc-051_des_v1_阶段一l1_l2质检方案_问题建模.md
qc-060_task_阶段一l1_l2质检实现任务文档.md
cls3-010_task_矩形边对齐功能实现任务文档.md
pose-020_impl_2026-06-16_姿态视图与自动聚焦实现总结.md
```

字段说明：

| 字段 | 说明 | 规则 |
|------|------|------|
| 领域码 | 功能或文档治理域 | 使用大写英文，保持稳定 |
| 三位序号 | 同领域内排序 | 从 `010` 开始，以 `10` 递增，方便插入 |
| 类型码 | 文档性质 | 使用固定枚举，避免自由命名 |
| 版本或日期 | 可选演进信息 | 有明确版本用 `v1`，有明确时间用 `YYYY-MM-DD` |
| 中文标题 | 人类可读标题 | 保留原语义，尽量短，不放重复分类词 |

## 三、领域码建议

| 领域码 | 范围 |
|--------|------|
| `doc` | 文档治理、文件命名、索引维护 |
| `qc` | l1/l2 质检、标注质量、阈值、复核队列 |
| `cls3` | 矩形框类别相关：矩形边编辑、边对齐、三框精修 |
| `pose` | 姿态视图、关键点、pose 标签 |
| `filter` | 筛选、选择、数据集索引、导航 |
| `canvas` | canvas 架构、鼠标事件、视口状态 |
| `inspect` | inspector 面板、外部结果导入 |
| `meth` | 方法论、prompt、问题建模、上下文净化 |
| `test` | 测试矩阵、验收清单 |
| `fix` | 零散修复、性能问题、卡顿分析 |
| `arch` | 历史归档、过期方案、一次性产物 |

如果某篇文档同时属于多个领域，只选择最主要的领域码，副分类写入 `docs/doc-010_spec_文件分类清单.md`。

## 四、类型码建议

| 类型码 | 含义 |
|--------|------|
| `req` | 需求、需求修订 |
| `des` | 设计方案、交互方案、架构方案 |
| `spec` | 规则规格、接口规格、输出规格 |
| `task` | 实现任务、拆解清单 |
| `impl` | 实现说明、代码构建说明、实现报告 |
| `review` | 审核结论、review 清单 |
| `fix` | 修复报告、故障追溯 |
| `summary` | 完成总结、阶段总结 |
| `guide` | 使用说明、操作指南 |
| `note` | 分析笔记、疑问清单、备忘 |

## 五、改名前准备

1. 确定本批次只处理一个领域，例如只处理 `qc` 或只处理 `cls3`。
2. 从 `docs/doc-010_spec_文件分类清单.md` 取出对应文件列表。
3. 为每个文件确定：
   - 主领域码
   - 排序号
   - 类型码
   - 是否保留版本号或日期
   - 新中文标题
4. 建立改名映射表，建议临时写在 `docs/doc-010_spec_文件分类清单.md` 的执行区中。

映射表模板：

```markdown
| 状态 | 旧文件名 | 新文件名 | 备注 |
|------|----------|----------|------|
| 已改 | 阶段一L1_L2质检规则阈值与输出规格_v0.md | qc-040_spec_v0_阶段一l1_l2质检规则阈值与输出规格.md | 阈值规格 |
| 已改 | 阶段一L1_L2质检实现任务文档.md | qc-060_task_阶段一l1_l2质检实现任务文档.md | 实现任务 |
```

## 六、改名执行流程

### 1. 生成当前文件清单

```powershell
$ErrorActionPreference = 'Stop'
Get-ChildItem docs -File | Select-Object Name | Sort-Object Name
```

### 2. 检查目标文件名是否冲突

改名前逐个确认新文件名不存在：

```powershell
$ErrorActionPreference = 'Stop'
Test-Path 'docs\qc-040_spec_v0_阶段一l1_l2质检规则阈值与输出规格.md'
```

返回 `False` 才能使用该目标名。

### 3. 使用 `git mv` 改名

```powershell
$ErrorActionPreference = 'Stop'
git mv 'docs\阶段一L1_L2质检规则阈值与输出规格_v0.md' 'docs\qc-040_spec_v0_阶段一l1_l2质检规则阈值与输出规格.md'
```

每个领域建议单独执行一批，不要把所有领域混在一次改名里。

### 4. 更新索引文档

改名后同步更新：

```text
docs/doc-010_spec_文件分类清单.md
```

建议在索引中保留三类信息：

1. 新文件名
2. 原文件名
3. 所属领域、阶段、状态、备注

### 5. 更新文档内链接

用旧文件名搜索引用：

```powershell
$ErrorActionPreference = 'Stop'
Select-String -Path 'docs\*.md' -Pattern '阶段一L1_L2质检规则阈值与输出规格_v0.md'
```

如果存在引用，改为新文件名。

### 6. 校验旧名是否残留

```powershell
$ErrorActionPreference = 'Stop'
Select-String -Path 'docs\*.md' -Pattern '阶段一L1_L2质检规则阈值与输出规格_v0'
```

没有结果时，说明旧文件名引用已清理。

### 7. 查看 git 变更

```powershell
$ErrorActionPreference = 'Stop'
git status --short
```

预期看到类似：

```text
R  docs/旧文件名.md -> docs/新文件名.md
M  docs/doc-010_spec_文件分类清单.md
```

## 七、排序号分配规则

同领域内按文档生命周期排序：

```text
010 总体方案 / 治理建模
020 需求 / 需求修订
030 设计方案
040 规格文档
050 实现任务
060 实现说明
070 测试 / review
080 修复报告
090 使用说明
100 总结
```

不要求每个领域完全一致，但同一领域内部要稳定。

当中间需要插入新文档时，使用空位：

```text
qc-030_task_...
qc-035_task_...
qc-040_spec_...
```

## 八、特殊情况处理

### 旧文档已有日期

保留日期，但不要放在文件名最前：

```text
pose-020_impl_2026-06-16_姿态视图与自动聚焦实现总结.md
```

### 同一主题有多个版本

版本号放在类型码后：

```text
qc-020_des_v0_阶段一l1_l2质检方案_问题建模.md
qc-021_des_v1_阶段一l1_l2质检方案_问题建模.md
```

如果 v1 已经完全替代 v0，可以把旧版改为：

```text
arch-qc-020_des_v0_阶段一l1_l2质检方案_问题建模.md
```

### 文档标题过长

保留关键词，删除重复词：

```text
原名：小目标Person矩形实时尺寸显示需求修订_v1.md
建议：cls3-020_req_v1_小目标person实时尺寸显示.md
```

### 文档跨多个领域

文件名只放主领域，索引中补充副领域：

```markdown
| 文件名 | 主领域 | 副领域 | 备注 |
|--------|--------|--------|------|
| canvas-050_note_鼠标事件处理顺序.md | canvas | cls3 | 为矩形边编辑梳理 canvas 鼠标事件 |
```

## 九、验收标准

一批文件名修改完成后，必须满足：

1. 同一领域文件在文件管理器中连续排列。
2. 文件名能看出领域、顺序、类型和主题。
3. `git status --short` 显示为 rename，而不是删除加新增。
4. `docs/doc-010_spec_文件分类清单.md` 已同步新旧映射。
5. 旧文件名在文档引用中没有残留。
6. 原生文档目录 `docs/en/`、`docs/zh_cn/` 未被误改。

## 十、推荐执行节奏

建议按以下顺序分批：

1. `doc` / `meth`：先把文档治理和方法论文档命名稳定。
2. `qc`：数量最多、关联最强，优先收益高。
3. `cls3`：矩形框类别相关文档成系列，适合快速整理。
4. `pose`：已有日期和阶段文档较多，适合第二轮细化。
5. `filter` / `canvas` / `inspect`：按使用频率逐步整理。
6. `arch`：最后处理历史产物和过期方案。

每批完成后单独提交，提交信息示例：

```text
docs: rename quality check documents with coded filenames
```
