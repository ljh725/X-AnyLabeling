# 自定义扩展功能描述指南

这份文档用于描述“我自己扩展了项目功能，但不清楚代码结构”的情况。

核心思路：**先说原功能节点，再说你扩展了什么，再说扩展后在哪一步出问题**。

## 1. 推荐描述结构

```text
我基于原项目的【原功能节点】做了一个扩展，扩展功能是【新增能力】。
现在问题发生在【触发动作】之后，表现为【现象】。
我怀疑和【扩展逻辑 / 原项目逻辑 / 两者交互】有关。
请先帮我定位这个扩展功能接入到了原项目的哪些流程节点，不要直接大改代码。
```

## 2. 你需要提供的信息

描述自定义扩展时，尽量提供下面信息：

- 原功能节点：例如导入数据、切换图片、加载标签、自动标注、保存标签
- 扩展目的：例如提速、减少自动扫描、改成手动触发、减少内存占用
- 扩展行为：例如新增按钮、新增开关、修改默认配置、延迟加载、缓存结果
- 触发动作：例如打开软件、打开文件夹、切换图片、点击按钮
- 异常现象：例如卡顿、没反应、重复执行、不自动执行、结果不刷新
- 怀疑范围：例如配置、任务调度、文件扫描、模型推理、标签加载、UI 刷新

## 3. 可直接复制的模板

```text
我在这个项目上做了一个自定义扩展，但我不熟悉项目结构。

扩展名称：
<例如：自动任务改手动触发 / 标签加载优化 / 文件扫描优化>

原本想解决的问题：
<例如：打开图片时会全量扫描所有图片，导致卡顿>

我改动后的预期行为：
<例如：打开图片时不自动扫描，只有点击按钮时才执行>

现在实际行为：
<例如：仍然会自动扫描 / 不再卡顿但某些功能不自动刷新 / 点击手动按钮无效>

问题发生的流程节点：
<启动 / 导入图片 / 切换图片 / 加载标签 / 保存标签 / 自动标注 / 设置界面>

请你先做三件事：
1. 根据我的描述，推断这个扩展可能接入了哪些原项目功能节点
2. 在代码里搜索相关关键词，定位可能的文件、类、函数或配置项
3. 给我一个最小验证方案，不要直接大范围重构
```

## 4. 针对性能优化扩展的示例

```text
我基于 X-AnyLabeling 的“加载图片 / 加载标签 / 自动任务”流程做了性能优化扩展。

扩展内容是：
把两个默认自动执行的任务从 auto 改为 manual，希望避免打开图片时自动扫描全量图片。

现在的问题是：
我不确定这个扩展到底接入了哪些流程节点，也不确定是否影响了自动标注、标签加载或文件列表刷新。

请你先帮我按功能流程定位：
1. 这个扩展可能影响哪些原功能节点
2. 这些节点对应哪些配置项或调用链
3. 是否存在副作用，比如自动标注不再自动触发、标签状态不刷新、文件列表不更新
4. 请先给出定位结论，再给出最小验证方案
```

## 5. 描述时优先使用的词

- 原功能节点
- 扩展入口
- 扩展目的
- 触发动作
- 预期行为
- 实际行为
- 自动执行
- 手动触发
- 默认配置
- 调用链
- 副作用
- 最小验证

## 6. 不建议的描述方式

不建议只说：

```text
我改了一个功能，现在有问题，帮我看看。
```

更推荐说：

```text
我把“加载图片后自动执行的任务”改成了“手动触发”，目的是减少打开图片时的全量扫描。现在想确认这个改动是否影响了标签加载、自动标注和文件列表刷新。请先帮我按功能流程定位相关节点。
```
