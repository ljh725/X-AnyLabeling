# 当前阶段开发习惯清单

这份清单用于帮助你在二次开发过程中，减少重复排查、减少 AI 全量遍历、降低改动风险，并逐步建立自己的项目理解能力。

## 1. 每次提问前

先准备下面信息，不需要都很完整，但越具体越好：

- 问题发生在哪个功能流程：启动、导入图片、切换图片、加载标签、创建对象、编辑对象、保存、自动标注、设置
- 具体触发动作：点击按钮、打开文件夹、切换下一张、勾选配置、手动触发任务
- 实际现象：卡顿、无响应、重复扫描、没有保存、自动触发、手动触发无效
- 你怀疑的范围：配置、信号、状态字段、调用链、模型推理、文件扫描、UI 刷新
- 你已经验证过什么：改了哪个配置、关闭了哪个功能、问题是否变好

推荐句式：

```text
问题发生在【功能流程】。
触发动作是【具体动作】。
实际表现是【现象】。
我怀疑和【范围】有关。
我已经验证过【验证结果】。
请只检查相关调用链，不要全量遍历项目。
```

## 2. 每次改动前

先确认这几个问题：

- 这次只改一个目标吗？
- 这个改动属于哪个功能节点？
- 是否有更小的修改方式？
- 是否会影响打开图片、切图、加载标签、保存这些主流程？
- 是否需要新增配置项？
- 是否需要记录参数、默认值、返回值、信号参数？
- 是否能通过信号、配置、回调或适配层实现，而不是直接大改核心逻辑？

建议改动前写一句：

```text
本次改动目标：<只写一个目标>
```

## 3. 每次改动中

保持下面习惯：

- 一次只处理一条调用链
- 不同时做重构、格式化、业务改动
- 不大范围移动代码，除非明确是拆分任务
- 不凭记忆改接口，先确认调用方
- 改函数签名时，同步检查所有调用方
- 改信号参数时，同步检查 emit 和 connect
- 改配置项时，同步检查默认值、读取位置、保存位置、运行时应用位置

## 4. 每次改动后

至少做一次最小验证：

- 启动软件
- 打开图片或图片目录
- 切换上一张、下一张
- 加载已有标签
- 创建一个对象
- 编辑一个对象
- 保存标签
- 触发你的自定义功能
- 确认没有意外自动触发

如果改动和自动任务有关，还要额外检查：

- 默认是否自动执行
- 手动触发是否可用
- 是否还会全量扫描
- 是否会重复执行
- 是否影响标签刷新或文件列表刷新

## 5. 每次让 AI 帮忙时

尽量让 AI 做局部分析：

```text
请只分析以下功能节点：<节点>
请重点检查以下锚点：<信号 / 方法 / 配置 / 状态字段>
请输出调用链、接口变化、风险点和验证步骤。
不要重新解释整个项目。
```

如果涉及接口细节，追加：

```text
请特别检查参数名、参数顺序、默认值、返回值、信号 emit 参数、slot 参数、配置默认值和所有调用方。
```

## 6. 每次同步上游时

先做这些事：

- 确认当前业务分支是否干净
- 记录当前自定义功能列表
- 备份或保留当前分支
- 查看上游是否改了你的关键锚点
- 只同步有价值的上游改动
- 同步后先跑最小验证清单

重点关注：

- `canvas.py` 是否拆分
- 信号名是否变化
- 方法签名是否变化
- 配置项是否变化
- 状态字段是否迁移
- 你的业务适配层是否仍然有效

## 7. 每次完成一个功能后

建议补一张功能记录：

```text
功能名称：

修改目的：

影响流程：

依赖锚点：

改动文件：

验证步骤：

已知副作用：

后续注意：
```

## 8. 长期习惯

建议长期坚持：

- 不追求一次性读懂全项目
- 通过真实修改逐步建立项目地图
- 把经验写成文档和模板
- 每次只让 AI 看相关局部
- 每个扩展都保留功能锚点
- 每个关键改动都保留验证步骤
- 项目越定制，越要重视文档和接口记录

## 9. 一句话原则

```text
每次改动都要做到：目标清楚、影响可控、接口可查、验证可重复。
```
