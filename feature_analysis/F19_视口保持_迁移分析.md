## 1. 架构概述

### 旧架构（已废弃）的问题

旧方案存在三个根本性缺陷：

1. **三重变换冲突**：`load_file` 执行一次图片加载时，视口变换被执行三次——`fit_to_window`（图片加载时）→ 信号驱动的 `adjustSize`（`zoom_widget.setValue` 触发 `valueChanged` → `paint_canvas`）→ 显式 `paint_canvas`（`load_file` 末尾）。后两次相互覆盖导致视口跳动。
2. **方向依赖保存**：引入 `_nav_direction` 区分前进/后退方向，后退时跳过保存。这种策略在复杂场景（文件列表点击、快速翻页）下容易出现状态丢失或覆盖。
3. **`self.filename` 提前赋值错位**：`open_next_image()` 在调用 `load_file()` 之前就覆盖 `self.filename`，导致保存的 key 错位，需要额外 `_last_loaded_filename` 字段修补。

### 新架构：ViewportController

**核心思想**：方向无关 + 单一变换点 + 信号解耦。

```
┌─────────────────────────────────────────────────────┐
│                    load_file()                       │
│                                                     │
│  ① on_file_leaving()  →  save(last_loaded, ...)    │
│       无条件保存当前图的视口状态                       │
│                                                     │
│  ② load_pixmap(fit=False)  (如果有待恢复状态)        │
│       跳过 fit_to_window，避免第一次变换              │
│                                                     │
│  ③ on_file_loaded()  →  resolve() + apply()         │
│       单次变换：resetTransform + scale + 滚动条定位   │
│       blockSignals 隔离 zoom_widget                  │
│                                                     │
│  ④ paint_canvas() 仅在未恢复时调用                   │
└─────────────────────────────────────────────────────┘
```

**已删除的概念**：
- `_nav_direction`（方向判断）→ 无条件保存替代
- `_last_loaded_filename`（错位修补）→ `controller._last_loaded` 在 `on_file_loaded` 末尾精确记录
- `_save_viewport_state()` 方法 → 直接调用 `controller.on_file_leaving()`
- `canvas._zoom_center_scene_pos` 锚点恢复 → `canvas.apply_viewport()` 单次变换替代

## 3. ViewportController 核心 API

### 数据结构

```python
@dataclass
class ViewportState:
    zoom_mode: int      # FIT_WINDOW=0 / FIT_WIDTH=1 / MANUAL_ZOOM=2
    zoom_value: int     # 百分比，如 150
    center_x: float     # 场景坐标 X
    center_y: float     # 场景坐标 Y
```

### 方法一览

| 方法 | 功能 | 调用时机 |
|------|------|----------|
| `capture(canvas, zoom_widget, zoom_mode)` | 从当前 canvas 采样视口状态，返回 `ViewportState`（不写入） | 内部使用 |
| `save(filename, canvas, zoom_widget, zoom_mode)` | 无条件保存指定文件的视口状态 | 由 `on_file_leaving` 调用 |
| `resolve(filename, keep_prev_viewport)` | 按优先级返回目标文件的恢复状态，无则返回 `None` | 由 `on_file_loaded` 调用 |
| `apply(state, canvas, zoom_widget)` | 一次性应用视口变换：`blockSignals` + `canvas.apply_viewport()` | 由 `on_file_loaded` 调用 |
| **`on_file_leaving(filename, canvas, zoom_widget, zoom_mode)`** | 离开图片时的生命周期钩子 | `load_file()` 开头 |
| **`on_file_loaded(filename, canvas, zoom_widget, keep_prev_viewport)`** | 新图加载完成后的生命周期钩子，返回恢复的 state 或 None | `load_file()` 恢复阶段 |
| `has_state(filename)` | 查询指定文件是否有历史状态 | 辅助 |

### 恢复优先级

1. 目标文件有历史状态（`_states[filename]`）→ 精确恢复
2. `keep_prev_viewport=True` 且上一图有状态 → 继承上一图视口
3. 返回 `None` → 调用方走旧逻辑（`zoom_values` → `keep_prev_scale` → `fit_window`）

## 4. canvas_adapter.apply_viewport() 方法

替代旧的"设锚点 + adjustSize"恢复模式，执行**单次不可分割的变换**：

```python
def apply_viewport(self, zoom_value, center_x, center_y):
    self.scale = 0.01 * zoom_value
    view = self._view
    view.resetTransform()
    view.scale(self.scale, self.scale)
    # 精确定位：将场景坐标映射到视口坐标，计算偏移量调整滚动条
    mapped = view.mapFromScene(QPointF(center_x, center_y))
    vp_center = QPoint(vp.width() // 2, vp.height() // 2)
    delta = mapped - vp_center
    view.horizontalScrollBar().setValue(h_scroll + delta.x())
    view.verticalScrollBar().setValue(v_scroll + delta.y())
```

**关键**：`resetTransform → scale → 滚动条偏移` 三步在同一方法内完成，不触发任何信号回调。

## 5. label_widget.py 集成点

### 初始化（`__init__`）

```python
self.viewport_controller = ViewportController()
self.viewport_state_manager = self.viewport_controller  # 兼容别名
self.viewport_states = self.viewport_controller.states   # 兼容别名
```

### load_file() 中的调用流程

```python
# ① 保存离开图的视口（方向无关，无条件）
self.viewport_controller.on_file_leaving(
    filename=self.viewport_controller.last_loaded, ...)

# ② 预判是否有恢复状态，决定 fit 参数
_will_restore = self.viewport_controller.resolve(filename, ...) is not None
self.canvas.load_pixmap(image, fit=not _will_restore)

# ... 加载标签数据 ...

# ③ 恢复视口
restored_state = self.viewport_controller.on_file_loaded(
    filename, canvas, zoom_widget, keep_prev_viewport)
if restored_state is not None:
    self.zoom_mode = restored_state.zoom_mode
    self.zoom_values[filename] = (restored_state.zoom_mode, restored_state.zoom_value)
    viewport_restored = True
elif filename in self.zoom_values:
    self.set_zoom(self.zoom_values[filename][1])
elif is_initial_load or not keep_prev_scale:
    self.adjust_scale(initial=True)

# ④ 仅在未恢复时触发渲染
if not viewport_restored:
    self.paint_canvas()
```

### 信号解耦

`set_zoom()` 使用 `blockSignals` 防止 `zoom_widget.valueChanged` 信号触发隐式 `paint_canvas`：

```python
def set_zoom(self, value):
    self.zoom_widget.blockSignals(True)
    self.zoom_widget.setValue(value)
    self.zoom_widget.blockSignals(False)
    ...
```

需要渲染的调用方（`add_zoom`、`loop_thru_labels`、`zoom_org` 菜单动作）在 `set_zoom` 之后显式调用 `paint_canvas()`。

### 导航方法

所有导航方法（`open_prev_image`、`open_next_image`、`open_checked_image`、`open_prev_unchecked_image`、`open_next_unchecked_image`）不再设置 `_nav_direction`，直接调用 `load_file()`。

## 7. 配置项

| 配置键 | 类型 | 默认值 | 作用 |
|--------|------|--------|------|
| `keep_prev_viewport` | bool | `false` | 开启后，切到**无历史状态**的图片时继承上一图的视口 |
| `keep_prev_scale` | bool | `false` | 开启后，切图时保持缩放比例（不含视口位置） |

两者不冲突：`keep_prev_viewport` 优先级高于 `keep_prev_scale`（在 `resolve()` 中优先判断）。
