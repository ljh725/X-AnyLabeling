### ⚠️ 命名冲突处理
3.3.8已有 `graphics/managers/visibility_controller.py` (283行)，与源版本是**完全不同的类**：

| 维度 | 3.3.8版本 | 源版本 |
|------|----------|--------|
| 位置 | `graphics/managers/` | `widgets/` |
| 职责 | **形状整体可见性** — 显示/隐藏ShapeItem | **标签显示可见性** — 控制哪些label该显示 |
| 接口 | `is_visible()`, `set_shape_visible()`, `set_focus_mode()` | `should_show_label()`, `get_visible_shapes()`, `should_show_shape()` |
| 依赖 | ShapeManager → ShapeItem.setVisible() | canvas.shapes + DisplayMode enum |
| Qt | QObject + pyqtSignal | 纯Python类 |

**决策**: 
- 3.3.8版本 → 保留不动
- 源版本 → 重命名为 `label_visibility_controller.py`，归入功能16(智能标签)子系统

### 导入变更
- 新增导入（`widgets/__init__.py`）:
  ```python

  ```

## 2. 集成点分析

### shape_constraint_manager.py

#### canvas_adapter.py
- **`__init__`**: 初始化 `self.constraint_manager = ShapeConstraintManager(self)`
- **作用**: 在形状编辑时应用约束（如限制不超出图片边界、保持最小尺寸等）

#### 与ShapeEditController的关系
3.3.8已有 `graphics/managers/shape_edit_controller.py` (11,891B)，负责编辑模式的拖拽/缩放交互。
- **集成方式**: ShapeConstraintManager可作为ShapeEditController的约束提供者
- 或在adapter层调用 `constraint_manager.apply(shape)` 作为后处理

### label_visibility_controller.py (重命名后)

已在功能16(智能标签)中分析。作为智能标签子系统的一部分迁移。
- 依赖 `label_display_models.py` 中的 `DisplayMode` 枚举
- 通过 `canvas.shapes` 遍历形状
- 迁移时需将 `self.canvas` 引用适配为3.3.8的adapter
