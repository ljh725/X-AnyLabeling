### visibility_controller.py 对比分析

**两个文件是完全不同的类，不是冲突而是互补：**

| 维度 | 3.3.8 `graphics/managers/` (283行) | 源 `widgets/` (302行) |
|------|-----------------------------------|-----------------------|
| **定位** | 形状整体可见性(显示/隐藏shape) | 标签显示可见性(哪些label该显示) |
| **继承** | `QObject` + pyqtSignal | 纯Python类，无Qt继承 |
| **依赖** | `ShapeManager` → `ShapeItem.setVisible()` | `canvas.shapes` + `DisplayMode` enum |
| **核心方法** | `is_visible()`, `set_shape_visible()`, `set_focus_mode()` | `should_show_label()`, `get_visible_shapes()`, `should_show_shape()` |
| **模式** | 二态: 用户visible + focus_mode | 五态: ALL/CURRENT_ONLY/NONE/FOCUS/SELECTED_ONLY |
| **group感知** | ❌ 无 | ✅ `is_in_same_group()`, `get_related_shapes()` |

**结论**: 3.3.8版本保留不动。源版本重命名为 `label_visibility_controller.py`，作为智能标签子系统的一部分。

### 新架构实现方案

**保留的组件**（纯逻辑/计算，可直接复用）:
- `label_display_manager.py` — 管理器入口
- `label_display_config.py` — 配置管理
- `label_display_models.py` — 数据模型（DisplayMode, LabelPosition, LabelLayout等）
- `layout_calculator.py` — 布局算法（纯数学，与渲染无关）
- `label_display_settings_dialog.py` — 设置UI

**需重构的组件**:
- `leader_line_renderer.py` — 旧版用QPainter直接绘制，需改为提供绘制数据给QGraphicsItem
- `label_visibility_controller.py`（重命名后）— 需适配canvas引用方式

**新建的组件**:
- `SmartLabelOverlayItem` — 整合标签+引导线的QGraphicsItem
  ```python
  class SmartLabelOverlayItem(QGraphicsItem):
      def __init__(self, parent=None):
          super().__init__(parent)
          self.setZValue(ZOrder.LABEL + 5)  # 略高于普通标签
          self._layouts = []  # List[LabelLayout]
      
      def update_layouts(self, layouts):
          """接收LabelDisplayManager计算的布局结果"""
          self._layouts = layouts
          self.update()
      
      def paint(self, painter, option, widget):
          """绘制所有智能标签+引导线"""
          for layout in self._layouts:
              self._draw_leader_lines(painter, layout)
              self._draw_labels(painter, layout)
  ```

### 坐标系
- 所有标签位置由 `layout_calculator.py` 在场景坐标系中计算
- SmartLabelOverlayItem的`paint()`直接使用场景坐标
