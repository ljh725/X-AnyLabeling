# X-AnyLabeling — Agent Guide

> This file is intended for AI coding agents. If you are reading this, you are expected to know nothing about the project beyond what is written here.

---

## Project Overview

**X-AnyLabeling** (`x-anylabeling-cvhub` on PyPI) is an advanced, AI-powered image and video annotation tool. It provides industrial-grade auto-labeling capabilities for computer-vision tasks such as object detection, instance segmentation, pose estimation, rotated-box detection, OCR, visual grounding, tracking, depth estimation, image matting, and vision-language tasks.

- **Version**: `4.0.0-beta.4`
- **License**: GPLv3
- **Python requirement**: `>=3.11`
- **Platforms**: Linux, macOS, Windows
- **Repository**: https://github.com/CVHub520/X-AnyLabeling

The project recently completed a PyQt5-to-PyQt6 upgrade refactor (Beta release). The GUI is built with **PyQt6** and uses Qt resource files for translations and images.

| Layer | Technology |
|-------|------------|

| Code Quality | black, flake8, pre-commit |
| i18n | Qt Linguist (`.ts` → `.qm`), `lrelease` |

### Optional dependency groups (mutually exclusive)

- `cpu` — `onnxruntime` CPU inference
- `gpu` — `onnxruntime-gpu` for CUDA 12.x
- `gpu-cu11` — `onnxruntime-gpu` for CUDA 11.x
- `dev` — build tools, black, flake8, pytest, pyinstaller, twine

**Important**: `onnxruntime` and `onnxruntime-gpu` must never be installed at the same time.

## Build and Run Commands

### Development installation

```bash
# CPU environment
pip install -e ".[cpu,dev]"

# CUDA 12.x
pip install -e ".[gpu,dev]"

# CUDA 11.x
pip install -e ".[gpu-cu11,dev]"
```

### Launch the application

```bash
xanylabeling                           # GUI mode
xanylabeling --filename <path>         # Open image/folder
xanylabeling checks                    # System & package info
xanylabeling version                   # Show version
xanylabeling config                    # Show config file path
xanylabeling convert --task <task> ... # Format conversion
```

### Compile translations and resources

After modifying `.ts` files or adding images to the `.qrc`:

```bash
python scripts/compile_languages.py
```

This runs `lrelease` for all supported languages and regenerates `anylabeling/resources/resources.py`.

### Build standalone executables

```bash
bash scripts/build_executable.sh win-cpu
bash scripts/build_executable.sh win-gpu
bash scripts/build_executable.sh linux-cpu
bash scripts/build_executable.sh linux-gpu
bash scripts/build_executable.sh macos
```

### Build and publish to PyPI

```bash
bash scripts/build_and_publish_pypi.sh
```

## Code Style Guidelines

### Formatter & Linter

- **Formatter**: `black`, line length `79`
- **Linter**: `flake8`, max complexity `18`
- Configuration lives in `pyproject.toml` and `.flake8`.
- Excluded from formatting/linting: `tests/`, `anylabeling/resources/resources.py`

### Quick style commands

```bash
# Format all code
bash scripts/format_code.sh

# Or manually
black -l 79 --exclude="tests/|anylabeling/resources/resources.py|venv/" .

# Lint
flake8 anylabeling/
```

### Docstrings and type hints

- **Mandatory**: Google-style docstrings for every new function or class.
- **Mandatory**: Python type hints on all function definitions.

Example pattern (from `CONTRIBUTING.md`):

```python
def greet(name: str, greeting: str = "Hello") -> str:
    """
    Greets a person with a specified greeting.

    Args:
        name (str): The name of the person to greet.
        greeting (str): The greeting message to use, defaults to "Hello".

    Returns:
        str: A greeting message.

    Examples:
        >>> greet("World")
        'Hello, World!'
    """
    return f"{greeting}, {name}!"
```

### Import conventions

- `os.path` is commonly imported as `osp`.
- Qt6 imports use `from PyQt6 import QtCore, QtGui, QtWidgets`.
- Relative imports are used heavily inside sub-packages (e.g. `from . import utils`).

### Pre-commit hooks

The project uses `.pre-commit-config.yaml` with:

- `check-added-large-files`, `check-yaml`, `check-merge-conflict`, `trailing-whitespace`, `end-of-file-fixer`
- `black` (format + check)
- `flake8` with plugins (bugbear, docstrings, comprehensions, blind-except)
- `rstcheck`, `codespell`

Run before committing:

```bash
pre-commit run --all-files
```

## Configuration System

- Default config: `anylabeling/configs/xanylabeling_config.yaml`
- User config file: `~/.xanylabelingrc` (YAML)
- Legacy config migration: `.anylabelingrc` → `.xanylabelingrc`
- Config keys include: `language`, `theme`, `device`, `auto_save`, `shape`, dock visibility, shortcuts, etc.
- Shortcuts are normalized on load; legacy keys (`epsilon`, `show_cross_line`, `ui`) are remapped or dropped automatically.

## Deployment and Release

### PyPI package

- Package name: `x-anylabeling-cvhub`
- Entry point: `xanylabeling = anylabeling.app:main`
- Wheels are built for both CPU and GPU variants by mutating `__preferred_device__` in `anylabeling/app_info.py` before building.

### Standalone executables

- Built with **PyInstaller** using platform-specific `.spec` files in `packaging/pyinstaller/specs/`.
- Runtime hooks handle ONNX Runtime DLL bootstrap on Windows.
- macOS builds are packaged into a `.app` bundle and then zipped with `ditto`; a SHA-256 checksum is generated.

## Security Considerations

- **Model downloads**: Models are downloaded from GitHub releases. The code sets `ssl._create_default_https_context = ssl._create_unverified_context` to allow downloads behind corporate proxies. Be aware this disables SSL certificate verification for model downloads.
- **Subprocess model checks**: `safe_check_model` spawns a separate `spawn` process to validate ONNX or PyTorch model integrity, with a timeout to prevent crashes from malformed files.
- **License**: GPLv3. Commercial use is permitted, but the source-project address and brand identity must be retained.

## Common Tasks for Agents

### Adding a new auto-labeling model

1. Add a model wrapper class in `anylabeling/services/auto_labeling/` (or under `__base__/` if it extends a family base class).
2. Register the model YAML config in `anylabeling/configs/auto_labeling/`.
3. Add the model entry to `anylabeling/configs/models.yaml`.
4. If needed, add an ONNX export script to `tools/onnx_exporter/`.
5. Update relevant docs in `docs/en/` and `docs/zh_cn/`.

### Adding a new label format converter

1. Extend `BaseLabelConverter` in `tools/label_converter.py`.
2. Wire the new task into `anylabeling/views/common/converter.py` so it is reachable from the CLI (`xanylabeling convert --task <task>`).

### Adding UI strings

1. Wrap new strings with `QCoreApplication.translate("Context", "text")` or use translatable Qt properties.
2. Update `.ts` files and run `python scripts/compile_languages.py`.
