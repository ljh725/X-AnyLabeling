# 密集复核人工样本（自制合成，可复现）

本目录是 X-AnyLabeling 密集复核工作流（OpenSpec `add-dense-annotation-review-workflow` 任务 1.3）使用的**自制合成样本**。全部图像由 `scripts/generate_dense_review_samples.py` 用 Pillow 绘制：纯色背景上的“人形”矩形与椭圆，不含真人照片、网络图片或第三方素材，可自由复制、修改和分发。

> 用途：人工复核体验、交互回归与性能对照。不是训练数据，也不代表真实项目分布。写操作请使用临时副本。

## 重新生成与校验

```bash
python scripts/generate_dense_review_samples.py            # 写入本目录
python scripts/generate_dense_review_samples.py --force    # 覆盖已有文件
python scripts/generate_dense_review_samples.py --output DIR   # 输出到其他目录
python scripts/generate_dense_review_samples.py --check    # 只校验，不写文件
```

- 确定性：固定坐标与绘制顺序、无随机数、无时间戳与 EXIF；同一 Pillow 版本下重复运行字节一致。`--check` 重新渲染并逐字节比对，缺失、不一致或多余文件都会报告并以非零状态退出。
- 自动化测试：`pytest tests/test_dense_review/test_samples.py`（重新生成到临时目录，校验计数、类别、对象 ID 与标注加载）。

## 场景详情

### `dense_30_six_classes` — 30 个对象 / 6 类密集图

- 图像：`dense_30_six_classes.png`，1280×720；标注 `dense_30_six_classes.json`，30 个对象（30 个矩形）。
- 类别分布：A 5、B 5、C 5、D 5、E 5、F 5。
- 建议批次：A/B 10 个；C/D 10 个；E/F 10 个。
- 框规则：A=可见框、B=可见框、C=可见框、D=可见框、E=可见框、F=可见框。
- 查漏：4×3 网格，重叠 0.15。
- 用途：密集相邻对象的类别判读、批次导航与性能对照。
- 特殊对象：无。
- 人工步骤：
  1. 配置批次 A/B、C/D、E/F，框规则按“可见框”。
  2. 逐批查看卡片与主画布，确认 30 个矩形没有错误类别或错框。
  3. 依次点击“完成本批并进入下一批”，每批确认 10 个对象。
  4. 进入查漏，按 4×3 网格（重叠 0.15）逐区确认。
- 预期结果：**complete** —— 30 个矩形全部正确；A/B、C/D、E/F 三批各 10 个一次确认，再完成 4×3 查漏区域后流程完成。
- 对应任务：1.3（30 对象 6 类密集样本）；10.1（冷/暖缓存 GUI 对照与拖框基线）；10.2（性能门槛的密集图场景）；10.3（卡片缓存峰值与连续切图）；10.4（两人对照的密集难度组）；10.5（质量抽查（本图标注全对））。

### `small_and_occluded` — 小目标与遮挡

- 图像：`small_and_occluded.png`，1280×720；标注 `small_and_occluded.json`，18 个对象（18 个矩形）。
- 类别分布：A 7、B 7、C 4。
- 建议批次：A/B 14 个；C 4 个。
- 框规则：A=可见框、B=可见框、C=完整框。
- 查漏：4×3 网格，重叠 0.15。
- 用途：验证小目标放大、上下文裁切与高度遮挡下的证据判断。
- 特殊对象：小目标 soc-011…soc-018；相互遮挡 soc-001…soc-010；旧 `difficult` 标记（仅 JSON 历史字段，不等于复核“疑难”）：soc-001、soc-006…soc-007。
- 人工步骤：
  1. 配置批次 A/B（14 个）与 C（4 个）；A/B 按可见框、C 按完整框。
  2. 用卡片上下文与画布放大检查 soc-011…soc-018 这 8 个小目标。
  3. 检查 soc-001…soc-010 两处重叠，判断遮挡是否影响类别与框。
  4. 确认批次并完成 4×3 查漏区域。
- 预期结果：**complete** —— 18 个矩形标注均正确；难点是证据：8 个小目标与两处密集遮挡需要放大和上下文。允许把 soc-001、soc-006、soc-007 标为疑难，标记后流程保持待审。
- 例外：若把高度遮挡对象标为疑难而不确认，结果为 **pending**：流程保持待审，直到解除疑难并重新确认。
- 对应任务：1.3（小目标与遮挡样本）；5.2（卡片上下文与贴边/遮挡的证据查看）；6.1（小目标与相邻近似尺寸目标的倍率连续性）；10.3（小目标缩略图与缓存开销）；10.5（质量复核：遮挡导致的漏标/错标）。

### `clipped_arm` — 框截掉手臂（可见框 / 完整框规则）

- 图像：`clipped_arm.png`，1280×720；标注 `clipped_arm.json`，6 个对象（6 个矩形）。
- 类别分布：A 3、B 3。
- 建议批次：A/B 6 个。
- 框规则：A=完整框、B=可见框。
- 查漏：4×3 网格，重叠 0.15。
- 用途：验证框外肢体证据、拖边扩框与规则差异判定。
- 特殊对象：框截断可见手臂 arm-001…arm-006；贴图像边界 arm-005。
- 人工步骤：
  1. 配置批次 A/B（6 个）；A 按完整框、B 按可见框。
  2. 用卡片上下文查看每个框外手臂，确认手臂像素在框外可见。
  3. 拖边扩大 arm-001…arm-004、arm-006 到包含可见手臂；编辑后类别/框确认失效，在批次确认时重新确认。
  4. arm-005 按可见框扩到图像边界；若按完整框判定完整手臂不可知，可标记疑难。
  5. 确认本批并完成 4×3 查漏区域。
- 预期结果：**complete** —— 6 个矩形都截断可见手臂：arm-001…arm-004、arm-006 需要拖边扩框，扩框后已确认状态失效需重新确认；arm-005 的手臂伸出图像右边界。
- 例外：若arm-005 按完整框规则标记为疑难，结果为 **pending**：流程保持待审，直到解除疑难并重新确认。
- 对应任务：1.3（框截掉手臂样本）；5.2（截断/贴边对象的上下文与倍率）；6.3（拖边扩框与当前对象保持）；10.4（两人对照的中等难度组）；10.5（质量复核：漏扩框与规则差异判定）。

### `misclassified_third_batch` — 第三批系统性错分

- 图像：`misclassified_third_batch.png`，1280×720；标注 `misclassified_third_batch.json`，19 个对象（19 个矩形）。
- 类别分布：A 3、B 3、C 4、D 3、E 3、F 3。
- 建议批次：A/B 6 个；C/D 7 个；E/F 6 个。
- 框规则：A=可见框、B=可见框、C=可见框、D=可见框、E=可见框、F=可见框。
- 查漏：4×3 网格，重叠 0.15。
- 用途：验证批内改类、跨批改类不跳位与错误批次计数。
- 特殊对象：类别错误：m3-013（F→E）、m3-014（F→E）、m3-015（E→F）、m3-016（F→E）、m3-017（E→F）、m3-018（E→F）、m3-019（C→F）。
- 人工步骤：
  1. 配置批次 A/B（6 个）、C/D（7 个）、E/F（6 个）。
  2. 确认 A/B 批。
  3. 在 C/D 批中把 m3-019 从 C 改为 F：它仍留在 C/D 批成员中，不会跳回 E/F 批。
  4. 在 E/F 批中把 m3-013…m3-018 改成真值类别（E↔F 互换）。
  5. 确认剩余批次并完成 4×3 查漏区域。
- 预期结果：**complete** —— 19 个矩形；第三批（E/F）6 个对象全部标成同类批次中的另一类，需要 6 次数字键改类；m3-019 真值 F 却标成 C，属于跨批错分。
- 注意：若未改类就确认第三批，流程仍会显示“完成”——流程只记录用户声明，不自动判对；独立复核时需比对真值。
- 对应任务：1.3（错分到第三批的样本）；2.3（改类不跳位、不重复进入另一批）；7.3（批次成员数与当前类别统计的区分）；10.4（两人对照的高难度组）；10.5（质量复核：改类错误与漏改）。

## 约定与注意

- 对象 ID 稳定并写入 `xanylabeling_shape_id`；脚本重跑不变，可直接用于验收记录。
- `manifest.json` 中的 `batches`、`box_rules`、`coverage`、`expected` 是**建议配置与预期结果**，在应用里按此配置即可复现；配置不写入标注文件。
- `misclassified` 段给出“预标注 → 真值”，只用于人工核对，不写入标注 JSON 的 `description`，避免提示泄漏。
- 标注 JSON 保留 `score`、`group_id`、`difficult`、`flags`、`attributes`、`kie_linking` 等既有字段，未写入任何复核进度命名空间。
